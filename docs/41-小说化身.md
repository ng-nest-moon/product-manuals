# 小说化身 — 产品功能说明书

## 一句话定义

小说沉浸式第一人称角色扮演游戏——导入任意小说即可化身主角，在 AI 实时生成的 3D 世界中亲历原著剧情，你的每个选择都让故事长出新的枝桠。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

| 维度 | 描述 |
|------|------|
| 年龄 | 18-40 岁，深度网文读者或经典文学爱好者 |
| 年阅读量 | 年均 20 本以上，对剧情和人物有强烈情感投入 |
| 游戏经验 | 玩过开放世界 RPG 或互动叙事类游戏 |
| 核心诉求 | 不只是"读"一个好故事，而是"走进"一个好故事 |
| 最大痛点 | 读完小说后意犹未尽，但没有方式真正参与其中 |

### 1.2 细分用户类型

| 类型 | 画像 | 核心需求 | 行为特征 |
|------|------|---------|---------|
| **网文深度读者** | 每天追更，熟知各大平台 | 亲眼看到自己追了几年的名场面，与喜欢的角色并肩作战 | 愿意为还原度付费，对 OOC 容忍度低 |
| **经典文学爱好者** | 读过大量中外经典名著 | 走进文字描写的世界里，体验与阅读完全不同的视角 | 看重氛围感和时代细节的真实性 |
| **多周目玩家** | 习惯同一游戏反复通关追全结局 | 在蝴蝶效应系统下探索与原作不同的分支走向 | 收集成就导向，热衷分享旅程报告 |
| **同人创作向** | 喜欢写同人文或跑团 | 以非主角身份进入故事，创造"if 线" | 对世界书编辑功能需求强 |

### 1.3 现有方案及其不足

| 现有方式 | 不足 |
|---------|------|
| 阅读文字原著 | 被动接收，无法参与 |
| 影视/动画改编 | 删改严重，且不是自己的选择 |
| 互动小说/视觉小说 | 预设分支有限，无法覆盖复杂原著 |
| 模组游戏（如 Garry's Mod） | 需大量手动搭建，无叙事引擎 |
| AI Chat 角色扮演 | 纯文字无 3D 呈现，缺乏世界连贯性 |

## 二、架构总览

```
用户层
 ├── 小说导入
 │    ├── 格式兼容（TXT / EPUB / 网页链接）
 │    ├── 知识图谱提取（角色/地图/势力/能力）
 │    ├── 编年史生成（刚性节点 + 弹性节点）
 │    └── 世界书编辑与校正
 │
 ├── 角色扮演
 │    ├── 身份选择（主角 / 配角 / 原创角色）
 │    ├── 身份锚定（行动受角色人设约束）
 │    ├── 第一人称自由探索
 │    └── 状态面板（能力/关系/背包/HUD）
 │
 ├── 交互系统
 │    ├── 动态对话（AI 按角色性格实时生成）
 │    ├── 战斗系统（按原著设定生成规则）
 │    ├── 书签回溯（任意节点重新选择）
 │    └── 导演模式（关键剧情自动运镜演出）
 │
 └── 社区生态
      ├── 世界书共享与校正
      ├── 番外模组导出
      └── 旅程报告

叙事引擎
 ├── 主线铁轨（原著关键节点锁定，不可绕过）
 ├── 日常沙盒（节点间自由活动，AI 实时生成内容）
 ├── 蝴蝶效应（非关键选择累积影响世界状态）
 └── 还原度滑块（0%~100% 调节改编自由度）

世界呈现
 ├── 美术风格匹配（文本调性 → 渲染管线）
 ├── 3D 场景生成（地形/建筑/室内布局）
 ├── 动态天气与昼夜（与剧情进度同步）
 └── NPC 独立生态（有名字的角色拥有独立日程）
```

## 三、核心功能清单

1. **小说导入与智能解析** — 导入任意格式小说文件，自动提取角色清单、地理地图、势力关系、能力体系、关键事件编年史
2. **世界书系统** — 解析结果生成结构化"世界书"，玩家可逐项校正确认，作为后续游戏世界的底层约束
3. **身份选择与锚定** — 可选原著主角、配角或原创角色，所选角色的身份决定可触发的剧情、对话选项与行动边界
4. **主线铁轨** — 原著关键剧情节点按顺序锁定，玩家必经不可绕过，但以第一人称亲历而非播片观看
5. **日常沙盒** — 两个主线节点之间完全自由，AI 根据原著风格实时生成符合世界观的内容
6. **蝴蝶效应** — 玩家的非关键选择存入世界状态档案，累积影响 NPC 态度、隐藏支线解锁、最终结局走向
7. **动态对话系统** — 每个 NPC 的台词基于其性格库 + 当前世界状态 + 玩家历史行为实时生成
8. **导演模式** — 关键剧情时刻自动切换第三人称运镜、慢动作、BGM 切入，节奏由剧情张力动态调度
9. **书签回溯** — 系统在关键节点前自动标记书签，玩家通关后可回退到任意分叉口重新选择
10. **旅程报告** — 完成全篇后生成个性化报告：最常对话的 NPC、关键选择图谱、与原著偏差率

## 四、核心模块详解

### 4.1 小说导入与智能解析

**职责：** 将非结构化的小说文本转化为结构化的世界数据，作为整个游戏的叙事基座

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 格式兼容 | 支持 TXT / EPUB / 网页链接多种导入方式 | 单文件上限 50MB，自动检测编码与章节结构 |
| 角色提取 | 自动识别所有有名字的角色，提取外貌、性格、身份、阵营 | 同名角色需用户确认是否合并（如两个"张三"） |
| 地图提取 | 分析文本中出现的所有地名及其方位关系 | 输出结果为层级结构（大陆→国家→城市→地点） |
| 能力体系 | 提取境界分级、技能名称、战斗规则 | 仅提取已描述的能力，未提及的不做推测 |
| 编年史构建 | 按时序排列关键事件，标注刚性/弹性属性 | 刚性节点：主线必达；弹性节点：可选或可改变 |

### 4.2 叙事引擎

**职责：** 在保证原著主线完整的前提下，提供无限自由的交互叙事体验

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 还原度滑块 | 调节叙事对原著的忠实程度 | 0%=完全自由演绎；100%=严格遵循原著，偏差即时纠回 |
| 主线铁轨 | 刚性节点按原著顺序锁定 | 玩家不可跳过节点，但可自由选择到达节点的方式 |
| 日常沙盒 | 节点之间完全开放的探索时段 | AI 根据原著风格实时生成对话/事件/环境细节 |
| 蝴蝶效应 | 非关键选择存入世界状态档案 | 影响 NPC 好感度、隐藏区域解锁、结局分支与 NPC 生还状态 |
| 悖论检测 | 检测玩家行为是否导致主线节点无法合理发生 | 触发时引导玩家回到轨道，或接受高还原度下的剧情崩坏 |

### 4.3 世界呈现

**职责：** 将小说文字描述转化为可自由探索的 3D 沉浸空间

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 美术风格匹配 | 分析文本调性自动匹配渲染管线 | 预设风格库：水墨/写实/哥特/赛博朋克/像素等 |
| 场景生成 | 根据文本描述构建地形与建筑 | 室内外一体化，支持无缝大世界与章节独立场景双模式 |
| 动态天气与昼夜 | 时间流逝与剧情进度同步 | 不同天气影响 NPC 行为、对话内容、可触发事件 |
| NPC 生态 | 每个有名字的角色拥有独立日程 | 玩家不触发时 NPC 按设定自动作息，非静止等待 |
| 环境叙事 | 场景中的物件可交互，背后对应原著细节 | 拾取一封信可能触发支线，翻看一本书可获取世界观背景 |

### 4.4 交互系统

**职责：** 处理玩家与世界之间的所有双向互动

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 动态对话 | 对话内容和选项基于角色性格+世界状态实时生成 | 选项数量 2~5 个，不使用预设对话树 |
| 战斗系统 | 战斗规则从原著能力体系自动映射 | 招式名称与效果从原著直接提取，不做额外创作 |
| 非战斗交互 | 交易/偷窃/说服/恐吓等通用交互方式 | 成功率受角色属性和 NPC 关系值影响 |
| 书签回溯 | 关键节点前自动书签标记 | 回溯后保留原进度的世界状态快照，可对比差异 |

## 五、竞品与差异化分析

### 对比矩阵

| 维度 | 小说化身 | 互动小说/视觉小说 | 开放世界 RPG | AI 角色扮演（纯文字） | 模组沙盒游戏 |
|------|---------|----------------|-------------|-------------------|------------|
| 作品源 | **任意小说导入** | 专门创作的交互剧本 | 厂商预设剧情 | 用户手动设定 | 需模组开发者适配 |
| 世界呈现 | 3D 第一人称 | 2D 立绘+背景 | 3D 开放世界 | 纯文字 | 3D 但无叙事引擎 |
| 剧情分支 | AI 实时生成，近乎无限 | 预制分支树，有限 | 固定多结局 | LLM 自由生成但易崩 | 无原生叙事支持 |
| 原著还原度 | **核心定位** | 无关 | 无关 | 用户自行维护 | 无关 |
| 场景生成 | 语义→3D 自动生成 | 手绘固定背景 | 手工制作 | 无 | 手动搭建 |
| 单次体验成本 | 一份小说 | 需等待专门创作 | 数年开发周期 | 低但品质不稳 | 需大量 MOD 积累 |

### 核心差异

**小说化身不做"更好的开放世界 RPG"，而做"任何小说都能变成的游戏"。** 它的对手不是《巫师 3》或《上古卷轴》，而是"读完一本书后那种意犹未尽的空虚感"。用户不需要等游戏厂商改编，不需要等互动剧本创作，只要有一本喜欢的小说，就能进入那个世界。

## 六、用户流程

```
开始
  │
  ├─ 1. 导入小说
  │     ├─ 上传文件 / 粘贴链接 / 社区世界书库
  │     └─ 系统解析，生成世界书草稿
  │
  ├─ 2. 校正世界书
  │     ├─ 确认角色资料正确性
  │     ├─ 修正地名称谓与方位关系
  │     ├─ 设定还原度（默认 85%）
  │     └─ 确认刚性节点清单
  │
  ├─ 3. 选择扮演身份
  │     ├─ 原著主角（推荐，完整主线体验）
  │     ├─ 重要配角（受限的剧情视角）
  │     └─ 原创角色（自由但脱离主线）
  │
  ├─ 4. 进入游戏
  │     ├─ 第一人称置于开场场景
  │     ├─ HUD 显示当前章节/目标/状态
  │     └─ 导演模式自动引导进入首个剧情节点
  │
  ├─ 5. 体验循环
  │     ├─ 到达刚性节点 → 导演模式演出 → 玩家参与
  │     ├─ 在两个节点之间 → 自由探索/对话/触发支线
  │     ├─ 蝴蝶效应累积 → 世界状态持续变化
  │     └─ 书签自动保存 → 玩家可随时回溯
  │
  └─ 6. 完成终章
        ├─ 播放结局演出
        ├─ 生成旅程报告
        └─ 可导出番外模组或存入社区世界书
```

## 七、应用场景

### 场景一：经典名著的全新体验

用户是《平凡的世界》的读者，想"走进双水村"。导入小说后，美术风格自动匹配黄土高原的质朴色调。用户以孙少平的身份经历从读书到揽工的全过程。在主线节点之间，可以在工地上和工友聊天，在县城街道上闲逛，AI 根据路遥原著的写实风格生成符合时代背景的日常对话。

### 场景二：玄幻小说的多重结局探索

用户通关《诛仙》后，在书签界面回到"青云山拜师"节点重新选择——这次不选张小凡，选林惊羽。两个身份的修行路径、同门关系截然不同。到了碧瑶挡剑的刚性节点时，因为之前积累的蝴蝶效应（主角修为不同、与碧瑶的关系值不同），可能触发与原作不同的后续发展。

### 场景三：侦探小说的沉浸式推理

用户导入阿加莎·克里斯蒂的《东方快车谋杀案》，以侦探波洛的身份上车。在到达"揭晓真凶"这个刚性节点之前，用户可以在列车上自由走访乘客、检查物证、进行推演对话。AI 根据每位乘客的性格和隐藏身份实时调整对话回应，用户收集的证据和做出的推论会影响最终揭晓时刻的演出方式。

## 八、风险与预期反馈

| 预期质疑 | 应对思路 |
|---------|---------|
| "这不就是 AI 生成的水游戏吗" | 核心卖点是还原原著而非自由生成，AI 是执行手段不是产品本身 |
| "版权问题怎么解决" | 产品定位为个人阅读辅助工具（类似"文字转游戏渲染"），不传播、不分发、不上架第三方内容 |
| "上千万字的小说真的能做成 3D 游戏？" | 日常沙盒模式不求穷尽全部细节，只保证关键节点完整；大量内容靠 AI 按需生成而非预载 |
| "AI 生成的对话会偏离原著人设" | 身份锚定 + 性格库约束 + 还原度滑块三重机制兜底 |
| "这和有声书/广播剧有什么区别" | 不仅是听觉呈现，而是可自由移动、交互、选择的沉浸式空间，本质是游戏而非内容消费 |
| "为什么不做成 VR？" | VR 是可选呈现层，产品核心是叙事引擎；第一阶段不做 VR 以降低硬件门槛 |

## 九、落地路径

### Phase 1：纯文字交互小说引擎

| 功能 | 说明 |
|------|------|
| 核心体验 | 终端/Web 界面，文字描述场景+选项交互 |
| 目标验证 | AI 能否在"还原原著"约束下提供连贯叙事体验 |
| 上线形态 | 输入小说→校正世界书→以文字交互体验剧情循环 |
| 成功标准 | 测试用户完成一本 30 万字小说的体验，剧情连贯不崩 |

### Phase 2：2D 视觉小说版

| 功能 | 说明 |
|------|------|
| 新增 | 自动生成场景插图 + 角色立绘 + 背景音乐匹配 |
| 目标验证 | 视觉呈现能否提升沉浸感而不破坏还原度 |
| 上线形态 | 类似 Galgame 但剧本来源为用户导入的小说 |
| 关键差异 | 插图由 AI 按当前章节内容实时生成，非预制图库 |

### Phase 3：3D 第一人称版

| 功能 | 说明 |
|------|------|
| 新增 | 3D 场景生成 + 第一人称自由移动 + 实时战斗/对话 |
| 目标验证 | 语义→3D 管线是否成熟到可支撑完整小说体验 |
| 前置条件 | AI 3D 生成技术（NeRF/Gaussian Splatting 等）达到消费级品质 |
| 最终形态 | 全 3D 沉浸式叙事游戏，连接任意小说即可开局 |

## 十、边界声明

| 不做 | 原因 |
|------|------|
| 非小说体裁的导入适配（剧本/漫画/论文） | 叙事结构与交互逻辑差异过大，需独立设计 |
| 玩家自创剧情发布为独立游戏 | 属于创作工具的范畴，与本产品"还原原著"的定位不符 |
| 多人联机模式 | 每个玩家的世界状态是私有的，同步机制破坏沉浸一致性 |
| 连载中作品的自动追踪更新 | 未完本状态的世界书频繁变更，导致玩家体验断裂 |
| 对原著剧情的 AI 改写作为官方版本发布 | 版权归属不明确，仅限单机个人体验 |

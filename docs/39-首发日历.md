# 首发日历 — 产品功能说明书

## 一句话定义

跨平台新品首发聚合与 AI 推荐工具，帮你在海量"首发"中找到真正值得关注和入手的那一个。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

**主要用户：25-40 岁，有消费力且热衷追新的城市中产**

| 维度 | 描述 |
|------|------|
| 年龄 | 25-40 岁 |
| 收入 | 个人月入 1.5-5 万 |
| 城市 | 一线及新一线城市 |
| 消费特征 | 愿意为新品/限定/首发支付溢价，注重"第一时间体验" |
| 日常行为 | 刷小红书/抖音看开箱评测、关注科技博主/美妆博主、加入品牌粉丝群 |
| 典型场景 | 想买新手机但不记得哪天发售、路过商场看到排长队才知道今天首店开业、朋友晒了限定款自己才知道已经卖完了 |
| 底层情绪 | 怕错过——错失感比买贵了更难受 |

**次要用户：品牌市场/电商运营人员**

| 维度 | 描述 |
|------|------|
| 角色 | 电商运营、品牌市场、线下门店管理 |
| 需求 | 监控竞品首发动态、发现跨平台新品趋势、跟踪首店/快闪店信息 |

### 1.2 真实痛点分级

| 需求类型 | 痛点 | 用户行为证据 |
|---------|------|-------------|
| **刚需** | 首发信息分散在 5+ 个平台（淘宝/京东/抖音/小红书/品牌官网），根本看不全 | 用户会同时关注多个博主/KOL 获取新品信息 |
| **刚需** | 知道了也来不及——等看到的时候已经抢光了/排完了 | 抢到了发朋友圈炫耀，没抢到的后悔 |
| **改善型** | 不知道哪个首发值得抢——有评测差的、有刷单的、有溢价的 | 用户会搜"XX 值得买吗"判断是否入手 |
| **改善型** | 线下首店/快闪店信息靠刷到才能知道 | 用户常在小红书刷到打卡帖才知道 |
| **猎奇伪需求** | "我想要一个平台看所有新品"——但大部分人只关注自己感兴趣的品类 | 泛泛的全品类信息不会带来付费意愿 |

## 二、解决方案与核心功能

### 2.1 解决方案概述

首发日历 = 跨平台首发聚合 × AI 推荐筛选 × 决策辅助。

不做"全量信息轰炸"，做**你关注领域内"值得关注"的首发筛选器**。用户设定一次偏好，每天收到的是经过筛精选后的首发清单，而非全量信息流。

### 2.2 核心功能清单

1. **首发聚合** — 跨淘宝/京东/抖音/小红书/品牌官网实时抓取新品首发信息，归一化为统一的首发事件
2. **智能推荐** — 基于用户品类偏好、所在城市、消费等级，AI 筛选并排序推荐首发列表
3. **决策辅助** — 整合多方评测与价格历史，生成"首发指数"辅助判断值不值得入手
4. **场景导航** — 按"科技/美妆/服饰/食品/家电/文旅/家居/运动"分类浏览，支持城市筛选
5. **提醒中心** — 关注的首发开售前推送提醒，品牌/品类上新自动通知
6. **商圈地图** — 标注近期有首店/快闪店的商圈，查看热度与活动密集度
7. **首发日历** — 日/周/月视图查看未来排期，一键订阅关注

## 三、竞品与差异化分析

### 3.1 同类替代品对比

| 竞品 | 优点 | 缺点 | 与本产品定位差异 |
|------|------|------|----------------|
| 慢慢买/什么值得买 | 价格监控成熟，用户量大 | 以比价为主，首发只是子类目，信息滞后 | 首发日历聚焦"首发"时间线，不做比价 |
| 小红书搜索 | 真实开箱内容多，种草力强 | 无结构化首发信息，全靠手动搜 | 首发日历结构化聚合，不用手动搜 |
| 电商平台新品频道 | 直接可以买 | 仅限本平台，无跨平台对比 | 首发日历跨平台，看到所有首发 |
| 品牌官方公众号 | 信息最准 | 必须关注 N 个号，被动接收 | 首发日历一站式，主动配置 |

### 3.2 差异化优势与护城河

| 优势 | 护城河评估 |
|------|-----------|
| 跨平台归一化首发聚合 | 中等——需要持续维护爬虫，有运营成本 |
| 首发指数（评测×价格×热度） | 中高——数据积累越久越准，后续者难以短期追赶 |
| 商圈首店地图 | 中——POI 数据可买，但首店标注需要人工标定 |
| 用户偏好训练数据 | 高——用户标记行为累积后形成偏好模型壁垒 |

## 四、系统架构总览

```
用户表现层
 ├── 首页（今日首发大盘 · 按热度排序）
 ├── 搜索与筛选（关键词 + 品类 + 城市 + 价格区间）
 ├── 个人偏好中心（品类 / 品牌 / 城市 / 消费等级）
 └── 提醒中心（推送 + 站内消息）

核心逻辑层
 ├── 智能推荐引擎
 │    ├── 偏好匹配（用户画像 × 首发标签）
 │    ├── 热度加权（全网讨论量 × 搜索指数 × 关注增长）
 │    └── 冷启动策略（新用户热门推荐）
 ├── 决策辅助引擎
 │    ├── 首发指数计算（关注度 × 好评率 × 性价比）
 │    ├── 评测聚合（媒体 / KOL / 用户评价摘要）
 │    └── 价格走势分析（同类历史对比）
 └── 场景导航（预设 8 大场景分类 + 城市筛选）

数据层
 ├── 首发聚合引擎
 │    ├── 电商爬虫（淘宝 / 京东 / 拼多多新品区）
 │    ├── 社交监听（抖音 / 小红书首发内容）
 │    └── 品牌官网监控（知名品牌上新页面）
 └── 数据处理（归一化 → 去重 → 分类 → 入库）

外部接口层
 ├── 地图 POI（首店位置 + 商圈信息）
 ├── 评测源（媒体 + KOL + 用户评价）
 └── 推送通道（App推送 / 微信 / 短信）
```

## 五、核心模块详解

### 5.1 首发聚合

**职责：** 从多平台实时收集新品首发信息，统一归一化为结构化事件。

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 平台覆盖 | 淘宝/京东/拼多多/抖音/小红书 + 100+ 品牌官网 | 仅抓取公开可访问信息，不碰付费内容 |
| 归一化 | 不同平台的首发信息统一字段（名称/价格/时间/平台/链接） | 同一商品跨平台发布自动合并 |
| 去重 | 同品牌同型号 SKU 按最早发布时间保留 | 不展示重复首发 |
| 更新频率 | 电商新品每日 4 次，社交媒体实时监听 | 避免触发反爬机制 |

### 5.2 智能推荐

**职责：** 从全量首发事件中筛选用户可能感兴趣的内容。

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 偏好匹配 | 品类 × 品牌 × 城市 × 消费等级四维匹配 | 新用户无偏好默认热门推荐 |
| 热度加权 | 全网讨论量 + 搜索指数 + 关注增长趋势 | 热度每 6 小时刷新 |
| 地域过滤 | 线下首店仅推荐所在城市用户 | 城市信息来自用户主动设置 |
| 冷启动 | 新用户展示各品类 Top 10 + 引导设置偏好 | 完成 3 次交互后切换个性化 |

### 5.3 决策辅助

**职责：** 量化评估首发值不值得入手，降低决策焦虑。

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 首发指数 | 关注度 × 好评率 × 性价比 三维综合评分（1-100） | 无评测数据时显示"暂无评分" |
| 评测聚合 | 自动汇总全网评测/开箱/评价的关键摘录 | 仅提取公开内容，标注来源 |
| 价格走势 | 同类商品历史价格曲线，首发价相对定位 | 历史数据覆盖首发前 3 个月 |
| 判断提示 | 高价值 "建议关注" / 溢价过高 "建议观望" | 提示仅供参考，不构成购买建议 |

### 5.4 提醒中心

**职责：** 不错过感兴趣的首发。

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 首发提醒 | 开售前 30 分钟推送 | 每用户最多 20 个活跃提醒 |
| 品牌上新 | 关注品牌有新首发时自动通知 | 不限品牌数量 |
| 品类订阅 | 订阅品类有新首发时通知 | 需开通推送权限 |
| 重复抑制 | 同品牌同品类 7 天内不重复通知 | 避免骚扰 |

### 5.5 商圈地图

**职责：** 发现身边的首店/快闪店，线下逛街有目标。

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 地图标注 | 首店/快闪店位置 + 开业时间 + 热度标签 | 数据覆盖一线+新一线 19 城 |
| 商圈热度 | 区域内首店密集度 + 近一周打卡人数 | 每 24 小时更新 |
| 详情弹窗 | 点击标记查看门店信息、用户评价、营业时间 | 评价来源于公开社交平台聚合 |

## 七、商业模式

### 7.1 定价区间

| 付费模式 | 定价区间 | 价值锚点 |
|---------|---------|---------|
| 基础版（免费） | 0 元 | 每日 10 条推荐 + 基础日历 |
| Pro 月费 | 15-25 元/月 | 无限推荐 + 首发指数 + 评测聚合 + 商圈地图 |
| Pro 年费 | 120-200 元/年 | 月费打 6-7 折 |

**用户心理价位：** 15-25 元/月。对标同类信息筛选工具（如什么值得买会员 19.9/月），提供的信息价值超过一顿外卖的价格即可留存。

### 7.2 销售渠道

| 渠道 | 优先级 | 说明 |
|------|--------|------|
| 独立 App/小程序 | ★★★★★ | 核心阵地，首发日历的主产品 |
| 微信小程序 | ★★★★ | 社交裂变入口，"发给朋友看今天首发" |
| 科技/消费类 KOL 合作 | ★★★ | "我一直在用这个追首发" 种草推广 |
| 品牌合作引流 | ★★ | 品牌付费推自己的首发给精准用户 |

### 7.3 盈利模式

| 收入来源 | 说明 | 阶段 |
|---------|------|------|
| Pro 订阅 | 用户端付费，解锁全部功能 | 稳定期主力收入 |
| 品牌首发推广 | 品牌付费将其首发置顶/推荐给相关用户（标注"推广"） | 用户量 10 万+ 后开启 |
| 电商 CPS 返佣 | 用户跳转购买后获得佣金（不自营、不改价） | 持续收入 |

## 八、落地路径

### 8.1 五大落地难点

| 难点 | 缓解策略 |
|------|---------|
| 爬虫稳定性——各平台反爬严格 | 多信源备选 + 优先使用平台公开 API + 用户可提交首发线索 |
| 信息质量——首发信息真假混杂 | 多源交叉验证 + 用户举报机制 + 首发标注"官方/非官方" |
| 用户精准度——推了不感兴趣的内容 | 偏好设置 + 负反馈标记持续优化 + 冷启动快速引导 |
| 线下首店数据——覆盖不全 | 初期仅覆盖 5 个一线城市，用户可主动提交首店线索 |
| 商业化节奏——过早收费流失用户 | 基础版永久免费，Pro 在用户养成日活习惯后再推动 |

### 8.2 MVP 最小可行产品

| 功能 | MVP | 后续 |
|------|-----|------|
| 首发聚合 | 淘宝+京东+抖音 3 个平台 | 扩充到全部信源 |
| 推荐 | 关键词匹配+品类筛选 | 个性化推荐+首发指数 |
| 提醒 | 手动设置关注，邮件/微信推送 | App 推送+智能推荐 |
| 商圈地图 | 不接入 | 用户量达标后开发 |
| 决策辅助 | 不接入 | 评测聚合+价格走势 |

### 8.3 第一步验证

**最关键假设：** 用户愿意主动打开一个 App 查看今日首发信息。

**验证方法：** 做一个 Telegram/Discord bot，用户设置关注品类后每天收到当日首发清单。追踪用户留存——如果 2 周后日活留存 > 30%，说明"主动查看首发"这个行为成立。

## 九、风险与预期反馈

| 预期负面吐槽 | 应对方案 |
|------------|---------|
| "首发信息不全" | 初期明确标注覆盖平台范围，鼓励用户提交线索 |
| "推荐不精准" | 强调需设置偏好，负反馈按钮优化模型 |
| "首发指数不靠谱" | 标注"仅供参考"，公示指数计算维度 |
| "跟什么值得买有什么区别" | 聚焦"首发时间线"而非比价，差异化定位清晰 |
| "免费版就够用了" | Pro 权益要足够吸引——首发指数+评测聚合是核心付费点 |

## 十、边界与原则

| 不做 | 原因 |
|------|------|
| 电商交易闭环（下单/支付） | 定位信息聚合，购买跳转原站，保持平台中立 |
| 品牌付费推广不加"推广"标注 | 标注推广信息，维持用户信任 |
| 采集用户跨平台购买行为 | 仅本地存储偏好，不追踪购买记录 |
| 售后/客服 | 售后由各电商平台与品牌方承接 |
| 爬取付费内容或私域社群 | 仅基于公开可访问信息源 |
| 用户画像变现 | 用户数据不做商业化利用 |
| 自己下场做评测 | 只聚合公开评测，不产出原创评测内容 |

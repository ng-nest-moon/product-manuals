# 机会雷达 — 产品功能说明书

## 产品架构

### 机会扫描

用户设定关注领域，系统从公开渠道抓取相关信息和动态。设定的内容包括：目标技术栈（如 Go、Rust、React Native）、关注行业（如 FinTech、SaaS、AI 等）、目标公司名单、职位类型（开发/架构/管理）、技能关键词。

扫描信源覆盖以下类别：

**招聘渠道** — 招聘网站和公司官网的职位发布。（仅提取公开信息，不接入封闭的招聘平台 API。）

**技术社区** — 技术文章、讨论帖、项目动态、技术博客。用于感知什么技术正在被讨论、什么话题正在升温。

**行业资讯** — 行业新闻、公司动态、融资信息、政策变化。关注大环境的变化对个人职业发展的影响。

**开源项目** — 关注领域的开源项目的 Star 趋势、贡献者活跃度、版本发布频率。开源社区的活跃度往往是技术趋势的先行指标。

扫描结果按两个维度排序：

**新鲜度** — 基于发布时间和讨论热度变化趋势。一条信息如果在短时间内被大量讨论，新鲜度评分会快速上升。

**关联度** — 基于与用户关注领域的匹配程度。不使用精确的关键词匹配，而是采用语义相似度——一条说"分布式存储"的帖子，对关注"Go 后端"的用户也可能相关。

扫描频率由用户设定：实时（仅重大变化推送）、每日（每日一次汇总）、每周（每周一次汇总）。默认每日一次。

---

### 趋势预警

当关注的领域出现显著变化时，生成预警卡片推送给用户。预警覆盖以下维度：

**需求变化** — 某技术岗位的发布量在短时间内激增或骤降。比如 Rust 开发者的招聘量在一个月内翻倍，系统会推送"Rust 岗位需求出现显著增长"。

**薪资波动** — 某岗位的薪资区间中位数出现明显偏移。标注变化幅度和可能的原因（如大量高薪岗位涌入拉高了均值）。

**新兴技能** — 关注领域的职位描述中，出现新的高频技能关键词。比如以前 Java 岗位很少提 Kafka，突然大量 JD 出现 Kafka 要求，系统会标记这个变化。

**组织变动** — 关注公司出现大规模招聘、裁员、架构调整或融资信息。这些变化可能直接影响职业机会。

预警阈值由用户设定敏感度等级：

**高敏感度** — 细微变化就预警。信息量大但噪音也多。

**中敏感度（默认）** — 仅在变化幅度超过一定阈值时预警。平衡信息量和准确度。

**低敏感度** — 只推送经过确认的重大变化。适合不想被信息打扰的用户。

每条预警卡片包含：变化内容描述、数据来源和可信度标注、变化幅度指标、原文链接。预警可标为"有用"或"噪音"，标记行为用于优化后续预警的筛选。

### 情报看板

个性化的信息聚合面板，默认展示三个核心模块：

**市场温度**

关注领域岗位数量的趋势曲线图（可选 1/3/6/12 个月区间）。曲线叠加关键事件标记（如某公司的战略调整、某技术的版本发布）。

薪资区间分布直方图。按工作年限分层展示：1-3年、3-5年、5-10年、10年以上。数据源为公开薪资报告和匿名众包数据。

技能需求热度排行榜。展示关注领域中出现频率最高的技能关键词，按频率排序。支持查看周期变化——哪些技能的排名在上升，哪些在下降。

**动态流**

按时间倒序排列的信息条目列表。每条信息包含：来源标识、标题、摘要（1-2句话）、原文链接、发布时间。

用户可对每条信息操作：标记感兴趣（提升此类信息的权重）、标记不感兴趣（降低权重）、标记已读。操作数据仅用于本地的信息排序优化，不上传。

动态流默认折叠较旧的条目，优先展示 48 小时内的新信息。

**机会清单**

从动态流中筛选出的高价值机会。筛选条件由用户设定：技术栈匹配度、薪资范围、公司阶段（初创/成长期/成熟期）、地点等。

每条机会包含：岗位名称、公司、薪资范围（如果可获取）、匹配理由（为什么这条和你相关）、紧急程度（高/中/低）。

清单按紧急程度排序。用户可标记"已了解""已申请""不感兴趣"。

**布局自定义**

三个模块的位置和大小可拖拽调整。用户可折叠不常用的模块、展开常用的模块。布局配置保存在本地。

### 人脉链

个人行业关系记录工具。纯手动记录，不接入任何社交平台，不读取通讯录。

每次记录包含：联系人姓名或代号、认识时间和场合、单位/职位、最近一次联系时间、交流内容摘要、联系方式、关系强度。

关系强度分三个等级：**弱连接**（仅认识、无深入交流）、**中连接**（有过合作或多次交流）、**强连接**（长期合作、互信关系）。

系统在弱连接超过 6 个月无更新时，推送一条温和的提示："你和【某人】有段时间没联系了。"不强调"你应该联系"，只是提醒你记得这个人存在。

不强提醒、不推送重复通知。一次提醒后，除非用户主动更新记录，否则不再重复提醒。

---

### 收藏夹

从扫描结果和动态流中收藏的有价值信息。收藏按用户自定义的分类管理，每个分类可设置名称和图标。

收藏时支持添加个人注释："为什么收藏这条""这条信息说明了什么""可以用于什么场景"。注释在日后回顾时帮助快速定位。

收藏不设过期时间，但可标记"已过期"或"待重新审视"。系统定期提醒用户检视收藏夹，清理过时信息。

---

### 市场画像

辅助功能，基于扫描数据生成用户关注领域的全景画像。画像包含：

**技术生态图** — 展示关注领域的主要技术栈和它们之间的关联关系。哪些技术经常出现在同一份 JD 中、哪些技术是替代关系。

**公司地图** — 展示关注公司在技术栈选型上的分布。哪些公司用 Go、哪些用 Java、哪些在转向 Rust。

**薪资热力图** — 按技术栈和城市两个维度展示薪资分布。帮助用户了解"我会的这些技术在哪个城市值多少钱"。

画像数据完全基于公开信息聚合生成，不涉及任何用户数据。画像不是为了给出"标准答案"，而是为用户提供决策参考的背景信息。

## 功能边界与限制

- 不自动投递简历和申请职位（机会雷达只帮你发现机会，不代你做申请）
- 不提供薪资谈判策略和话术建议（只展示市场数据，不指导你该说什么）
- 不接入招聘平台的封闭 API（仅基于公开可访问的信息，不侵入平台规则）
- 不做匹配评分和推荐排序（是否匹配、值不值得投，你自己判断）
- 不做社交推荐和"你可能认识的人"
- 不做人脉关系图谱分析（不计算"你和某公司差几层关系"）
- 不保存用户的浏览、搜索、点击行为数据（不追踪用户）

## 反思建议

机会雷达的核心价值建立在这样一个观察上：很多人的职业瓶颈不是能力问题，而是信息差——不知道市场上在招什么人、什么技能正在变得重要、哪些公司在扩张、薪资的天花板在哪里。

他们有实力、有经验，但因为信息渠道太窄，长期停留在同一个位置。机会雷达要做的就是拓宽他们的信息面，让他们知道更广阔的职业可能性。

但这里有一个需要警惕的悖论：如果用户完全依赖被动推送的信息，反而可能错过真正的好机会——真正好的机会很少出现在公开渠道，更多的是来自弱连接、偶然的对话、不经意的交流。所以功能设计上，人脉链和主动搜索入口的重要性不亚于自动扫描和推送。

另一个要关注的是：机会信息天然带焦虑属性。"别人在学这个""那边在扩招""你的技能排名在下降"——每一句话都可能触发"我是不是落后了"的不安感。预警信息的措辞应该中立、事实性、不加情绪判断。只说变化，不评价好坏。

# 机会雷达 — 产品功能说明书

## 一句话定义

拓宽职业信息面——从公开渠道持续扫描岗位、技术、公司和行业动态，帮助用户感知市场变化，发现隐藏的职业机会。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

**主要用户：在职中高级技术人员（3-10 年经验）**

| 维度 | 描述 |
|------|------|
| 年龄 | 25-35 岁 |
| 岗位 | 软件开发、产品、设计等技术岗位 |
| 工作年限 | 3-10 年，已经跨过新手期 |
| 收入 | 月薪 1.5-4 万 |
| 当前状态 | 在岗但"不看机会"——不会主动找工作，但不拒绝看看 |
| 日常行为 | 偶尔刷刷招聘网站、关注技术动态 |
| 底层焦虑 | 怕错失机会——怕自己不知道市场在变、技术在换、有人在挖 |

**次要用户：被动观望的求职者**

| 维度 | 描述 |
|------|------|
| 状态 | 有工作但考虑跳槽，想了解市场但没时间持续关注 |
| 需求 | 被动的信息接收器——不要我主动搜，推给我就行 |

### 1.2 真实痛点分级

| 需求类型 | 痛点 | 用户行为证据 |
|---------|------|-------------|
| **刚需** | 职场人不知道市场在发生什么变化 | "不知道自己不知道"才是最大的风险 |
| **刚需** | 信息源太分散，没时间每天刷 | 招聘站、技术社区、行业新闻、公司动态分布在 5+ 个平台 |
| **改善型** | 不知道自己的技能在市场值什么价 | 凭感觉要薪资，谈 Offer 底气不足 |
| **改善型** | 想维持行业人脉但不好意思主动联系 | 弱连接长期不维护才会遗忘 |
| **猎奇伪需求** | "我要换工作"的确定意向 | 已经决定跳槽的人会用招聘平台而非信息雷达 |

## 二、解决方案与核心功能

### 2.1 解决方案概述

机会雷达是一个"被动信息接收器"。你设定好关注领域，它每天帮你扫一遍公开信息源，把有意义的信号筛出来送到你面前。

核心设计：
- **你不需要主动**——设定一次，持续接收
- **信息不是越多越好**——按新鲜度和关联度排序，屏蔽噪音
- **不是求职工具**——不代投、不推荐、不评分
- **不是社交网络**——不读取通讯录、不推荐联系人

机会雷达只做一件事：帮你感知市场变化。是否行动、怎么行动，你自己决定。

### 2.2 核心功能清单

1. **机会扫描** — 多源信息聚合，按新鲜度和关联度排序
2. **趋势预警** — 关注领域出现显著变化时推送预警卡片
3. **情报看板** — 个性化信息聚合面板（市场温度/动态流/机会清单）
4. **人脉链** — 手动记录行业关系，弱连接超过 6 个月温和提醒
5. **收藏夹** — 分类管理和注释收藏的有价值信息
6. **市场画像** — 技术生态图、公司地图、薪资热力图

## 三、竞品与差异化分析

### 3.1 同类替代品对比

| 竞品 | 优点 | 缺点 | 差异 |
|------|------|------|------|
| LinkedIn 动态流 | 信息丰富，人脉网络成熟 | 噪音大、社交压力、算法不透明 | 机会雷达只关注你的关注领域 |
| 招聘网站推送 | 岗位多，推荐算法成熟 | 只看岗位，不看技术和行业趋势 | 机会雷达覆盖技术新闻和开源动态 |
| Google Alerts | 免费、自定义关键词 | 无排序、无分析、全英文 | 机会雷达有排序、预警和画像 |
| Feedly/RSS | 自由订阅、无广告 | 需要手动订阅来源 | 机会雷达自动聚合，不需要手动维护 |

### 3.2 差异化优势

| 优势 | 说明 |
|------|------|
| 语义相似度排序 | 不是关键词匹配，没写到你的词也可能相关 |
| 被动模式 | 每天自动推给你信息，不需要每天主动打开 |
| 趋势预警 | 检测量变，在变化成为潮流前推送 |

## 五、核心模块详解

### 5.1 机会扫描

用户设定关注领域，系统从公开渠道抓取相关信息和动态。设定的内容包括：目标技术栈（如 Go、Rust、React Native）、关注行业（如 FinTech、SaaS、AI 等）、目标公司名单、职位类型（开发/架构/管理）、技能关键词。

扫描信源覆盖以下类别：

**招聘渠道** — 招聘网站和公司官网的职位发布。（仅提取公开信息，不接入封闭的招聘平台 API。）

**技术社区** — 技术文章、讨论帖、项目动态、技术博客。用于感知什么技术正在被讨论、什么话题正在升温。

**行业资讯** — 行业新闻、公司动态、融资信息、政策变化。关注大环境的变化对个人职业发展的影响。

**开源项目** — 关注领域的开源项目的 Star 趋势、贡献者活跃度、版本发布频率。开源社区的活跃度往往是技术趋势的先行指标。

扫描结果按两个维度排序：

**新鲜度** — 基于发布时间和讨论热度变化趋势。一条信息如果在短时间内被大量讨论，新鲜度评分会快速上升。

**关联度** — 基于与用户关注领域的匹配程度。不使用精确的关键词匹配，而是采用语义相似度——一条说"分布式存储"的帖子，对关注"Go 后端"的用户也可能相关。

扫描频率由用户设定：实时（仅重大变化推送）、每日（每日一次汇总）、每周（每周一次汇总）。默认每日一次。

### 5.2 趋势预警

当关注的领域出现显著变化时，生成预警卡片推送给用户。预警覆盖以下维度：

**需求变化** — 某技术岗位的发布量在短时间内激增或骤降。比如 Rust 开发者的招聘量在一个月内翻倍，系统会推送"Rust 岗位需求出现显著增长"。

**薪资波动** — 某岗位的薪资区间中位数出现明显偏移。标注变化幅度和可能的原因（如大量高薪岗位涌入拉高了均值）。

**新兴技能** — 关注领域的职位描述中，出现新的高频技能关键词。比如以前 Java 岗位很少提 Kafka，突然大量 JD 出现 Kafka 要求，系统会标记这个变化。

**组织变动** — 关注公司出现大规模招聘、裁员、架构调整或融资信息。这些变化可能直接影响职业机会。

预警阈值由用户设定敏感度等级：

**高敏感度** — 细微变化就预警。信息量大但噪音也多。

**中敏感度（默认）** — 仅在变化幅度超过一定阈值时预警。平衡信息量和准确度。

**低敏感度** — 只推送经过确认的重大变化。适合不想被信息打扰的用户。

每条预警卡片包含：变化内容描述、数据来源和可信度标注、变化幅度指标、原文链接。预警可标为"有用"或"噪音"，标记行为用于优化后续预警的筛选。

### 5.3 情报看板

个性化的信息聚合面板，默认展示三个核心模块：

**市场温度**：关注领域岗位数量的趋势曲线图（可选 1/3/6/12 个月区间），叠加关键事件标记。薪资区间分布直方图（按工作年限分层）。技能需求热度排行榜。

**动态流**：按时间倒序排列的信息条目列表。每条信息包含来源标识、标题、摘要、原文链接、发布时间。用户可标记感兴趣/不感兴趣/已读。默认折叠较旧条目，优先展示 48 小时内的新信息。

**机会清单**：从动态流中筛选出的高价值机会。筛选条件由用户设定：技术栈匹配度、薪资范围、公司阶段、地点等。按紧急程度排序。用户可标记"已了解""已申请""不感兴趣"。

**布局自定义**：三个模块的位置和大小可拖拽调整。布局配置保存在本地。

### 5.4 人脉链

个人行业关系记录工具。纯手动记录，不接入任何社交平台，不读取通讯录。

每次记录包含：联系人姓名或代号、认识时间和场合、单位/职位、最近一次联系时间、交流内容摘要、联系方式、关系强度。

关系强度分三个等级：**弱连接**（仅认识、无深入交流）、**中连接**（有过合作或多次交流）、**强连接**（长期合作、互信关系）。

系统在弱连接超过 6 个月无更新时，推送一条温和的提示："你和【某人】有段时间没联系了。"不强提醒、不推送重复通知。

### 5.5 收藏夹

从扫描结果和动态流中收藏的有价值信息。收藏按用户自定义的分类管理，每个分类可设置名称和图标。

收藏时支持添加个人注释："为什么收藏这条""这条信息说明了什么""可以用于什么场景"。

收藏不设过期时间，但可标记"已过期"或"待重新审视"。

### 5.6 市场画像

基于扫描数据生成用户关注领域的全景画像。包含：

**技术生态图** — 展示关注领域的主要技术栈和它们之间的关联关系。

**公司地图** — 展示关注公司在技术栈选型上的分布。

**薪资热力图** — 按技术栈和城市两个维度展示薪资分布。

## 六、用户流程

```
设定关注领域 → 选择敏感度与扫描频率
    ↓
系统开始自动扫描（每日默认）
    ↓
情报看板持续更新 → 趋势预警触发时推送
    ↓
用户浏览动态流 → 标记感兴趣 / 收藏 / 忽略
    ↓
机会清单自动筛选高价值机会
    ↓
用户自行判断并行动（机会雷达不代投）
```

## 七、商业模式

| 付费模式 | 定价区间 | 依据 |
|---------|---------|------|
| SaaS 月费 | 15-30 元 | 信息辅助工具的价格区间 |
| 年费 | 120-240 元 | 月费 x 12 打 6-7 折 |

**用户心理价位：** 提供每月信息价值超过 30 元即可留存。关键驱动力是持续有效覆盖的信息面。

| 销售渠道 | 优先级 |
|---------|--------|
| 独立官网订阅 | ★★★★★ |
| 职场类公众号/KOL 推荐 | ★★★★ |
| 个人开发者社区 | ★★★ |

**盈利模式：** 仅订阅收入，无广告、无数据销售、无增值内购。

## 八、落地路径

### 8.1 五大落地难点

| 难点 | 缓解策略 |
|------|---------|
| 信息质量差、噪音过大 | 语义排序 + 用户反馈标记持续优化 |
| 招聘信息源依赖爬虫稳定性 | 备选多源+用户可自定义 RSS 源 |
| 用户活跃度低导致流失 | 被动模式不需要每天打开 |
| 价值感知弱"就是看新闻" | 趋势预警和市场画像提供增值感知 |

### 8.2 MVP 最小可行产品

| 功能 | MVP | 后续 |
|------|-----|------|
| 机会扫描 | 招聘+技术社区 2 个信源 | 扩充到全部信源 |
| 排序 | 关键词匹配 | 语义相似度 |
| 看板 | 动态流 + 基础搜索 | 市场温度 + 公司画像 |

### 8.3 第一步验证

**最关键的假设：** 用户愿意为"被动获取职业信息"买单。

**验证方法：** 做一个 Telegram/Discord bot 版本，用户设置关注关键词后每天接收信息推送。如果 2 周后留存超过 40%，说明需求成立。

## 九、风险与预期反馈

| 预期槽点 | 应对方案 |
|---------|---------|
| "这不就是 RSS 吗" | 语义排序和趋势预警是差异化价值 |
| "信息太乱没意义" | 敏感度可调，用户反馈优化排序 |
| "我不用这个，LinkedIn 就够了" | 机会雷达只看信息不社交，不同赛道 |
| "每月 30 元不值" | 先免费 MVP 验证，价值感知做起来再定价 |

## 十、边界声明

| 不做 | 原因 |
|------|------|
| 自动投递简历和申请职位 | 只帮你发现机会，不代你做申请 |
| 提供薪资谈判策略和话术建议 | 只展示市场数据，不指导你该说什么 |
| 接入招聘平台的封闭 API | 仅基于公开可访问的信息 |
| 匹配评分和推荐排序 | 是否匹配，你自己判断 |
| 社交推荐和"你可能认识的人" | 不制造社交压力 |
| 人脉关系图谱分析 | 不计算"你和某公司差几层关系" |
| 保存用户的浏览、搜索、点击行为数据 | 不追踪用户 |

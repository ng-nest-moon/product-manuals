# 三角核心 — 产品功能说明书

## 一句话定义

每次开局都面临同一个选择题——容量、性能、稳定，三个属性互相拉扯，你只能选两个做强，剩下的注定是短板。在限制里组装芯片套装，进副本打一场，验证你的判断。

---

## 一、架构总览

```
芯片组装
 ├── 容量 ── 能装多少芯片
 ├── 性能 ── 芯片效果有多强
 ├── 稳定 ── 系统会不会翻车
 └── 三者互斥 ── 一条池里的水，一边多另外两边就少

副本流程
 ├── 程序生成地图 ── 每次路径不同
 ├── 战斗 ── 实时打怪，验证你的芯片组合好不好使
 ├── 商店与事件 ── 买芯片 / 换芯片 / 赌一把
 └── Boss ── 最终考试

局外成长
 ├── 记忆晶体 ── 打完带回来的升级资源
 └── 基地升级 ── 加容量上限、解锁更多芯片位
```

---

## 二、核心功能清单

1. **三角分配** — 开局在"容量/性能/稳定"三条属性上分配点数，一条多另外两条就少
2. **芯片组装** — 装上不同功能的芯片，四种类型：感知、技能、运算、强化
3. **副本探索** — 每次进本路线不同，敌人、商店、事件随机出现
4. **实时战斗** — 用你装的芯片打怪，检验这套组合实战行不行
5. **神经排斥** — 稳定低了芯片会随机失效或反噬扣血
6. **过载风险** — 性能太高而稳定不够会触发过载，过载满直接晕
7. **随机供给** — 每局掉落的芯片池不一样，你只能围绕"这局给了什么"来搭
8. **局内经济** — 打怪赚"数据"，在商店买芯片或改造
9. **元进度** — 带回"记忆晶体"升级基地，加总容量上限
10. **区域侧重** — 不同区域对属性的要求不一样，固定一套走不到底

---

## 三、核心模块详解

### 3.1 三角分配

**职责：** 每局开始的灵魂选择——三条属性互相抢资源

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 容量 | 决定了这局你能装几个芯片 | 容量越高→能带的芯片越多→装备丰富；占的总点数越多→性能和稳定就得让路 |
| 性能 | 决定了你的芯片效果有多强 | 性能越高→伤害/效果越猛；性能太高而稳定不够→过载条涨得快 |
| 稳定 | 决定了你的系统稳不稳 | 稳定越高→越不容易翻车；稳定太低→装得越多越容易触发排斥 |
| 三者互斥 | 三条属性共享一池总点数，此消彼长 | 总点数固定，每局开局分配；抬任何一边，另外两边自动降低 |

### 3.2 芯片系统

**职责：** 提供不同功能的芯片供玩家组装，形成战斗套路

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 芯片类型 | 四类：感知（新视野）、技能（战斗技）、运算（辅助）、强化（属性） | 每块芯片占用一定容量值 |
| 芯片等级 | 从低到高分多个等级 | 高阶芯片有属性门槛（如性能和稳定都达到某个值才能装） |
| 排斥机制 | 稳定太低 → 芯片可能随机失效或反噬 | 触发频率 = f（装载芯片总数 ÷ 稳定值）；触发时芯片闪红或弹负面效果 |
| 过载机制 | 性能太高 → 过载条累积 | 稳定值会影响过载条增长速度；过载条满=眩晕/短暂死亡 |

### 3.3 副本系统

**职责：** 程序生成每次不同的探索路线

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 地图生成 | 每次进本自动生成新路线 | 房间制连接，不同区域有不同主题 |
| 区域侧重 | 不同区域对属性有隐性要求 | 防火墙区更考验稳定、战斗区更考验性能、解谜区更考验容量 |
| 随机供给 | 每局芯片掉落池不一样 | 基于 seed 洗牌，同一局里你只能选"这局给了什么"来做 build |
| 商店节点 | 用打怪赚的"数据"买芯片或改造 | 固定出现在每局的中段和尾前段 |
| 事件节点 | 随机触发增益、陷阱或交易 | 如：超频陷阱（性能+但稳定-）、黑市（用数据换稀缺芯片） |

### 3.4 战斗系统

**职责：** 实时检验玩家的芯片组合是否有效

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 实时对战 | 不用回合等待，即时操作 | 走位 + 技能释放 |
| 敌人类型 | 普通怪 + 精英 + Boss | 不同区域敌人倾向克制某种属性 |
| 死亡判定 | 本局结束，带走记忆晶体 | 无续命机制，符合肉鸽规则 |

### 3.5 元进度

**职责：** 局外成长，让下一局更强

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 记忆晶体 | 死亡或通关后带回的升级资源 | 数量与局内表现相关 |
| 总容量 C 升级 | 提升三角三条属性的总点数 | 永久提升，所有局共享 |
| 插槽解锁 | 增加更多芯片位 | 需要晶体 + 达到指定总容量 |
| 兼容性提升 | 降低排斥触发概率 | 元进度积累，逐级解锁 |

## 四、用户流程

```
开局 ── 分配三角点数（容量/性能/稳定）
   │
   ├─ 进入副本
   │    ├─ 探索房间 → 遇敌战斗 → 掉落芯片
   │    ├─ 随机事件 → 选择增益或承受代价
   │    ├─ 商店 → 用数据买芯片 / 改造
   │    └─ 区域切换 → 属性偏好变化
   │
   ├─ Boss 战
   │
   ├─ 死亡 → 结算：记忆晶体
   │
   └─ 通关 → 结算：更多记忆晶体
         │
         回基地：升级总容量 / 解锁新插槽 → 下一局
```

---

## 五、应用场景

### 场景一：新手第一局——先"稳"一把

第一次玩，看不懂三个属性怎么选。先把稳定拉高、容量适中、性能压最低。这样芯片装不多，打得慢，但不会触发排斥也不会过载。活到 Boss 面前，虽然输出不够打不过，但明白了"原来如此"——下一局知道怎么调了。

### 场景二：老手试套路——"玻璃大炮"

玩熟了，知道不同区域要换不同配置。这局决定赌一把：性能拉满、稳定压到最低，装一堆高伤芯片。前面几关一路秒杀，爽到飞起。到了防火墙区，稳定太低触发排斥，芯片集体失效，被杂兵围死。笑骂一句"下次注意"，带回晶体，重开。

### 场景三：优解挑战——"看菜吃饭"

老玩家不再执着于"我要玩什么 build"，而是根据每局掉落的芯片池做决定。这局前期掉了两个感知系稀有芯片，走感知路线；中期商店刷出一个强力技能芯片但需要高容量支撑，临时从性能里匀点数过去。最后一关就是检验你这局的"看菜吃饭"做得对不对。

## 六、边界声明

| 不做 | 原因 |
|------|------|
| 复杂数值运算 | 三个属性的互动规则直观可感，玩家不需要算公式，靠感觉就能做判断 |
| 回合制 | 实时战斗更爽快，也符合现代肉鸽的习惯 |
| 联网 / 多人 | 单机体验，每次开局都是自己的选择题 |
| 内购 / 抽卡 | 买断制，元进度靠游戏内记忆晶体解锁 |
| 少年 / 教学模式 | 首版不考虑低龄化适配，后续可能追加独立模式 |
| 多结局叙事 | 首版聚焦核心玩法循环，剧情做减法 |

---

*三角核心 — 每次开局都是一道取舍题。*

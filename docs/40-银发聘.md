# 银发聘 — 产品功能说明书

## 一句话定义

退休人群灵活用工匹配平台——让低龄老人找到适合的零工/顾问/兼职，帮企业合规用工降本，实现"老有所为"的双向奔赴。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像（供给端）

**主要用户：60-69 岁低龄退休老人**

| 维度 | 描述 |
|------|------|
| 年龄 | 60-69 岁，占老年人口 55% 以上 |
| 状态 | 已退休，有退休金，身体健康 |
| 再就业意愿 | 约 59% 想继续工作 |
| 动机分层 | 增加收入 / 找事做防孤独 / 发挥余热传承技能 |
| 最大痛点 | **不知道去哪找**——58.9% 只能靠熟人介绍 |
| 技能特征 | 从退休会计/教师/医生到退休工人/服务员，跨度极大 |

**三种典型供需画像：**

| 类型 | 画像 | 典型岗位 | 行为特征 |
|------|------|---------|---------|
| **银发白领** | 退休医生/教师/会计/工程师 | 顾问、代账、培训、质检 | 证书可查、经验可量化、挑活 |
| **银发蓝领** | 退休工人/服务员/保洁 | 家政、保安、绿化、后厨 | 体力尚可、需要稳定排班 |
| **银发社交型** | 退休后孤独想找伴 | 社区服务、陪诊、带娃接送 | 收入次要、社交需求优先 |

### 1.2 核心用户画像（需求端）

**主要用户：需要灵活用工的中小企业和连锁机构**

| 维度 | 描述 |
|------|------|
| 典型客户 | 代账公司、体检中心、家政公司、餐厅、工厂 |
| 痛点 | 正式员工成本高（社保+公积金），年轻人不稳定 |
| 核心诉求 | 降用工成本 + 合规用工（免社保 + 按日保险） |
| 顾虑 | 工伤风险、法律不明确、管理难度 |

### 1.3 真实痛点分级

| 需求类型 | 痛点 | 用户行为证据 |
|---------|------|-------------|
| **刚需** | 老人找不到合适的工作渠道 | 58.9% 靠熟人介绍，信息面极窄 |
| **刚需** | 企业不敢用超龄劳动者 | 怕工伤纠纷、怕法律风险 |
| **刚需** | 传统招聘平台对老人不友好 | 字体小、操作复杂、全是全职岗位 |
| **改善型** | 子女反对老人出去工作 | "都退休了还出去丢人" |
| **改善型** | 老人有技能但不懂怎么"卖" | 有经验但不会写简历、不会上线找 |
| **伪需求** | 老人想要长期全职合同 | 实际调研显示灵活零工需求远大于全职 |

## 二、解决方案与核心功能

### 2.1 解决方案概述

银发聘 = 适老化找工作工具 × 合规用工基础设施 × 灵活用工平台。

不做传统招聘网站，做 **"老年版灵活用工平台"**——按小时/按天/按项目匹配，而非全职雇佣。两端分别解决：
- **老人端**：语音找工作、附近门店、大字操作、子女代操作
- **企业端**：合规模板、按日保险、技能画像匹配

### 2.2 核心功能清单

1. **语音找工作（老人端）** — 语音说出"找附近做饭的活儿"，语义理解匹配岗位
2. **LBS 附近岗位地图** — 基于位置的零工推荐，步行或公交可达
3. **技能轻画像** — 选择题+语音回答生成能力标签（无需简历）
4. **企业合规用工工具** — 内置《超龄用工协议》模板+按日工伤保险投保
5. **AI 岗位拆解** — 企业输入需求，自动生成岗位描述+合规模板+保险方案
6. **双向信用体系** — 出勤率+雇主好评+技能认证综合评分
7. **子女辅助模式** — 子女代为操作账号、接收进度通知
8. **时间银行** — 服务时长可兑换未来养老服务或社区福利

## 三、竞品与差异化分析

| 对比 | 银发聘 | 中国老年人才网 | 银发聘（现有竞品） | BOSS/58 同城 |
|------|-------|---------------|-----------------|-------------|
| 适老化体验 | **全语音+大字+地图** | 传统网站 | 一般 | 不适老 |
| 灵活用工 | **按小时/按天匹配** | 全职 | 全职为主 | 全职为主 |
| 按日保险 | **内置信保** | 无 | 无 | 无 |
| 合规模板 | **内置协议生成** | 无 | 无 | 无 |
| 技能画像 | **选择题+AI 生成** | 传统简历 | 传统简历 | 传统简历 |

**差异化优势：** 不做招聘做"灵活用工匹配" + 合规基础设施（协议+保险） + 全语音适老化设计。

## 五、核心模块详解

### 5.1 语音找工作（老人端）

**职责：** 让不会打字的老人用自然语言找到合适的零工

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 语音输入 | 老人说"我想找周六日帮人做饭的活" | 支持方言识别（首批粤语/四川话/上海话） |
| 语义理解 | 提取意图+技能+时间+地点四个维度 | 不依赖关键词匹配，同义表达均可理解 |
| 结果语音播报 | 匹配结果自动语音朗读 | 每次播报限 3 条，可重复听 |
| 语音下单 | 选中后直接语音确认接单 | 需提前完成实名认证 |

### 5.2 附近岗位地图

**职责：** 基于位置的零工推荐，降低出行门槛

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| LBS 定位 | 自动获取当前位置 | 需授权定位，可手动输入地址 |
| 通勤半径过滤 | 默认 2 公里，可调 | 最大不超过 5 公里（步行/公交舒适距离） |
| 地图模式 | 大图标+高对比度配色 | 点击显示距离和岗位摘要 |
| 列表模式 | 大字卡片列表，按距离排序 | 卡片含：时薪、时段、是否需要特定技能 |

### 5.3 技能轻画像

**职责：** 无需传统简历，通过互动方式生成老人能力标签

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 基础信息 | 年龄/性别/健康状况/可工作时间 | 健康状况用选择题（"能不能连续站 2 小时？"） |
| 技能图谱 | 从"你以前做过什么"展开 | 选择行业→选择岗位→确认技能点 |
| 证书认证 | 拍照上传+AI OCR 识别 | 支持退休证、职称证、技能证书 |
| 画像产出 | 自动生成可被搜索的能力标签 | 标签示例：{会计,代账,Excel,60岁,每天4小时} |

### 5.4 企业合规用工工具

**职责：** 让雇老人在法律和保险上可落地

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 用工协议生成 | AI 根据岗位信息自动生成 | 符合《超龄劳动者基本权益保障暂行规定》 |
| 按日保险投保 | 发单时自动绑定，按天扣费 | 费率 = 基本费率 × 岗位风险系数 |
| 风险系数表 | 岗位分类→保险定价 | 文职 0.5 元/天，家政 1 元/天，体力 2 元/天 |
| 合规档案 | 每个订单的协议+保险+考勤自动归档 | 保留 2 年，可用于劳务纠纷举证 |

**保险定价参考：**

| 岗位类型 | 风险系数 | 保费（元/人/天） | 赔付上限 |
|---------|---------|----------------|---------|
| 文职/顾问 | 低 | 0.5 | 10 万 |
| 家政/保洁 | 中 | 1.0 | 20 万 |
| 体力/搬运 | 高 | 2.0 | 30 万 |

### 5.5 信用体系

**职责：** 降低双端信任成本

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 老人信用分 | 出勤率×40% + 好评×30% + 技能×20% + 健康×10% | 初始 60 分，3 单后激活 |
| 企业信用分 | 按时结算×50% + 老人评价×30% + 纠纷率×20% | 低于 40 分限制发单 |
| 信用权益 | 高分老人→优先派单+更高时薪建议+免费保险升级 | 高信用企业→免抽佣期 |

## 六、用户流程

```
一、老人端流程

打开小程序 → 语音说"找活" 或 手动浏览
    ↓
① 首次使用：实名认证（人脸+子女辅助） → 技能轻画像（3-5 分钟）
② 已认证用户：进入附近岗位地图 / 语音搜索
    ↓
浏览岗位卡片（语音播报 / 大字列表）
    ↓
选择岗位 → 查看详情（时间/薪资/保险/距离）
    ↓
语音确认接单 → 系统记录 → 保险自动生效
    ↓
工作完成 → 企业线上确认 → 薪资到账
    ↓
双方评价


二、企业端流程

注册企业 → 实名认证（营业执照）
    ↓
发布岗位 → 语音/文字描述需求 → AI 拆解岗位
    ↓
AI 自动生成：岗位描述 + 用工协议模板 + 保险方案
    ↓
确认发布 → 平台推送匹配老人
    ↓
接收申请 → 查看老人画像（技能/信用/距离）
    ↓
确认人选 → 签署电子协议 → 保险生效
    ↓
工作完成 → 线上确认 → 结算薪资 → 评价
```

## 八、落地路径

### 8.1 MVP 最小可行产品

| 功能 | MVP | 后续 |
|------|-----|------|
| 语音找工作 | 关键词匹配+3 种方言 | 完整语义理解 |
| 附近岗位地图 | 列表模式，手动输入地址 | LBS 自动定位+地图模式 |
| 技能画像 | 选择题模板（会计/家政/保安 3 类） | AI 对话式画像 |
| 企业端 | 岗位发布+按日保险 | 合规模板+评价体系 |
| 信用体系 | 出勤率追踪 | 完整双端评分 |
| 子女辅助 | 短信通知 | 完整代操作模式 |

### 8.2 第一步验证

**最关键假设：** 退休老人愿意通过语音找零工。

**验证方法：** 不做 App，先做微信小程序，选择一个城市（建议武汉/成都），联系当地 3-5 家代账公司/家政公司入驻，通过老年大学/退休办招募 50 名种子老人用户，全程人工辅助走完接单流程。如果 2 周内复购率 > 30%，需求成立。

### 8.3 第一阶段聚焦

从 **退休会计+代账公司** 切入口：
- 老人端：证书可查、技能清晰、轻体力
- 企业端：月度/季度报税季有明确波峰波谷
- 匹配简单：通勤半径+CPA/职称+时间匹配

## 九、风险与预期反馈

| 预期槽点 | 应对方案 |
|---------|---------|
| "老人不会用小程序" | 语音优先+子女辅助模式+社区指导员 |
| "企业怕招老人出工伤" | 平台强制投保+合规模板+法律援助 |
| "子女反对父母打工" | 转化叙事为"老有所为"，不是"被迫打工" |
| "保险成本谁出" | 企业出（比社保便宜 90%） |
| "订单不够没密度" | 先做单一城市+单一品类（会计）打透 |
| "这不就是 58 的老年版" | 适老化设计+合规基础设施+按日零工才是根本差异 |

## 十、边界声明

| 不做 | 原因 |
|------|------|
| 全职/长期雇佣匹配 | 老人和企业的核心需求是灵活用工 |
| 代替子女赡养责任 | 平台解决"找事做"而非"养老送终" |
| 接入现有招聘平台 API | 仅基于自主注册的老人和企业 |
| 老人简历对外搜索暴露 | 仅向已认证的企业展示画像 |
| C 端收费 | 老人付费意愿极低，先做 B 端收入 |
| 医疗/护理类岗位 | 资质要求高、风险大，后期再考虑 |
| 老人个人健康数据商业化 | 健康信息仅用于岗位匹配，不做他用 |
| 代接送/代陪诊等贴身服务 | 涉及人身安全的服务需专用资质 |

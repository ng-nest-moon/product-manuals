# 一语成世界 — 产品功能说明书

## 一句话定义

面向普通用户的 AI 城市生成器——输入一句话或一段文案描述，几秒内生成一座可自由漫步、俯瞰、切换风格的立体 3D 城市，秒出、秒逛、随时导出。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

**主要用户：18-40 岁的创意泛大众（游戏爱好者、内容创作者、学生、故事作者）**

| 维度 | 描述 |
|------|------|
| 身份 | 没有专业美术/建模背景，但对"造一座城"有想象的人 |
| 日常行为 | 写小说/跑团设定世界观、剪视频、画插画、玩沙盒游戏 |
| 现有方案 | 想给世界找张"脸"，结果只能搜网图、手绘草图、或憋着不画 |
| 底层情绪 | 有想法，但不会建模、没渲染设备——"如果我能直接把它造出来就好了" |

**次要用户：小型游戏/内容团队**，需要快速产出城市概念，用于方案对齐与演示。

### 1.2 真实痛点分级

| 需求类型 | 痛点 | 用户行为证据 |
|---------|------|-------------|
| **刚需** | 有城市点子却不会建模，专业软件门槛太高（CityEngine 学一周起步） | 常靠临摹网图 / 放弃视觉呈现 |
| **刚需** | 生成概念图只有"一张图"，没有立体结构，想看的街区进不去 | 用 AI 画图工具反复生成但只有平面 |
| **改善型** | 做内容需要多种风格的城市（科幻/赛博/中世纪/田园），每次都从零 | 一个题材要搜集多张不同风格参考 |
| **改善型** | 想微调已生成的城市，但要重新画/重写提示词 | 改一处需求就要整张重出 |
| **猎奇伪需求** | "我要一个超真实的城市"——但大多数人要的是"够用、有氛围、能逛" | 过度追求真实反而不会用 |

## 二、解决方案与核心功能

### 2.1 解决方案概述

> 一语成世界 = 一句话生成 × 可漫游 3D × 对话式微调 × 一键导出。

不做"真实城市规划"，做**想法到可逛城市的直达通道**。用户输入任意风格的一句话，系统产出城市会持续探索的场景，并允许像问答一样持续"说"出自己的修改，而不是艰难调参数。

### 2.2 核心功能清单

1. **一句话起模** — 输入一句话或一段描述，生成城市/植被/光照的起始 3D 场景
2. **3D 漫游** — 支持自由视角、漫步、俯视、快进等多种视角，实时查看城市全貌
3. **对话微调** — 用自然语言持续调整单个要素（风格/温度/交通/坐标），无需重写提示词
4. **风格时代** — 科幻/现代/赛博朋克/中世纪/古典等风格模板一键切换
5. **局部编辑** — 点名局部地块替换其属性、删除建筑、复制地块
6. **可视化导航** — 图层/地表类型/光照显示，标注重复区域或某种功能密度
7. **多视角成果** — 生成多角度截图 / 全景 / 俯视图，保存为城市"相册"或世界观素材
8. **导出与分享** — 导出 3D 场景、高清截图、概念图与城市描述文档

## 三、竞品与差异化分析

| 竞品 | 优点 | 缺点 | 与本产品差异 |
|------|------|------|----------------|
| Midjourney 概念图 | 画面品质高、流行 | 只有"平面图"，无立体结构可逛 | 一语成世界产出"可走进了的 3D"而非一张图 |
| CityEngine / InfraWorks | 专业、可规划 | 学习门槛高、面向正从业者 | 面向零门槛泛大众，一句话起模 |
| SimCity / 沙盒游戏 | 可玩、有系统 | 需逐步建造、缺乏"AI 一句话"即时性 | 输入文案即时生成，无需逐栋搭 |
| 图片素材库 | 大量现成城市图 | 不是自己的世界、无原创性 | 生成专属城市，随想法而变化 |

**差异化核心：** "一句话起用 + 即时可漫游 + 对话式微调"三步合一的低门槛体验。

## 五、核心模块详解

### 5.1 一句话起模

**职责：** 把用户的自然语言描述转成一座可浏览的城市起始场景。

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 描述生成 | 输入一句话/多句，自动识别城市与风格 | 最短 1 句即可起模 |
| 模板速选 | 内置风格模板一键应用，再叠加入描述 | 模版为起点，可覆盖 |
| 随机灵感 | 无思路时一键生成随机城市灵感 | 提供 3 种惊异摘要供选择 |
| 冲突消解 | 描述中内容冲突（如"雨林又沙漠"，则取主导或提示） | 明确提示需要重选 |

### 5.2 3D 漫游与可视化

**职责：** 让用户像"逛一座真实存在的城"一样查看自己的创作。

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 自由视角 | 旋转、缩放、拖动看全局 | 无新手门槛，即时反应 |
| 漫游模式 | 以步行视角沿街道穿过城市 | 可暂停/快进 |
| 俯视模式 | 一键拉高俯瞰全局布局 | 配合标签看结构 |
| 时间光照 | 切换白天/黄昏/夜晚 | 夜间联动灯光效果 |

### 5.3 对话式微调

**职责：** 持续用自然语言让城市朝用户想要的方向变化，而非反复从头生成。

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 整城调整 | "把所有楼调高""换成暖色调"等全局命令 | 一次命令全局生效 |
| 局部点名 | 选中局部或说出方位修改该范围 | 范围可自定义大小 |
| 增量增删 | 只对变化部分重生成，其他保持不变 | 保持主体一致 |
| 历史还原 | 微调不满意可返回值某一步 | 保留若干快照 |

### 5.4 风格与时代

**职责：** 一键把城市换成另一套整体视觉体系，服务不同世界观需要。

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 风格模板 | 现代 / 赛博朋克 / 科幻 / 中世纪等 | 模板可叠加描述 |
| 时代切换 | 古代 / 近代 / 未来 / 架空 | 结构保留、外观变化 |
| 写实与风格化 | 真实系 / 手绘 / 像素风三档 | 切换成本低，可随时回退 |

### 5.5 局部编辑（点名改）

**职责：** 对特定坐标/范围的精确修改，满足"单独改一块"的诉求。

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 局部选择 | 框选/点选一个区域或单栋建筑 | 范围可粒化到单体 |
| 属性重注入 | 只更换选中的模板或属性 | 其余城市别更动 |
| 删除/移动/粘贴 | 对局部进行删除、搬移、复制 | 有操作撤消 |
| 承接细化 | 对局部放大后命令细化该处 | 局部与全局互不影响 |

### 5.6 成果输出与分享

**职责：** 把可逛的城市沉淀成可视化、可传播、可复用的产物。

| 功能点 | 说明 | 规则 / 约束 |
|--------|------|-------------|
| 高清截图 | 生成封面、仰视、夜景等多种构图 | 可选风格处理 |
| 城市相册 | 多视角自动收集成一套世界观 | 可命名沉淀 |
| 3D 场景导出 | 导出城市场景文件供其它工具用 | 限制单城规模 |
| 作品分享 | 生成链接供他人"线上逛" | 公开/私密可控 |

## 六、用户流程

```
想造一座城
   │
   ├─ 输入一句话（或选模板）
   │    例："一座被迷雾罩住的未来海港城"
   │
   ├─ 系统起模 → 生成可供探索的 3D 城市
   │
   ├─ 浏览 / 逛城
   │    ├─ 自动展示 或自由视角浏览
   │    └─ 切换 白天/夜晚/俯视
   │
   ├─ 不满意？
   │    └─ 对话微调： "再加一座跨海大桥""把建筑换成黑白"
   │
   ├─ 满意？
   │    └─ 导出：截图相册 / 高清图 / 3D 场景 / 分享链接
   │
   └─ 结束：沉淀为一套可用的城市世界观
```

## 七、应用场景

### 场景一：写小说/Run 团，想要世界观城市

> 作者写下"一座浸泡在紫雾与广告灯里的犯罪都市"，随即生成可随意俯瞰与漫步的赛博城，据此写街区与建筑细节，导出夜景图作为角色立绘的背景排版。

### 场景二：做视频/插画素材

**：** 博主用"一座被雪环抱的北欧渔港城"进行创作，切换冬天和黄昏，一键导出俯视与街景高清图，直接作为视频底与插画参考。

### 场景三：游戏/文案立项前的概念对齐

策划用"海底蒸汽钟鬼城"快速出三个风格的漫游原型，对齐美术方向，再把选定的一个导出 3D 场景递交给美术推进，省下大量沟通成本。

## 八、商业模式

| 付费模式 | 说明 |
|---------|------|
| 免费版 | 每日 N 次生成 + 基础漫游 + 截图（带水印） |
| Pro 月费 | 无限生成 / 4K 导出 / 3D 场景导出 / 无放大水印 |
| 团队版 | 多席位 + 协作书与资源调度 |

**基本原则**：核心"一句话起用"免费，让想造城的人先体验到"逛进自己的城"，把付费点放在输出（导出 / 规模 / 协作）上。

## 九、落地路径

### 9.1 MVP
一句话起模 + 基础漫游 + 2-3 个大城模板 + 对话微调局部示例 + 截图导出。目标：用户能"一句话起城 → 逛得舒服 → 存一张图"。

### 9.2 第一步验证

**最需要修证的核心假设：** 用户是否会在拿到可逛的城市后愿意停留、并多次用语言调整它。
**验证方法：** 发布 Web 版，让用户写一句话生成并逛 2 分钟，统计"浏览时长 > 3 分钟且至少改一次"的占比。若留存良好，则"一句话 → 可逛 → 改"的闭环成立。

## 十、边界声明

| 不做 | 原因 |
|------|------|
| 真实城市数据与卫星还原 | 定位创意生成，不做地理级还原 |
| 专业城市 B 端规划工具（管线/交通仿真）| 服务创意表达而非市政工程 |
| 高质量精细建模需 3D 软件 | 强调"即时与免购"替代重工具 |
| 多人实时联机 | 保持单机的轻量与聚焦 |
| 追求照片级渲染五感全开 | 优先场景与速度生效于认真 |

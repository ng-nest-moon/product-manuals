# 地震救援 — 产品功能说明书

## 一句话定义

俯视图即时策略救援模拟游戏——地震发生后，你是指挥官，在时间、物资、信息三重压力下调派救援力量，处理连锁灾害，做出艰难取舍，在被掩埋的城市的命运走向终局之前拯救更多生命。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

**主要用户：策略游戏爱好者（20-40 岁）**

| 维度 | 描述 |
|------|------|
| 年龄 | 20-40 岁，以 PC 游戏玩家为主 |
| 游戏偏好 | 喜欢 RTS、城市建造、模拟经营、生存类游戏 |
| 收入 | 有稳定收入，愿意为优质独立游戏付费 50-150 元 |
| 游戏习惯 | Steam 深度用户，关注独立游戏，对"经营/策略/灾难"标签感兴趣 |
| 日常痛点 | 市面上没有真正专注地震救援的深度策略游戏——要么太浅（点一下自动完成），要么太泛（多灾种但不专） |
| 深层需求 | 想要一个有决策重量、有信息不对称、每个选择都有后果的救援战术游戏 |

**次要用户：灾难应急爱好者、模拟类玩家**

| 维度 | 描述 |
|------|------|
| 场景 | 对应急救援感兴趣，喜欢模拟真实场景的游戏 |
| 需求 | 希望游戏有一定的真实感和专业性，而不是卡通化 |

### 1.2 真实痛点分级

| 需求类型 | 痛点 | 用户行为证据 |
|---------|------|-------------|
| **刚需** | 策略游戏玩家缺少垂直深度——多数救援游戏操作太浅 | Steam 评价中常见"太简单""点一下单位自动完成"的差评 |
| **刚需** | 决策缺乏重量——多数游戏的"选择"没有真正的后果 | 玩家渴望有道德困境、资源权衡、不可逆选择的游戏 |
| **改善型** | 灾害类游戏不够专业——地震只是背景板，没有真实感 | 相关游戏的 mod 社区经常出现"寻求更真实体验"的讨论 |
| **改善型** | 现有游戏的可重复性不够——通关后不再想玩 | 玩家追求多周目、随机生成、挑战模式的游戏 |
| **猎奇伪需求** | "想体验灾难"的观光心态 | 这种用户不会持续玩，浅尝辄止 |

## 二、解决方案与核心功能

### 2.1 解决方案概述

地震救援做一件事：**在地震救援这个细分赛道上做到最专业、最深度。**

核心设计理念：
- **信息不对称** — 不是全知全能的上帝视角，而是真实的指挥困境：你看到的永远是不完整的、可能错误的信息，必须主动侦察
- **操作有分量** — 不是点一下"救援"就自动完成，而是逐阶段决策：选择切入方式、控制破拆进度、决定救出顺序
- **决策有代价** — 每个选择都有真实后果：救这个人就可能错过那个区域，服从上级指令可能牺牲你的判断
- **深度可调** — 从"一键救援"到"完整五阶段破拆"，一条滑竿覆盖所有类型的玩家

### 2.2 核心功能清单

1. **俯视图城市指挥** — 以俯视图视角在一座受损城市中调派救援力量，点击建筑查看详情、框选单位下达指令
2. **多城市主题** — 沿海城市、山城、平原都会、工业城市、古城等 5 种以上主题，每种主题灾害表现和救援策略不同
3. **多层次地图** — 地表建筑+道路、地下空间（地铁/管廊/地下室）、基础设施网络（电力/供水/通信/燃气）三层联动
4. **动态灾害系统** — 地震破坏 → 余震二次坍塌 → 次生灾害链（火灾蔓延/燃气爆炸/危化品泄漏/水淹），无人处理的灾害持续恶化
5. **20+ 单位类型** — 搜救类、医疗类、消防/危化类、工程类、后勤/指挥类五大类别，各有独立职能
6. **单位成长体系** — 经验升级 + 专精技能树 + 装备配置 + 士气/疲劳管理 + 永久伤亡
7. **条件触发事件** — 灾害链事件、人物故事线、道德困境、上级指令、媒体舆论、国际援助六大类事件
8. **时间三重压力** — 全局倒计时 + 每个幸存者独立存活倒计时 + 单位行动需要时间，三管齐下制造紧迫感
9. **真实物资体系** — 7 类物资分质量等级，多维经济（拨款/捐赠/保险/国际援助），完整补给链（外部→仓库→前线）
10. **天气与昼夜** — 雨雪高温大风影响救援效率，夜间视野降低需照明设备，天气可动态变化
11. **社会与治安** — 民众恐慌/哄抢/谣言，需分配力量维持秩序，投入治安过少则局势失控
12. **完整灾后收尾** — 幸存者安置、防疫消杀、心理干预、重建规划，影响最终评分
13. **综合评分+详细战报** — S/A/B/C/D/E 六级评级 + 幸存者统计/时间线复盘/决策回顾/单位表现
14. **局外成长** — 指挥官技能树 / 基地建设 / 图鉴收集 / 成就系统 / 全局统计
15. **三种游戏模式** — 单人战役、自由模式（参数自定义随机生成）、挑战模式（特殊条件限制）
16. **全难度系统** — 预设（简单/普通/困难/专家）+ 自定义（逐项调节）+ 动态难度（自动适配）

## 三、竞品与差异化分析

### 3.1 竞品格局

| 游戏 | 类型 | 地震深度 | 救援细节 | 决策厚重 | 垂直深度 |
|------|------|---------|---------|---------|---------|
| The Big One（1990） | 城市管理 RTS | ★★ | ★★ | ★★★ | ★★ |
| 灾难大师（手游） | 多灾种策略 | ★★ | ★★ | ★★ | ★★ |
| Operator（itch.io） | 极简调度 | ★ | ★ | ★★★ | ★★ |
| Earthquake Rescue Beta | 教育模拟 | ★★★ | ★★ | ★ | ★★ |
| 急难先锋系列 | 综合应急 | ★★ | ★★★ | ★★ | ★★★ |
| 911 Operator | 接警调度 | ★ | ★ | ★★ | ★★ |
| 玩命救援模拟（手游） | 多灾种经营 | ★★ | ★★ | ★ | ★ |
| Rescue Ops Simulator（Steam） | 第一人称搜救 | ★★ | ★★★ | ★★★ | ★★★ |

**共同短板：** 要么做"通用救援"不专攻地震，要么做了地震但操作浅（点一下单位自动完成）。没有一款在地震救援的垂直领域做深做透。

### 3.2 五大差异点

| 差异维度 | 竞品做法 | 我们的做法 | 护城河评估 |
|---------|---------|-----------|-----------|
| 地震破坏模型 | 建筑随机倒塌，只分完好/倒塌 | 按结构分类，完整性百分比，余震序列，土壤液化 | 中等——需要专业知识积累 |
| 微观救援操作 | 派→等→完成，黑箱 | 五阶段破拆：评估→方案→执行→接触→移交 | 低——操作深度可模仿 |
| 信息不对称 | 信息 100% 可见 | 三层迷雾 + 信息置信度标记 | 中等——系统设计复杂度高 |
| 受困者个体化 | 纯数字，无差异 | 每个受困者有名字/年龄/关系网/故事 | 低——内容投入大但易复制 |
| 垂直深度自由调节 | 固定难度，不可拆分 | 6 个维度独立调节，新手到专家一网打尽 | 低——设计理念可复制 |

**核心护城河：** 不是单点功能，而是**地震救援的完整垂直深度**——当所有竞品都在做"通用救援"时，我们在地震这个单一场景里做到了最细。先发优势一旦建立，后来者需要同等的内容投入才能追上。

## 五、核心模块详解

### 5.1 指挥阶段

#### 5.1.1 简报阶段

| 环节 | 内容 | 玩家操作 |
|------|------|---------|
| 灾情简报 | 地震震级、震中位置、预估受灾范围、天气情况 | 阅读报告 |
| 地图概览 | 显示城区分区、已知建筑状态（部分信息隐藏） | 查看地图 |
| 初始部署 | 选择初始单位放置位置、分配初始物资 | 拖拽部署 |
| 确认开始 | 确认部署完成后地震"正式发生" | 点击开始 |

#### 5.1.2 黄金救援期

**特征：** 信息最不完整、受困者存活率高、外部援助未到。核心矛盾：先救容易救的还是先去找最难救的？

```
① 侦察区域 → ② 发现受困者 → ③ 派遣救援队 → ④ 救出 → ⑤ 医疗队救治
                ↘ 发现火情 → 派遣消防队
                ↘ 发现危化品 → 派遣危化组
```

#### 5.1.3 攻坚期

**特征：** 信息较完整、受困者陆续进入重伤/死亡、增援到达、次生灾害扩散。核心矛盾：救剩下的人越来越难，是否值得投入？

#### 5.1.4 收尾阶段

**核心矛盾：** 是最后一搏去救可能还活着的人，还是转向收尾提高灾后评分？

### 5.2 场景与 UI 交互

**主界面布局：**

```
┌───────────────────────────────────────────────────────────┐
│  ⏱ 12:34 │ 🚑 救出 23/67 │ 📦 物资 ████░░  │ ★ 当前评级 B │
├───────────────────────────┬───────────────────────────────┤
│                           │                               │
│     俯视图城市地图          │  ┌─ 事件 ──────────────┐     │
│     (可缩放/拖拽)          │  │ 余震！建筑二次坍塌   │     │
│                           │  │ [立即派人搜救]       │     │
│   🏠 🏠 🔥 🏚️            │  │ [先确认安全再进]    │     │
│        🚒                  │  └─────────────────────┘     │

├───────────────────────────┴───────────────────────────────┤
│  指令栏：[选中建筑查看] [派遣单位] [调配物资] [请求增援]   │
└───────────────────────────────────────────────────────────┘
```

### 5.3 随机事件系统

| 类型 | 举例 | 呈现方式 |
|------|------|---------|
| 灾害链 | 余震→燃气泄漏→爆炸→火灾 | 弹窗+后续需手动处理 |
| 人物故事 | 发现一位被困教师保护着学生 | 多阶段叙事选择 |
| 道德困境 | 救 5 个轻伤还是 1 个重伤 | 弹窗 2-3 选项 |
| 上级指令 | "立即优先救援学校区域" | 弹窗 + 抗命后果 |
| 媒体舆论 | 记者报道你们的进展 | 影响后续外部支持 |
| 国际援助 | 外国救援队到达，但需协调 | 弹窗+手动安排 |

### 5.4 单位与成长系统

**5 大类 20+ 单位类型：** 搜救类（救援队/搜救犬/无人机/生命探测仪）、医疗类（医疗队/野战医院/防疫组/心理救援）、消防类（消防队/危化品组/洗消组）、工程类（结构工程师/重型设备/道路抢修/电力抢修/供水抢修）、后勤类（指挥车/通讯组/物资运输/空投接收）。

**每个单位属性：** 等级 1-10、经验值、行动力、疲劳度、士气、生命值、技能树。执行危险任务可能永久伤亡。

### 5.5 多周目与重玩价值

随机生成城区布局 / 事件分支导向不同后续 / S/A/B/C/D/E 多重结局 / 指挥官技能树 / 基地建设 / 图鉴收集 / 成就系统 / 挑战模式 / 难度解锁 / 全局统计。

## 六、用户流程

### 6.1 首次游戏流程

```
启动游戏
    ↓
新手教程 → 基础操作指引（移动地图/选中单位/下达指令）
    ↓
选择难度 → 推荐"简单"模式（完整信息可见 + 一键救援）
    ↓
简报阶段 → 查看灾情报告 → 部署初始单位
    ↓
黄金救援期 → 侦察 → 发现受困者 → 派遣单位救援 → 处理突发事件
    ↓
攻坚期 → 评估后续策略 → 分配增援 → 控制次生灾害
    ↓
收尾阶段 → 安置幸存者 → 防疫消杀 → 评分结算
    ↓
查看战报 → S/A/B/C/D/E 评级 + 时间线复盘 + 决策回顾
    ↓
解锁局外成长 → 获取经验点 → 升级指挥官技能 → 准备下一局
```

### 6.2 一局游戏节奏

```
简报阶段（1-2 分钟）→ 阅读报告 + 初始部署
黄金救援期（10-15 分钟）→ 高强度救援 + 多次事件
攻坚期（8-12 分钟）→ 增援到达 + 次生灾害高峰
收尾阶段（3-5 分钟）→ 灾后处理 + 评分解锁
```

## 七、商业模式

### 7.1 定价区间

| 付费模式 | 定价区间 | 依据 |
|---------|---------|------|
| PC 买断制 | 68-98 元（Steam 首发） | 同类独立策略游戏标准价格带（环世界 188 元、This War of Mine 78 元） |
| 首发折扣 | 48-68 元（首周折扣） | 独立游戏常规首发折扣策略 |

### 7.3 盈利模式

| 收入来源 | 说明 | 预期占比 |
|---------|------|---------|

## 八、落地路径

### 8.1 五大落地难点

| 难点 | 详细描述 | 缓解策略 |
|------|---------|---------|
| 内容量 | 地震深度模型需要大量专业知识和内容制作 | 初期抽象化，简化物理模型，用游戏化代替真实感 |
| 平衡性 | 20+ 单位、6 类系统之间的平衡调优 | 前期固定参数，上线后基于数据调整 |
| AI 行为 | 事件中的 AI 角色行为和反应需要合理 | 事件采用脚本化编写，不做复杂 AI |
| 新手指引 | 系统复杂度高，新手容易茫然 | 简单模式大幅简化 + 交互式教程 |
| 定价 | 独立游戏定价天花板 | 靠 Demo + Wishlist 积累信心，不盲目提价 |

### 8.2 MVP 最小可行产品

**MVP 范围：** 一个城市主题 + 核心循环可跑通。

| 功能 | MVP 做法 | 非 MVP（后续再做） |
|------|---------|------------------|
| 地图 | 1 个城市主题，6-8 个区域 | 多城市主题、三层地图、地下空间 |
| 单位 | 5 个基础单位类型 | 20+ 单位、技能树、成长系统 |
| 救援操作 | 一键救援 | 五阶段破拆 |
| 事件 | 5-8 个脚本事件 | 事件链、道德困境、外部势力 |
| 难度 | 简单/普通 两档 | 完整可调系统 |
| 多周目 | 无 | 指挥官技能树、基地建设、挑战模式 |

**最低试错成本估算：**
- 开发：1-2 人 × 4-6 个月 ≈ 15-20 万
- 美术外包：5-10 万（像素风降低美术成本）
- 到可玩 Demo：3-4 个月

## 十、边界与原则

| 不做 | 原因 |
|------|------|
| 3D 画面 | 俯视图 2D 是核心风格，降低美术成本，聚焦玩法 |
| 真实物理模拟 | 抽象化灾害模型，重玩法轻模拟 |
| 多人在线 | 单人指挥游戏，不设计联机模式 |
| 内购/抽卡 | 买断制，不搞商业化设计 |
| 真实城市地图 | 虚构城市主题，避免合规问题 |
| UGC 编辑器 | MVP 阶段不开放自制关卡 |
| 移动端首发 | 以 PC 端为主，移动端后续考虑 |

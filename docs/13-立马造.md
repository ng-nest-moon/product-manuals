# 立马造 — 产品功能说明书

## 一句话定义

上传一份产品功能说明书（Markdown），系统自动拆解任务、生成代码并部署上线，输出一个可直接分享的链接。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

**主要用户：有想法但不会写代码的人**

| 维度 | 描述 |
|------|------|
| 身份 | 产品经理、创业者、学生、自由职业者 |
| 痛点 | 脑子里有个产品想法，但没法让它在浏览器里跑起来 |
| 现有解法 | 找外包（贵且慢）/ 学编程（太久）/ 用低代码（也还要学）|
| 核心诉求 | "把需求写成文档，剩下的系统来做" |

**次要用户：想快速出原型的开发者**

| 维度 | 描述 |
|------|------|
| 场景 | 想快速验证想法，不想折腾脚手架和部署 |
| 需求 | 从说明书到可交互产品，一键生成 |

### 1.2 真实痛点分级

| 需求类型 | 痛点 |
|---------|------|
| **刚需** | 非技术人员的产品想法无法快速落地验证 |
| **刚需** | 写代码的门槛把大量有想法的人挡在外面 |
| **改善型** | 低代码工具仍然需要学习拖拽/配置 |
| **改善型** | 开发者的原型验证过程繁琐（脚手架→编码→部署） |

## 二、解决方案与核心功能

### 2.1 解决方案概述

立马造把"写代码"这件事替换成"写文档"。用户写一份 Markdown 产品说明书，系统自动解析、生成代码并部署上线。

核心设计：
- **说明书驱动** — 不聊天、不拖拽、不改代码
- **一次生成** — 从零到可访问链接，全程自动化
- **零门槛** — 没有登录、没有配置环境、没有部署流程

### 2.2 核心功能清单

1. **说明书上传** — 粘贴 Markdown 或上传 .md 文件
2. **智能解析** — AI 读取说明书，提取功能模块、页面数量、数据模型
3. **计划预览** — 展示将要生成的内容（页面/模块/数据），可调整
4. **人工确认** — 用户在执行前可删除/合并某些模块
5. **实时进度展示** — 大白话加进度条，非技术用户也能看懂
6. **一键部署** — 生成完成后自动部署，产出可直接访问的链接
7. **模板启动** — 内置多套产品模板（内容页/表单/工具/管理面板）
8. **历史记录** — 记录每次生成的产物链接

## 三、竞品与差异化分析

| 竞品 | 优点 | 缺点 | 差异 |
|------|------|------|------|
| Bolt.new / v0 | AI 生成代码 | 需要对话式描述，仍需调试 | 立马造从结构化说明书出发 |
| 低代码平台 | 可视化拖拽 | 仍需学习平台操作 | 立马造零操作，上传即生成 |
| 外包开发 | 定制化程度高 | 贵（5k-50k）且慢 | 立马造分钟级免费/低价 |

**差异化优势：** 文档驱动（不是对话驱动）+ 零门槛（上传→链接）+ 结构化输出。

## 四、架构总览

```
用户层
  └── Web 端 —— 上传说明书 / 查看计划 / 确认执行 / 查看进度 / 获取链接

核心流程
  ├── 解析器 —— 读取 Markdown，提取功能模块、页面、数据
  ├── 规划器 —— 生成可执行开发计划
  ├── 生成器 —— 按计划创建项目文件
  └── 部署器 —— 部署上线，返回访问链接

状态层
  ├── 解析完成 → 等待确认
  ├── 生成中 → 实时进度
  ├── 已完成 → 可访问链接
  └── 失败 → 错误原因 + 重试
```

## 五、核心模块详解

### 5.1 说明书解析器

自动识别 Markdown 标题层级作为模块划分依据。从列表、表格、段落中提取功能点、推断页面数量（根据功能点关联关系）、识别用户角色和数据实体。

**解析结果示例：** 识别到 3 个页面（首页/详情页/管理页）、2 个数据实体（项目/分类）、页面关系（首页↔详情页）。

### 5.2 计划预览与调整

解析完成后展示可勾选清单：页面、数据实体、功能模块。用户可取消勾选不需要的部分。

### 5.3 产物

产物是可直接使用的 Web 页面，包含完整交互、数据可保存（本地）、手机适配。示例类型：信息展示页、工具页（计算器/打卡器/记账本）、表单页、内容页、管理面板。

产物特点：无需注册、无需登录、数据独立、手机可用、可反复使用。

### 5.4 模板启动

6 套内置模板（个人作品集/投票工具/书单管理/记事本/数据看板/购物清单），填入 3-5 个关键信息即可生成，无需写完整 Markdown。

## 六、用户流程

```
打开网站 → 选择「从模板开始」或「上传说明书」
  ↓
如果上传说明书：粘贴 Markdown 或上传 .md 文件
  ↓
系统解析（3-10 秒）→ 展示解析结果
  ↓
用户确认计划（勾选/取消模块）
  ↓
点击「开始生成」→ 等待（30 秒 - 3 分钟）
  ↓
完成 → 弹出链接：「你的产品已上线」
```

## 八、落地路径

### 8.1 MVP

说明书上传与解析（Markdown 输入 + AI 解析）→ 计划预览与确认 → 单页产物生成（展示/表单/工具）→ 自动部署与链接返回 → 实时进度展示。

### 8.2 第一步验证

**最关键假设：** 用户愿意花 2 分钟写一个 Markdown 文档来替代学习编程/低代码平台。

**验证方法：** 邀请 20 个有"产品想法但不会写代码"的人，提供模板填写，观察生成后打开链接的即时反应。如果 > 60% 表示"再来一次"，需求成立。

## 九、风险与预期反馈

| 预期槽点 | 应对方案 |
|---------|---------|
| "生成的东西不完整" | 确认时可以手动调整，减少预期落差 |
| "还不如我自己写" | 目标用户不是开发者 |
| "说明书怎么写" | 模板 + 示例说明书降低入门门槛 |
| "没有源代码" | 产物可用，不需要代码 |
| "AI 生成的能用吗" | 有限的功能范围确保质量可控 |

## 十、边界声明

| 不做 | 原因 |
|------|------|
| 登录注册系统 | MVP 零门槛，打开即用 |
| 数据库存储 | MVP 产物的数据存在浏览器本地 |
| 多人实时协作 | 产物是单人使用或分享查看 |
| 自定义域名 | MVP 使用统一子域名 |
| 支付/计费 | MVP 完全免费 |
| 移动端 App | 产物是 Web，手机浏览器可用 |
| 导出源代码 | MVP 产出可用的产品，不是开发工具包 |
| UGC 编辑器 | 不提供界面拖拽编辑 |
| AI 对话式生成 | 坚持"说明书驱动" |

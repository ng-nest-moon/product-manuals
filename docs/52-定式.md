# 定式 — 产品功能说明书

## 一句话定义

把每天两百次小选择压缩成十几条早已验证过的走法——一年只决定一次，剩下的时间不必再想。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

**主要用户：30-45 岁，决策电量每天下午三点就见底的人**

| 维度 | 描述 |
|------|------|
| 身份 | 中层管理者、创业者、独立开发者、双职工带娃父母 |
| 日常 | 一天要做几十上百个微小决定，晚上被问"吃什么"会突然烦躁 |
| 典型片段 | 衣柜塞满，早上站着发呆六分钟，最后还是穿那件旧的 |
| 已试过的方案 | 断舍离、胶囊衣橱、极简生活博主、待办清单、自动化工具 |
| 试过的结果 | 坚持两周，回归原样；或者变成新的维护负担 |
| 真实期待 | 不是"少买点"，是"这件事以后不用再想了" |
| 付费意愿 | 一年被这些琐事吃掉两百小时，愿意为"停下来"付一百块 |

典型用户不是极简主义爱好者，也不是懒人。他**自律、能干、有审美**，问题恰恰在于：越是事事都想选好，越是被无穷多的微小选择磨掉了判断力。他不缺意志力，缺的是一套**允许他不再决定**的结构。

### 1.2 真实痛点分级

| 需求类型 | 痛点 |
|---------|------|
| **刚需** | 每天大量重复决策无法外包——没人能替你决定穿什么、吃什么、买哪个 |
| **刚需** | 选择过载导致"比价瘫痪"：买个吹风机看三天测评，最后什么都没买 |
| **刚需** | 现有的极简方案本身需要持续维护，减负工具变成了新的负担 |
| **改善型** | 早上出门前的摩擦让人一整天起点就很差 |
| **改善型** | 家里吃饭、采购每天都要商量一遍，耗的是两个人的力气 |
| **改善型** | 想把"决定"集中到一年一次，而不是每天重新做一遍 |
| **猎奇伪需求** | 想让 AI 替自己做所有决定——重大决策不能外包，也不该外包 |
| **猎奇伪需求** | 想要"极简人设"——那是审美消费，不解决决策成本 |

关键区分：这款产品解决的是**决策的重复次数**，不是"东西太多"，也不是"审美不够好"。用户家里并不缺衣服，缺的是"今天不用想穿哪件"的许可。

## 二、解决方案与核心功能

### 2.1 解决方案概述

三步：**盘点 → 编译 → 冻结。**

先用两周记录"你到底在重复决定些什么"，算出这些决定一年吃掉多少时间；再把每类重复决策编译成一条「触发条件 → 唯一动作」的定式；最后**冻结 90 天**，期间只能执行不能修改。

设计的核心不是"帮你选得更好"，而是**把选择的频率从每天一次改成每年一次**。所以最关键的一条规则是：

> **定式不是不能改，是只能在指定日期改。**

想改的念头不会被压制，而是被**记录、搁置、到期统一处理**。九十天后回看，绝大多数当时的"必须换"已经不想换了——那一刻用户第一次看清：冲动不是需求。

### 2.2 核心功能清单

1. **决策流水盘点** — 连续 14 天只记一件事："今天你选了什么"，自动聚类出真正的重复决策清单
2. **决策税计算** — 按「频次 ×（耗时 + 注意力残留）」算出年化成本，把"烦"变成一个刺眼的数字
3. **定式编译** — 把一类决策写成「触发 → 唯一动作 → 例外」三段式，做到不用想就能执行
4. **定式卡** — 每条定式一屏可见：触发时机、唯一动作、例外条件、库存数量、下次复检日
5. **90 天冻结期** — 生效即锁定，期间只能执行不能修改，从机制上阻断反复推翻自己
6. **待改清单** — 想改时只允许"记下来"：写下想改什么、为什么、日期，然后搁置到期
7. **年度复检** — 一年一次，集中处理待改清单，一次性批量改，改完再冻结一年
8. **四张破例券** — 每季度 4 张，不累积；用掉一张今天可以完全自由选择，用完就等下一季
9. **冲突检测** — 新定式与旧定式矛盾时提示拆分，例如"全年同款"撞上"每周三次正式场合"
10. **同款白名单与复购** — 把选定的商品锁进白名单，低于库存阈值一键复购，不再重新挑
11. **72 小时冷静期** — 白名单之外的商品，下单前挂起三天；三天后还想买再买
12. **今日看板** — 首页只显示两栏：今天不需要你决定的事、今天需要你决定的 1 件事
13. **定式包市场** — 可导入他人打磨成熟的整套定式（程序员版、双职工带娃版、常出差版）
14. **交接卡** — 把定式导成一张卡，家人或助理可以照着执行采购、打包、备餐

## 三、竞品与差异化分析

### 3.1 同类替代品对比

| 竞品 | 优点 | 缺点 | 与本产品定位差异 |
|------|------|------|----------------|
| 断舍离 / 极简主义书籍 | 观念有冲击力，读完确实想扔东西 | 只解决"东西多"，不解决"每天还是要选"；且极易反弹 | 本产品不关心你有多少东西，只关心你要做多少次决定 |
| 胶囊衣橱 App | 搭配直观，能可视化衣橱 | 需要持续录入与维护，本质是又一个要打理的 App | 本产品允许你只有三套衣服，且不需要录入全部衣橱 |
| 订阅制配衣服务 | 省心，衣服寄到家 | 昂贵，审美被平台决定，且每季仍要重新选 | 本产品不卖衣服，只锁定你已经验证过的那一件 |
| 习惯打卡 App | 机制成熟，能坚持 | 打卡针对"做某事"，不针对"不做某个决定" | 本产品的成功指标是"今天少想了 N 次"，不是连续天数 |
| 自动化工具（IFTTT 类） | 能真正串起流程 | 面向数字任务，管不到穿衣吃饭这类物理决策 | 本产品的定式一半活在物理世界 |
| 通用 AI 助手 | 随时能问"今天穿什么" | 每次都要问一遍，等于把决定换成提问，成本没降 | 本产品一年只问一次，之后不再问 |

### 3.2 差异化优势与护城河

**核心差异：市面上所有"减法产品"都在减物品，只有它在减决定。**

第二个差异是**冻结机制**。所有效率工具都假设"你要随时可调"，本产品反过来假设"你调得越勤，越没有系统"。90 天不可改是一条反产品直觉的规则，但正是它把"又一次半途而废"变成了"一次就定下来"。

诚实评估护城河：**中等偏浅。**

- 功能层几乎不可守。定式编译、冷静期、复购白名单，任何一个团队两周就能抄完。
- 真正难抄的是两处：
  1. **定式库的沉淀**——三年后积累的上千条真实定式（某种职业、某种家庭结构下的成套走法），是别人拿不到的样本。
  2. **切换成本**——用户在冻结期里越久，待改清单越厚，年度复检的记忆越完整。中途换产品意味着把一年的决定重新做一遍，这件事没人愿意干。
- 品牌人格也算一层：敢对用户说"这九十天不许改"，需要产品有说"不"的性格，而大多数工具型产品做不到。

## 五、核心模块详解

### 5.1 决策流水盘点

**职责**：让用户第一次看见自己一天到底在决定什么。

不做复杂记录。只有一句话输入框，每天最多记 10 条，格式固定为「时间 + 我选了什么」。

| 字段 | 说明 | 示例 |
|------|------|------|
| 时间 | 大致时点，不要求精确 | 07:20 |
| 选了什么 | 一句话，不超过 20 字 | 又穿了那件灰 T |
| 纠结多久 | 三档：秒选 / 想了一会 / 站了很久 | 想了一会 |
| 心情 | 三档：无所谓 / 有点烦 / 很烦 | 有点烦 |

**14 天后自动聚类**，输出三类结果：

- **真重复**：一周出现 5 次以上（穿衣、早餐、通勤路线、晚饭）
- **假重复**：看着像重复，其实每次条件不同（回谁的消息、给孩子穿什么）
- **一次性**：不值得定式化（修水管、换手机）

只有"真重复"进入下一步。**这条筛选比功能本身更重要**——把不该定式化的事定式化，是这类产品最常见的失败方式。

### 5.2 决策税计算

**职责**：把"烦"换算成一个用户无法忽略的数字。

```
年化决策税 = 年频次 ×（单次耗时 + 注意力残留）
```

注意力残留是指：做完这个决定后，注意力回到正事上需要的时间。小决定的残留常被低估——它才是成本的大头。

| 决策 | 年频次 | 单次耗时 | 残留 | 年化成本 |
|------|-------|---------|------|---------|
| 今天穿什么 | 365 | 6 分钟 | 0 | 36.5 小时 |
| 早饭吃什么 | 365 | 8 分钟 | 2 分钟 | 60.8 小时 |
| 晚饭吃什么 | 365 | 15 分钟 | 3 分钟 | 109.5 小时 |
| 买菜买什么 | 104 | 20 分钟 | 5 分钟 | 43.3 小时 |
| 这个要不要买 | 260 | 9 分钟 | 6 分钟 | 65 小时 |
| **合计** | — | — | — | **约 315 小时 / 年** |

界面上的呈现方式固定为一句：**「你去年在这五件事上花了 315 小时，等于 39 个工作日。」**

不用"提升效率""节省时间"这类词。只给数字，让人自己对号入座。

### 5.3 定式编译

**职责**：把一类决策写成一条机器和人都能照着做的三段式。

```
【定式 · 工作日穿衣】
触发：周一至周五 07:00 起床后
动作：灰/藏青/白 三色同款 T + 深色直筒裤 + 同一双鞋
例外：见客户 → 加一件深色外套；下雨 → 换那双防水的
库存：T×5  裤×3  外套×1
复检：2027-01-01
```

三段式是硬性结构，缺一段不允许保存：

| 段 | 作用 | 不合格写法 |
|----|------|-----------|
| 触发 | 什么条件下进入这条定式 | "想穿的时候"（太虚，永远触发不了） |
| 动作 | 唯一的一个动作，不许有第二个选项 | "看心情挑一件"（这就是原问题） |
| 例外 | 允许偏离的唯一条件，最多 3 条 | "特殊情况另行考虑"（等于没有例外） |

**唯一动作是这条规则的灵魂。** 只要动作里出现"或""看情况""合适的话"，编译器直接拒绝保存，并提示：这条还没编译完。

### 5.4 冻结期管理

**职责**：用时间限制阻断"反复推翻自己"这个最常见的失败模式。

| 规则 | 说明 |
|------|------|
| 生效即冻结 | 定式保存后立即进入 90 天冻结，倒计时显示在定式卡右上角 |
| 冻结期内只读 | 不能修改、不能删除、不能新增同类定式 |
| 只能记待改 | 想改时唯一可做的事：写进待改清单（想改什么 + 为什么 + 日期） |
| 到期处理 | 90 天到期或每年 1 月 1 日复检，一次性处理全部待改项 |
| 复检后重冻 | 处理完立即重冻，进入下一个周期 |

**待改清单的心理学设计**：清单只写不提醒，到期前不推送任何消息。系统会在复检日给每条待改项标一行小字：**「写下时你说很急，距今 87 天。」**

这条小字是整个产品最锋利的地方。它不劝人，只陈列时间。

### 5.5 破例券

**职责**：给"人需要变化"留一个受控出口，避免定式变成苦行，也避免失控。

| 参数 | 规则 |
|------|------|
| 数量 | 每季度 4 张 |
| 累积 | 不累积，季度末清零 |
| 用法 | 用掉一张 = 今天可以完全自由选择，不需要理由 |
| 记录 | 用掉时可选填一句"为什么"，不强制 |
| 提醒 | 只在季度末告知剩余张数，平时不催 |

**为什么是 4 张**：一个月一张多一点。够应付突发心情、约会、重要场合，不够把破例变成日常。数量本身就是设计——如果给 30 张，等于没有定式；如果给 0 张，用户会在第三周偷偷破戒，然后彻底放弃。

### 5.6 冲突检测

**职责**：防止两条各自合理的定式，叠在一起变得不可执行。

| 冲突类型 | 例子 | 处理 |
|---------|------|------|
| 场景重叠 | 穿衣定式"全年同款" × 社交定式"每周三次正式场合" | 提示拆成"日常 / 正式"两条 |
| 时间打架 | 早餐定式 07:00 × 通勤定式 07:10 出发 | 提示调整触发时点 |
| 库存矛盾 | 采购定式"每月一次" × 饮食定式"每周三次鲜蔬" | 提示补一条中间补给 |
| 例外过多 | 单条定式例外超过 3 条 | 强制要求拆成两条定式 |

**判定原则**：一条定式如果需要超过 3 个例外才能成立，说明它其实覆盖了两个不同场景，应该拆开，而不是继续加例外。

### 5.7 复购与冷静期

**职责**：把"买东西"从一次次重新比价，变成一次锁定后的自动补给。

| 机制 | 说明 |
|------|------|
| 同款白名单 | 录入商品：名称、尺码、颜色、链接、单件价格、安全库存 |
| 库存阈值 | 低于阈值自动提醒，一键复购，不再重新挑 |
| 冷静期 | 白名单之外的商品，下单入口挂起 72 小时，到期才可下单 |
| 冷静期统计 | 每月告知：挂起 N 件，三天后仍买了 M 件——比例越低，冲动越多 |
| 停产处理 | 白名单商品下架时推送"替代品确认"，替代品一经确认即锁定三年 |

**冷静期不是拦着用户买，是把"想要"和"需要"隔开三天。** 大部分东西会在这三天里自己消失。

### 5.8 今日看板

**职责**：首页只回答一个问题——今天我需要想什么。

```
┌─────────────────────────────────────┐
│  今天不用你决定                      │
│  ✓ 穿什么      ✓ 早饭      ✓ 通勤路  │
│  ✓ 晚饭（周三 · 番茄牛腩）           │
├─────────────────────────────────────┤
│  今天需要你决定 · 1 件               │
│  → 要不要接那个外包项目              │
├─────────────────────────────────────┤
│  本月已省下 187 次决定               │
│  破例券余额 3 / 4                    │
└─────────────────────────────────────┘
```

**界面硬约束**："需要你决定"这一栏最多显示 3 件，超过 3 件时只显示前 3 件加一行"其余 11 件明日再看"。这条约束的意义是：**看板本身不能变成新的待办清单。**

## 六、用户流程

```
首次使用（前 14 天）
  │
  ├─ ① 只装一件事：每天记 10 条"我选了什么"
  │        └─ 记录量不足 5 天 → 提示"样本太少，再记几天"
  │
  ├─ ② 自动聚类 → 分出真重复 / 假重复 / 一次性
  │        └─ 真重复不足 3 类 → 告知"你的重复决策很少，可能不需要这个产品"
  │
  ├─ ③ 算出年化决策税 → 一屏只有一个数字
  │
  ├─ ④ 逐类编译定式（触发 / 唯一动作 / 例外，缺一段不让存）
  │        └─ 动作里含"或""看情况" → 拒绝保存，提示没编译完
  │
  ├─ ⑤ 冲突检测 → 重叠 / 打架 / 例外超 3 条 → 要求拆分
  │
  ├─ ⑥ 一键冻结 → 倒计时开始，90 天内只读
  │
  └─ ⑦ 今日看板开始工作：不用决定的事逐条打勾

日常使用（冻结期内）
  │
  ├─ 早上 → 看板列出今天不用想的事 → 照做 → 打勾
  ├─ 想改定式 → 只能写进待改清单 → 不推送、不提醒
  ├─ 实在想换 → 用一张破例券 → 今天完全自由
  ├─ 想买白名单外的东西 → 挂起 72 小时
  └─ 库存低于阈值 → 推送补货 → 一键复购

到期（第 90 天 或 1 月 1 日）
  │
  ├─ 待改清单全部展开，每条附一句"距今 N 天"
  ├─ 用户逐条判：改 / 不改 / 再放 90 天
  ├─ 批量提交 → 重新编译 → 再次冻结
  └─ 输出年度小结：今年省下多少次决定、破例用了几张、哪些念头到期后自己消失了
```

## 七、商业模式

### 7.1 定价区间

**订阅 19 元/月，或 99 元/年；定式包单卖 9.9-29 元。**

定价依据不是成本，是替代参照：一杯咖啡 30 元，一次外卖纠结 15 分钟。99 元换一年 300 小时，用户算得过来。

**不做免费版**。这个产品一旦免费，用户不会认真写"唯一动作"，会写成"看情况"，而无唯一动作的定式等于没有定式，用了没效果反而砸口碑。首次盘点（14 天记录 + 决策税）免费，够体验，不够依赖。

### 7.2 销售渠道

- **内容引流**：只写一种内容——真实的决策税账单。"我把去年穿衣吃饭的决定算了一遍，315 小时"。数字比观点传播得快。
- **定式包传播**：程序员版、双职工带娃版这类成品定式包，天然适合在垂直社区扩散，且带自传播属性（用户会晒自己的定式卡）。
- **不做投放**。这类产品靠"看见别人的账"转化，投放拉来的多是猎奇用户，留存极差。

### 7.3 盈利模式

| 收入 | 说明 |
|------|------|
| 订阅 | 主收入，解锁无限定式 + 冻结期管理 + 年度复检 |
| 定式包 | 他人打磨成熟的成套走法，作者分成 50%，形成供给侧 |
| 实体定式卡 | 一套 12 张硬卡，贴在衣柜和冰箱上，定价 49，作为周边与礼品 |
| **不做** | 不做电商导购、不做返佣、不做品牌合作推荐 |

最后一条是商业模式的底线，也是产品的信誉来源：**一旦靠卖货赚钱，"帮你少买"就变成了利益冲突。** 这条边界比多一条收入重要得多。

## 八、落地路径

### 8.1 五大落地难点

| 难点 | 具体表现 | 应对 |
|------|---------|------|
| 用户觉得"这也要管" | 一听要记录 14 天就烦，觉得比原来更麻烦 | 只记一句话，每天 30 秒；且明确告知第 15 天开始就不用记了 |
| 定式僵化伤生活 | 全照定式活，三个月后觉得日子没劲 | 破例券兜底；年度复检强制"至少改一条"，防止完全不动 |
| 家人不配合 | 你的定式管不了伴侣和孩子 | 定式只约束自己；交接卡可选共享，不强制 |
| 同款停产 | 锁定的商品下架，整套系统失效 | 白名单支持"替代品确认"，且建议一次备足三年量 |
| 产品自己变成负担 | 配置项越加越多，用户又要开始选 | 定式总数硬上限 20 条，超出必须先停一条才能加 |

最后一条是这个产品最容易死的地方，也是必须写进产品规则的：**一个用来消除选择的产品，绝不能自己变成一堆需要选择的功能。** 因此所有设置项总数不超过 9 个，且不提供主题、皮肤、布局自定义。

### 8.2 MVP 最小可行产品

**只做一件事：穿衣定式。**

砍掉：饮食、采购、通勤、社交、工作节奏，五类全部不做；砍掉破例券、冲突检测、定式包市场、交接卡。

保留：穿衣流水记录 + 决策税 + 一条穿衣定式 + 90 天冻结 + 待改清单。

形态可以只是一个网页 + 每天早上一条推送。验证周期 90 天（这个产品的验证周期天生就长，因为冻结期就是验证本身），成本一个人力。

### 8.3 第一步验证

**最关键假设**：人愿意把审美决定权交出去，换取注意力。

**验证方法**：找 20 个目标用户，收 199 元押金，签一份《90 天穿衣协议》——90 天内只穿定式内的那几套，每天打卡一张出门照。

不问"你喜不喜欢这个产品"。只看到期那天，有几个人续费。

**通过标准**：20 人里 **≥12 人完成 90 天**（说明可执行），其中 **≥8 人愿意付 99 元续费**（说明有价值）。

低于 12 人完成，说明定式不够日常化，是设计问题；完成了但没人续费，说明"省时间"这件事对用户不值钱，整个命题要重做。

## 九、风险与预期反馈

### 9.1 预期负面吐槽

| 吐槽 | 背后的真实问题 | 应对 |
|------|--------------|------|
| "这不就是懒吗" | 被贴上标签，有羞耻感 | 明确话术：懒是不想动，这是把力气留给值得动的事。两者结果相反 |
| "我穿一样的，同事会觉得我不换衣服" | 社交压力是真实成本 | 定式支持"同款多件"备案；也可给"日常 / 正式"两套，用冲突检测拆分 |
| "定式过时了怎么办" | 怕被困住 | 冻结只有 90 天，不是终身；且年度复检强制至少改一条 |
| "最后又变成一个要维护的 App" | 最致命的反馈 | 定式总数上限 20 条，设置项 ≤9 个，不做任何主题与布局自定义 |
| "它算的 315 小时不准" | 数字被质疑，信任崩塌 | 所有耗时都显示算法与默认值，允许用户逐项改成自己的数 |
| "我不想被规则管着" | 反感被约束 | 破例券就是为此存在；且强调规则由用户自己写，系统只负责不让改 |

## 十、边界与原则

| 不做 | 原因 |
|------|------|
| 不做穿搭推荐与审美评判 | 审美是主观的，一旦评判就会引导消费，与"减决定"背道而驰 |
| 不做电商导购与返佣 | 靠卖货赚钱就无法真诚地劝人少买，这是结构性利益冲突 |
| 不接管重大决策 | 买房、结婚、换城市这类决策只发生几次，不值得定式化，也不该外包 |
| 不做社交比较与打卡排名 | 一旦有排名，用户会为了连续天数做假，系统就失去真实性 |
| 不追求极简美学 | 产品不是审美主张，衣服多的人也能用，只要他不用每天决定 |
| 不替用户修改定式 | 系统只负责执行与冻结，改不改永远由用户在复检日自己决定 |
| 不提供无限配置 | 配置项本身就是新的选择，这是产品最需要自我克制的地方 |
| 不做全生活覆盖 | 只处理每周出现 3 次以上的重复决策，其余一律不管 |
| 不承诺提升幸福感 | 它只减少决定次数，情绪、意义、满足感不在承诺范围内 |

## 十一、配置示例

### 三个典型定式包

| 参数 | 程序员版 | 双职工带娃版 | 常出差版 |
|------|---------|-------------|---------|
| 穿戴 | 同款黑/灰 T ×6 + 同款长裤 ×3 + 同款外套 ×1 | 通勤 3 套 + 周末 2 套，全部同款多件 | 一套"行李箱定式"：衣物固定 12 件，装箱图固定 |
| 饮食 | 早餐固定 A（燕麦+蛋）/ B（包子+豆浆）二选一 | 一周七天菜单固定，周末一天自由 | 出差期固定：酒店早餐 + 同一家简餐 |
| 采购 | 每月 1 日一次性补货，白名单 11 项 | 每周日 20:00 线上下单，清单固定 | 出行前 1 天按装箱图一次买齐 |
| 通勤 | 固定路线，不看导航 | 固定送娃路线 + 固定返程路线 | 固定航司 + 固定时段 |
| 社交 | 默认不参加，需要理由才去 | 每月固定 1 次家庭日 | 出差期不安排私人会面 |
| 定式总数 | 9 条 | 14 条 | 11 条 |
| 破例券 | 4 张 / 季 | 6 张 / 季（带娃突发多） | 4 张 / 季 |
| 年度决策税（预估） | 约 210 小时 | 约 340 小时 | 约 260 小时 |

# 挑刺工坊 — 产品功能说明书

## 一句话定义

让应用像产品一样被评估：用户执行真实任务，系统从操作效率、界面可用性、流程完整性三个维度自动分析，输出体验评分与改进建议。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

**主要用户：AI 应用的产品经理和设计师**

| 维度 | 描述 |
|------|------|
| 角色 | AI 应用的产品经理、交互设计师、用户研究员 |
| 场景 | 做竞品分析、内部产品体验评审、上线前的体验验收 |
| 日常行为 | 自己手动测试竞品、逐个记录操作路径、手工整理对比表 |
| 底层痛点 | 体验评估高度依赖主观判断，缺少量化和自动化工具 |

**次要用户：创业团队和开发者**

| 维度 | 描述 |
|------|------|
| 场景 | 自己做了一个 AI 应用，想看看用户体验到底怎样 |
| 需求 | 简单的体验评分工具，不用专业研究背景也能用 |

### 1.2 真实痛点分级

| 需求类型 | 痛点 | 用户行为证据 |
|---------|------|-------------|
| **刚需** | 产品经理做竞品分析全靠手动截图+录屏，效率极低 | 手动测试一个场景需要 30 分钟+整理时间 |
| **刚需** | 体验评估标准不统一，不同人评出不同结果 | 团队内部评审时经常有分歧 |
| **改善型** | 无法量化用户体验的"好"和"差" | 汇报时只能展示截图和主观描述 |
| **改善型** | 改进建议缺乏数据支撑 | "我觉得不好用"说服力不够 |
| **猎奇伪需求** | "我要 100% 自动化的体验评估" | 完全自动化的体验评估在当前技术下不可靠 |

## 二、解决方案与核心功能

### 2.1 解决方案概述

挑刺工坊是一个端到端的 AI 应用体验评估工具。用户定义评估任务 → 录制操作过程 → 系统自动分析 → 生成量化评分和改进建议。

核心设计：
- **标准化评估框架** — 操作效率、界面可用性、流程完整性三维度量化评分
- **操作录制 + 截图采集** — 执行过程中自动记录每一步
- **瓶颈自动识别** — 卡点、迷失、重复操作一键定位
- **竞品横向对比** — 同一场景下多应用体验对比
- **改进建议生成** — 基于数据自动输出可落地的优化方案

### 2.2 核心功能清单

1. **评估场景管理** — 预设 + 自定义评估场景，覆盖应用主流使用场景
2. **任务设计器** — 定义用户角色、目标任务、预期操作路径、成功标准
3. **操作录制与回放** — 录制用户在应用中的完整操作，支持回放标注
4. **界面可用性评估** — 布局、导航、反馈、一致性、响应式自动检测
5. **流程效率分析** — 任务完成率、操作步数、耗时、迷失度、重复率
6. **交互体验评估** — 自然度、流畅度、学习成本、容错性、满意度
7. **用户旅程可视化** — 操作路径热图、漏斗图、时间轴
8. **竞品对比评估** — 同一场景下多个应用的体验横向对比
9. **瓶颈自动识别** — 自动标记操作卡点、高跳出率步骤、重复操作
10. **改进建议生成** — 基于评估数据自动生成界面/流程/交互的优化建议
11. **报告生成** — 体验评分卡 + 旅程图 + 瓶颈列表 + 改进建议

## 三、竞品与差异化分析

| 竞品 | 优点 | 缺点 | 差异 |
|------|------|------|------|
| 人工竞品分析 | 深度好，分析师能发现深层问题 | 耗时、主观、标准不统一 | 挑刺工坊量化 + 自动化 |
| Hotjar / FullStory | 用户行为分析工具 | 针对自有产品，不适合竞品分析 | 挑刺工坊专门做第三方应用评估 |
| 可用性测试服务 | 专业机构，结果可信 | 成本高、周期长 | 挑刺工坊即开即用、自助服务 |

**差异化优势：** 聚焦 AI 应用场景 + 标准化量化评估 + 竞品横向对比 + 自动出改进建议。

  ├─ 竞品对标（多应用横向对比）
  └─ 改进建议（自动生成优化方案）

## 五、核心模块详解

### 5.1 场景库与任务设计器

系统预置典型评估场景：智能客服、写作助手、数据分析助手、编程助手、搜索工具、绘图工具、通用对话。用户可自定义场景名称、角色描述、任务列表、预期完成路径。

每个评估任务包含：任务名称、用户角色、起始状态、成功标准、预期路径（可选）、难度等级、关联评估维度。

竞品配置支持预置登录凭证和对比维度权重。

### 5.2 操作录制器

评估人员执行任务时，系统自动记录：鼠标事件（点击坐标/右键/悬停/拖拽）、键盘输入、页面跳转、滚动行为、时间戳、屏幕截图、系统响应内容与耗时。

**迷失度检测规则：** 同一页面连续点击 3 次以上无跳转 → 迷失；URL 回退 → 回退；输入框反复修改同一内容 2 次以上 → 犹豫；超过 15 秒无操作 → 思考停顿。

### 5.3 界面可用性分析

基于截图和操作数据自动评估：布局合理性（信息密度/视觉层级）、导航清晰度、反馈即时性、一致性（跨页面风格统一）、信息可读性（字号/对比度/色彩）、错误提示质量、响应展示体验。

每项 1-10 分：9-10 无需改进，7-8 细微瑕疵，5-6 明显问题，3-4 严重问题，1-2 功能不可用。

### 5.4 流程效率分析

以任务为单位分析：任务完成率、操作步数、任务耗时、偏离度（实际路径与预期路径差异）、迷失度（无效操作 / 总步数）、重复操作率、首次成功时长、辅助求助次数。

**漏斗分析示例：** 退货任务：客服入口（100%）→ 描述问题（85%，15% 放弃）→ 系统理解（70%）→ 上传凭证（60%，10% 找不到入口）→ 确认提交（55%），总体流失率 45%。

### 5.5 报告层

**体验评分卡：** 操作（完成率/步数/迷失度）、界面（布局/反馈/一致性）、流程（转化漏斗/容错性/分支覆盖）三维度加权评分。

**瓶颈自动识别规则：** 操作步数 > 预期 2 倍 → "步数过多"；某步骤流失率 > 20% → "高流失率"；同一位置重复操作 > 2 次 → "用户困惑"；某步骤耗时 > 平均 3 倍 → "异常耗时"；截图 OCR 检测到"错误"/"失败"文案 → "错误状态"。

**竞品对标：** 同一场景下多应用体验评分、任务完成率、平均步数、耗时、迷失度、界面评分、用户满意度横向对比，最佳值绿色高亮，最差值红色高亮。

**改进建议生成：** 来自界面分析（布局调整）、操作分析（流程简化）、对话分析（交互优化）、漏斗分析（流失干预）、竞品对比（功能补齐）。

## 六、用户流程

```
定义评估任务
  ├─ 选择/创建场景 → 设计任务 → 配置竞品
  ├─ 开始录制 → 执行任务（记录操作轨迹+截图）
  ├─ 采集主观反馈（每步评分 + 完成后 SUS）
  └─ 提交评估
    ↓
系统自动分析 → 生成报告
    ↓
查看体验评分卡 → 旅程图 → 瓶颈列表 → 改进建议
    ↓
竞品对比（多应用横向评估）
```

## 七、商业模式

| 付费模式 | 定价 | 依据 |
|---------|------|------|
| 按次付费 | 50-100 元/次评估 | 单次竞品分析或内审使用 |
| 团队月付 | 500-2000 元/月 | 产品团队持续使用的画风 |
| 企业版 | 按需定价 | 私有化部署 + 定制场景 |

**用户心理价位：** 一次专业可用性测试收费 5000-20000 元，挑刺工坊成本更低。

**盈利模式：** 纯 SaaS 订阅，不做广告和数据销售。

## 八、落地路径

### 8.1 落地难点

| 难点 | 缓解策略 |
|------|---------|
| 操作录制在第三方网站不稳定 | 浏览器插件方案 + 强烈推荐 Chrome |
| AI 分析评分不够准确 | 评分作为参考，非绝对结论 |
| PM 不习惯结构化评估 | 预设场景降低使用门槛 |
| 竞品评估的合规性 | 只做公开可访问的应用，不涉及授权内容 |

### 8.2 MVP

- 浏览器录制插件（仅 Chrome）
- 预设 3 个评估场景
- 操作效率分析 + 基础旅程图
- 单应用评估（无竞品对比）

### 8.3 第一步验证

**最关键的假设：** 产品经理愿意用自动化工具替代手动竞品分析。

**验证方法：** 邀请 10 个 AI 产品经理试用，录制一个竞品分析任务。观察他们是否在第二次评估时继续使用而不是回去手动做。

## 九、风险与预期反馈

| 预期槽点 | 应对方案 |
|---------|---------|
| "评分不准" | 评分标注为"参考"，展示详细推理链 |
| "我还是自己来吧" | 展示时间是手动操作的 1/5 |
| "录制不稳定" | 回放编辑功能，允许手动修正 |
| "只能评估 AI 应用？" | 通用框架，但初期垂直聚焦 AI |

## 十、边界声明

| 不做 | 原因 |
|------|------|
| 模型层 Benchmark | 不评估模型本身，只评估应用体验 |
| 性能压测 | 不测高并发/QPS |
| 代码级测试 | 不测 API 返回格式 |
| 自动化 UI 测试替代 | 不替代 Selenium/Playwright 回归测试 |
| A/B 实验平台 | 不在线分流用户流量 |
| 移动端录制 | MVP 仅支持 Web |
| 真实用户大规模采集 | MVP 以专家评估 + 小样本用户测试为主 |
| 自动修复 | 发现问题后不自动改代码，只出建议 |

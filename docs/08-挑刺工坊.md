# 挑刺工坊 — 产品功能说明书

## 一句话定义

让应用像产品一样被评估：用户执行真实任务，系统从操作效率、界面可用性、流程完整性三个维度自动分析，输出体验评分与改进建议。

---

## 一、系统架构总览

```
评估任务定义层
 ├── 场景库 —— 预设评估场景模板（客服 / 写作 / 数据分析 / 编程助手）
 ├── 任务设计器 —— 定义用户角色、目标任务、成功标准
 └── 竞品配置 —— 指定要对比的应用（多个）

数据采集层
 ├── 操作录制 —— 录屏 + 操作轨迹（点击/输入/滚动/页面跳转）
 ├── 界面截图 —— 关键步骤自动截图
 ├── 眼动/热区 —— 用户注意力区域记录（可选）
 └── 反馈采集 —— 用户每步的主观感受评分

分析引擎
 ├── 操作分析 —— 步数、耗时、路径、重复操作、迷失度
 ├── 界面分析 —— 布局密度、信息层级、反馈清晰度、一致性
 └── 流程分析 —— 完成率、转化漏斗、异常退出点、容错性

报告层
 ├── 体验评分卡 —— 各维度量化得分
 ├── 用户旅程图 —— 操作路径可视化
 ├── 瓶颈分析 —— 卡点、迷失、重复识别
 ├── 竞品对标 —— 多应用横向对比
 └── 改进建议 —— 自动生成优化方案
```

---

## 二、核心功能清单

1. **评估场景管理** — 预设 + 自定义评估场景，覆盖应用主流使用场景
2. **任务设计器** — 定义用户角色、目标任务、预期操作路径、成功标准
3. **操作录制与回放** — 录制用户在应用中的完整操作，支持回放标注
4. **界面可用性评估** — 布局、导航、反馈、一致性、响应式自动检测
5. **流程效率分析** — 任务完成率、操作步数、耗时、迷失度、重复率
6. **交互体验评估** — 自然度、流畅度、学习成本、容错性、满意度
7. **用户旅程可视化** — 操作路径热图、漏斗图、时间轴
8. **竞品对比评估** — 同一场景下多个应用的体验横向对比
9. **瓶颈自动识别** — 自动标记操作卡点、高跳出率步骤、重复操作
10. **改进建议生成** — 基于评估数据自动生成界面/流程/交互的优化建议
11. **报告生成** — 体验评分卡 + 旅程图 + 瓶颈列表 + 改进建议

## 三、评估任务定义层

### 3.1 场景库

系统预置典型评估场景：

| 场景 | 说明 | 典型任务示例 |
|---|---|---|
| **智能客服** | 用户通过对话解决问题 | 退换货申请、发票开具、账号申诉 |
| **写作助手** | 辅助内容创作 | 写周报、改简历、生成营销文案 |
| **数据分析助手** | 数据问答与可视化 | 导入 CSV 做分析、生成图表 |
| **编程助手** | 代码生成与调试 | 生成 API 接口、调试 Bug、代码审查 |
| **搜索工具** | 信息检索与整合 | 调研竞品、文献综述、知识库问答 |
| **绘图工具** | 文生图/图生图 | 生成海报、修图、风格迁移 |
| **通用对话** | 开放域聊天 | 闲聊、头脑风暴、翻译 |

用户可自定义场景，包含：场景名称、角色描述、任务列表、预期完成路径。

### 3.2 任务设计器

每个评估任务包含：

| 字段 | 说明 | 示例 |
|------|------|------|
| 任务名称 | 一句话描述 | "通过客服助手申请退货退款" |
| 用户角色 | 使用者的背景假设 | "普通消费者，不太熟悉流程" |
| 起始状态 | 任务开始前的前提 | "已登录，在首页" |
| 成功标准 | 任务完成的判定条件 | "提交退货申请并看到确认页面" |
| 预期路径 | 理想的操作步骤（可选） | 首页→客服入口→描述问题→上传凭证→提交 |
| 难度等级 | 简单 / 一般 / 复杂 | 一般 |
| 关联维度 | 该任务重点评估的维度 | 流程 + 界面 |

### 3.3 竞品配置

| 字段 | 说明 |
|------|------|
| 应用名称 | 如"应用 A"、"应用 B" |
| 访问方式 | Web URL / 桌面客户端 / 移动端 |
| 登录凭证 | 预置账号或 SSO 配置 |
| 对比维度权重 | 每个竞品可单独配置（界面/流程/操作 权重） |

## 四、数据采集层

### 4.1 操作录制器

评估人员（或真实用户）在执行任务时，系统自动记录：

| 数据类型 | 记录内容 |
|---------|---------|
| **鼠标事件** | 点击坐标、右键、悬停、拖拽轨迹 |
| **键盘输入** | 输入内容、组合键、快捷键 |
| **页面跳转** | URL 变更、路由切换、弹窗打开/关闭 |
| **滚动行为** | 滚动方向、滚动距离、停留位置 |
| **时间戳** | 每个操作的精确时间点 |
| **屏幕截图** | 关键节点自动截图（点击前、跳转后、弹窗时） |
| **系统响应** | 回复内容、响应耗时、流式输出过程 |

**录制格式示例：**

```
t=0.00    navigate    https://example.com
t=1.20    click       (320, 180)    输入框聚焦
t=2.50    type        "帮我写一封请假邮件"
t=3.10    click       (420, 200)    发送按钮
t=3.80    response    "好的，以下是请假邮件模板..."
t=6.50    scroll      down 300px
t=7.20    click       (520, 600)    复制结果
t=8.00    complete    用户标记"任务完成"
```

### 4.2 界面截图采集

在每个关键操作节点自动截取界面截图，用于后续的界面分析：

| 触发条件 | 截图用途 |
|---------|---------|
| 页面首次加载 | 首屏布局分析 |
| 点击后 | 点击反馈状态（按钮变化、加载态） |
| 响应后 | 回复展示区域的布局 |
| 弹窗出现时 | 弹窗层级、遮罩、关闭体验 |
| 错误/异常时 | 错误提示的醒目度和清晰度 |
| 任务结束时 | 最终状态截图 |

### 4.3 用户主观反馈

在任务执行的特定节点或完成后，采集用户的主观感受：

| 采集时机 | 问题 | 形式 |
|---------|------|------|
| 每步完成后 | "这一步操作你觉得顺畅吗？" | 5 星评分 + 可选评论 |
| 任务完成后 | 整体满意度、费力度、推荐意愿 | NPS + SUS 量表 |
| 遇到困难时 | "你刚才遇到了什么问题？" | 多选 + 自由输入 |

**SUS（System Usability Scale）精简版：**

```
1. 我觉得这个应用操作起来很简单
2. 我觉得这个应用功能很强大，但用起来不顺手（反向）
3. 使用这个应用时，我知道下一步该做什么
4. 如果能熟练使用，我能很快完成任务
（5 分制）
```

## 五、分析引擎

### 5.1 操作效率分析

以任务为单位，分析用户操作过程中的效率指标：

| 指标 | 计算方式 | 正常范围（参考） |
|------|---------|----------------|
| **任务完成率** | 成功完成 / 总尝试次数 | > 80% |
| **操作步数** | 从开始到完成的总操作数 | 预期步数的 ±50% |
| **任务耗时** | 从开始到完成的总用时 | 视任务复杂度而定 |
| **偏离度** | 实际路径与预期路径的差异程度 | < 30% |
| **迷失度** | 无效操作步数 / 总步数 | < 20% |
| **重复操作率** | 回退/撤销/重复输入次数 / 总步数 | < 10% |
| **首次成功时长** | 用户第一次尝试即成功的耗时 | 越短越好 |
| **辅助求助次数** | 查看帮助/FAQ/外部搜索的次数 | < 2 次 |

**迷失度检测规则：**

```
- 在同一个页面内连续点击 3 次以上无页面跳转 → 标记为"迷失"
- 操作路径中出现 URL 回退（返回上一步）→ 标记为"回退"
- 输入框反复修改同一内容 2 次以上 → 标记为"犹豫"
- 超过 15 秒无操作 → 标记为"思考停顿"
```

### 5.2 界面可用性分析

基于截图和操作数据，自动评估应用的界面质量：

| 维度 | 评估项 | 方法 |
|------|--------|------|
| **布局合理性** | 信息密度、视觉层级、F/Z 型布局适配 | 截图分析（布局检测模型） |
| **导航清晰度** | 功能入口是否易找、路径是否直观 | 操作路径分析 + 首次点击位置 |
| **反馈即时性** | 点击反馈、加载态、操作确认 | 操作与界面变化的时间差分析 |
| **一致性** | 按钮风格、术语统一、交互模式一致 | 跨页面截图对比 |
| **信息可读性** | 字号、对比度、行距、色彩使用 | 截图 OCR + 视觉分析 |
| **错误提示** | 错误信息的醒目度、明确度、解决方案 | 错误截图 OCR + 语义分析 |
| **响应展示** | 流式展示体验、引用标注、来源清晰度 | 响应区域截图分析 |

**评分标准（每项 1-10 分）：**

| 分数 | 含义 |
|------|------|
| 9-10 | 无需改进 |
| 7-8 | 有细微瑕疵，不影响使用 |
| 5-6 | 明显问题，影响部分用户 |
| 3-4 | 严重问题，多数用户会困惑 |
| 1-2 | 功能不可用或极易出错 |

### 5.3 流程完整性分析

评估应用的工作流是否完整、闭环、容错：

| 指标 | 说明 |
|------|------|
| **转化漏斗** | 每一步的流失率，识别高流失环节 |
| **异常退出率** | 用户未完成任务就退出的比例 |
| **容错能力** | 输入错误/操作失误后是否能恢复 |
| **分支覆盖** | 流程可选分支是否都被正确处理 |
| **循环检测** | 是否存在死循环路径（用户反复在同几个页面兜圈） |
| **成功路径多样性** | 用户是否有多种方式完成同一任务 |

**漏斗分析示例：**

```
任务：通过客服提交退货申请

步骤1: 找到客服入口      → 100% 进入
步骤2: 描述问题          → 85% 进入（15% 在这步放弃）
步骤3: 系统理解并给出方案  → 70% 进入（15% 因理解错误放弃）
步骤4: 上传凭证          → 60% 进入（10% 找不到上传入口）
步骤5: 确认提交          → 55% 完成（5% 在最后一步犹豫）
                        ╰—— 45% 总体流失率
```

### 5.4 交互体验评估

评估人与系统交互过程中的自然度和流畅度：

| 维度 | 评估项 | 方法 |
|------|--------|------|
| **自然度** | 对话是否自然、是否理解意图 | 对话轮次分析、自动评分 |
| **流畅度** | 多轮对话是否连贯、上下文保持 | 上下文丢失检测 |
| **主动性** | 系统是否主动引导、追问、澄清 | 对话策略分析 |
| **透明度** | 是否解释自己的推理过程 | 引用/解释内容的覆盖度 |
| **容错性** | 错误后是否能纠正 | 用户纠正后的反应质量 |
| **个性化** | 是否适配用户的使用习惯 | 重复用户的行为变化分析 |
| **情感交互** | 语气、同理心、礼貌程度 | 对话情感分析 |

### 6.3 瓶颈自动识别

自动标记问题点，按严重程度排序：

| 严重程度 | 问题 | 位置 | 建议 |
|---------|------|------|------|
| 🔴 严重 | 上传按钮无点击反馈，3 人中有 2 人重复点击 | 退货流程-上传凭证 | 按钮点击后立即显示加载态或文件选择器 |
| 🟡 中等 | 系统首次回复无法识别订单号，5 人中有 2 人需要重述 | 客服对话-问题描述 | 优化意图识别，增加"请提供订单号"的主动引导 |
| 🟢 轻微 | 提交按钮在首屏下方需滚动才能看到 | 退货流程-提交页 | 将按钮固定在底部或缩短表单 |

**瓶颈检测规则：**

```
- 操作步数 > 预期路径步数的 2 倍 → 标记"步数过多"
- 某步骤流失率 > 20% → 标记"高流失率"
- 同一位置重复操作 > 2 次 → 标记"用户困惑"
- 某步骤耗时 > 平均耗时的 3 倍 → 标记"异常耗时"
- 截图 OCR 检测到"错误"/"失败"/"请重试"文案 → 标记"错误状态"
```

## 七、边界声明

| 不做 | 原因 |
|------|------|
| 模型层 Benchmark | 不评估模型本身的能力指标，只评估应用的产品体验 |
| 性能压测 | 不测高并发/QPS，只感知用户视角的响应体验 |
| 代码级测试 | 不测 API 返回格式、不测 SDK 集成 |
| 自动化 UI 测试替代 | 不替代 Selenium/Playwright 的功能回归测试 |
| A/B 实验平台 | 不在线分流用户流量，只做离线体验评估 |
| 移动端自动化录制 | MVP 仅支持 Web 端，移动端后续版本 |
| 真实用户大规模采集 | MVP 以专家评估 + 小样本用户测试为主 |
| 自动修复 | 发现问题后不自动改代码，只出建议 |

## 八、开发优先级

### 第一周 —— 录制 + 任务管理

- 评估场景管理（预设 5 个场景）
- 任务设计器（角色/目标/成功标准）
- 浏览器录制插件（操作轨迹 + 截图）
- 操作回放与基础编辑
- 录制数据存储

### 第二周 —— 分析引擎（操作 + 流程）

- 操作效率分析（完成率、步数、耗时、偏离度）
- 迷失度与重复操作检测
- 转化漏斗分析
- 异常退出与循环检测
- 操作路径可视化（时间轴 + 旅程图）

### 第三周 —— 界面分析 + 主观反馈

- 截图采集与关键帧提取
- 布局合理性分析
- 反馈即时性分析（操作到界面变化的延迟）
- 一致性检测（多页面截图对比）
- 用户主观反馈采集（每步评分 + SUS）
- 主观数据与分析数据的关联

### 第四周 —— 报告 + 竞品对比

- 体验评分卡生成
- 瓶颈自动识别 + 标记
- 改进建议生成
- 竞品对比视图（多应用并排）
- 导出报告（HTML / PDF）

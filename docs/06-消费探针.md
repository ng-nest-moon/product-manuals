# 消费探针 — 产品功能说明书

## 一句话定义

一个 AI 驱动的消费陷阱识别引擎，买前查一查，避开消费坑。

---

## 一、产品架构

```
用户输入（商品链接 HTML / 截图 / 文字描述）
        ↓
  信息提取层 —— 从 HTML/OCR/文本中提取标题、价格、描述、评价、条款
        ↓
  分析引擎 —— 8 类分析器并行运行，每类独立打分
        ↓
  风险聚合 —— 综合风险等级 + 逐项明细
        ↓
  HTTP API 输出 —— JSON 格式报告
```

---

## 二、覆盖范围

8 类消费陷阱：

| 类别 | 识别内容 | 示例 |
|------|---------|------|
| 价格陷阱 | 虚假折扣、先涨后降、价格误导 | 划线价499元，常年实卖199元标成"限时特价" |
| 虚假宣传 | 夸大功效、虚假认证、误导描述 | "7天瘦10斤"、虚构专利认证、"全网第一" |
| 评价造假 | 刷单、虚假好评、恶意差评压制 | 好评集中发布、内容模板化、追评突然消失 |
| 订阅暗坑 | 自动续费不提示、难取消、免费试用陷阱 | 免费试用自动转付费、取消入口藏5层菜单 |
| 霸王条款 | 隐藏条款、责任免除、不合理退货 | "拆封不退"、"最终解释权归商家" |
| 诱导消费 | 紧迫感制造、默认勾选、暗黑模式 | "仅剩2件"倒计时、默认勾选附加服务 |
| 假冒伪劣 | 山寨品牌、伪进口、以次充好 | 商标相似、产地造假、材质虚标 |
| 隐私陷阱 | 过度收集信息、强制授权 | 拍照App要求读取通讯录、不给权限不让用 |

## 三、分析流程

### 3.1 输入与信息提取

| 输入方式 | 处理方式 |
|---------|---------|
| 商品链接 + HTML | 直接解析页面中的标题、价格、促销标签、评价、条款等 |
| 截图 | OCR 提取文字 + 视觉分析（红色促销标签、倒计时、勾选框等） |
| 文字描述 | 直接送入分析引擎 |
| 信息不足 | 返回"无法判断" |

### 3.2 8 类分析器（并行）

每个分析器输出：

| 字段 | 说明 |
|------|------|
| 得分 | 0-100，越高越危险 |
| 等级 | 低 / 中 / 高 |
| 命中 | true/false，该类别是否存在陷阱 |
| 推理链 | 判断依据，引用原文片段 |
| 置信度 | 分析器对自身判断的确信程度 |
| 建议 | 针对该陷阱的避坑提示 |

### 3.3 风险聚合

```
综合风险等级:
  - 安全 (0-15)    所有类别低分
  - 低风险 (15-40)  1-2 类中分，无高风险项
  - 可疑 (40-65)   有 1 类高风险 或 3+ 类中风险
  - 危险 (65-100)  2+ 类高风险 或 极端单项（>90）
```

### 3.4 输出报告格式

```json
{
  "risk_level": "可疑",
  "total_score": 52,
  "summary": "该商品存在价格误导和刷单嫌疑",
  "items": [
    {
      "category": "price_trap",
      "score": 78,
      "level": "高",
      "hit": true,
      "reason": "划线价499元，标注'限时特价199元'，但日常售价即为199元",
      "confidence": 0.92,
      "suggestion": "截图保存价格页面，可向12315投诉虚假促销"
    },
    {
      "category": "fake_reviews",
      "score": 65,
      "level": "中",
      "hit": true,
      "reason": "近7天好评集中发布，内容模板化，疑似刷单",
      "confidence": 0.78,
      "suggestion": "关注中差评和追评，勿被好评刷屏误导"
    }
  ],
  "advice": "建议观望或对比同款商品在其他店铺的价格和评价",
  "feedback_token": "a1b2c3d4",
  "timestamp": "2026-06-16T12:00:00Z"
}
```

## 四、调用方式

- **协议：** HTTP API
- **鉴权：** API Key
- **数据格式：** 请求/响应均为 JSON
- **状态：** 无状态，每次请求独立分析
- **超时：** 建议设置 30s 超时

---

## 五、反馈机制

每次分析结果附带 `feedback_token`，用户可反馈：

| 反馈类型 | 含义 |
|---------|------|
| false_positive | 误报——引擎说有问题，实际上没有 |
| false_negative | 漏报——引擎说没问题，实际上有陷阱 |
| correct | 判断正确 |

反馈数据不改变当前接口行为，仅用于后续模型迭代和性能评估。

---

## 六、边界声明

| 不做 | 原因 |
|------|------|
| 前端渠道（浏览器插件/小程序/聊天机器人等） | 第一版只做引擎，前端后续对接 |
| 内置网页爬虫 | 前端传入 HTML，引擎不处理反爬 |
| 用户系统 / 账号体系 | 引擎无状态，不存用户数据 |
| 历史价格数据库 / 价格追踪 | 依赖前端或后续规则引擎 |
| 众包数据 / 用户社区 | MVP 不做社交和 UGC |
| 多语言支持 | 初期只做中文 |
| 自动维权 / 代投诉 | 只出建议，不代操作 |

## 七、开发优先级

### 第一阶段 — 分析引擎核心

- 8 类分析器（逐类实现并测试）
- 信息提取（HTML 解析 + OCR 接入 + 文字输入）
- 风险聚合逻辑
- HTTP API 接口
- 输出报告格式化

### 第二阶段 — 评估与迭代

- 已知陷阱测试集构建
- 误报/漏报分析
- 分析器性能优化（Prompt 调优、Few-shot 优化）

### 第三阶段 — 生态拓展

- 用户反馈数据管道
- 规则引擎叠加（降低成本、提升确定性）
- 前端集成指南与 SDK

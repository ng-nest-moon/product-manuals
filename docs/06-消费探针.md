# 消费探针 — 产品功能说明书

## 一句话定义

一个 AI 驱动的消费陷阱识别引擎，买前查一查，避开消费坑。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

**主要用户：电商消费者（25-45 岁）**

| 维度 | 描述 |
|------|------|
| 年龄 | 25-45 岁，有稳定网购习惯 |
| 月均网购频次 | 5-15 次 |
| 消费决策 | 会在购买前花时间比较 |
| 典型行为 | 看评价、比价格、查品牌 |
| 底层心理 | 怕被坑——信息不对称下的不安全感 |

**次要用户：电商平台/比价工具开发者**

| 维度 | 描述 |
|------|------|
| 需求 | 嵌入消费探针 API 为自家用户提供商品预警 |
| 场景 | 比价 App 接入后，在显示价格的同时标注风险 |

### 1.2 真实痛点分级

| 需求类型 | 痛点 | 用户行为证据 |
|---------|------|-------------|
| **刚需** | 无法快速判断商品价格和描述是否真实 | 消费者在购买前缺乏系统化验证工具 |
| **刚需** | 虚假折扣和先涨后降防不胜防 | 双十一等大促期间投诉量激增 |
| **改善型** | 评价造假让消费者无法参考真实体验 | 好评刷单已成产业链 |
| **改善型** | 隐形条款和自动续费不易察觉 | 取消订阅的用户体验极差 |
| **猎奇伪需求** | "我要查遍所有商品"的过度使用 | 实际上消费者只对高价/关注商品有验证意愿 |

## 二、解决方案与核心功能

### 2.1 解决方案概述

消费探针是一个 AI 驱动的消费陷阱识别 API。用户提供商品信息（链接 / 截图 / 文字描述），引擎返回风险分析报告。

核心设计：
- **输入灵活：** 链接 HTML、截图 OCR、文字描述均可，按需选择
- **并行分析：** 8 类陷阱分析器同时运行，互不干扰
- **结果可理解：** 不只是一个风险分数，还有推理链和引用原文
- **支持二次开发：** 纯 API 设计，前端可自行集成到不同渠道

### 2.2 核心功能清单

1. **信息提取** — 从 HTML/OCR/文字中提取标题、价格、描述、评价、条款
2. **8 类分析器并行运行** — 每类独立打分，输出得分+等级+命中+推理链+置信度+建议
3. **风险聚合** — 综合 8 类评分，输出综合风险等级（安全/低风险/可疑/危险）
4. **JSON 报告输出** — 结构化报告，包含风险摘要和逐项明细
5. **反馈机制** — 用户可以报告误报/漏报，用于引擎迭代

## 三、竞品与差异化分析

| 竞品 | 优点 | 缺点 | 差异 |
|------|------|------|------|
| 商品评价分析工具 | 聚焦评价内容 | 不覆盖价格陷阱和订阅陷阱 | 消费探针覆盖 8 类陷阱 |
| 浏览器比价插件 | 价格追踪和历史对比 | 只看价格不看欺诈 | 消费探针核心是识别陷阱 |
| 12315 投诉平台 | 官方维权渠道 | 只能事后维权 | 消费探针是买前预警 |

**差异化优势：** 覆盖 8 类陷阱的并行分析 + 推理链可追溯 + 纯 API 设计可嵌入任何前端。

## 四、架构总览

```
用户输入（商品链接 HTML / 截图 / 文字描述）
        ↓
  信息提取层 —— 从 HTML/OCR/文本中提取标题、价格、描述、评价、条款
        ↓
  分析引擎 —— 8 类分析器并行运行，每类独立打分
        ├─ 价格陷阱   ├─ 虚假宣传   ├─ 评价造假
        ├─ 订阅暗坑   ├─ 霸王条款   ├─ 诱导消费
        ├─ 假冒伪劣   └─ 隐私陷阱
        ↓
  风险聚合 —— 综合风险等级 + 逐项明细
        ↓
  HTTP API 输出 —— JSON 格式报告
```

## 五、核心模块详解

### 5.1 信息提取层

| 输入方式 | 处理方式 |
|---------|---------|
| 商品链接 + HTML | 直接解析页面中的标题、价格、促销标签、评价、条款等 |
| 截图 | OCR 提取文字 + 视觉分析（红色促销标签、倒计时、勾选框等） |
| 文字描述 | 直接送入分析引擎 |
| 信息不足 | 返回"无法判断" |

### 5.2 8 类分析器

| 类别 | 识别内容 | 示例 |
|------|---------|------|
| 价格陷阱 | 虚假折扣、先涨后降、价格误导 | 划线价 499 元，常年实卖 199 元标成"限时特价" |
| 虚假宣传 | 夸大功效、虚假认证、误导描述 | "7 天瘦 10 斤"、虚构专利认证 |
| 评价造假 | 刷单、虚假好评、恶意差评压制 | 好评集中发布、内容模板化 |
| 订阅暗坑 | 自动续费不提示、难取消、免费试用陷阱 | 免费试用自动转付费 |
| 霸王条款 | 隐藏条款、责任免除、不合理退货 | "拆封不退"、"最终解释权归商家" |
| 诱导消费 | 紧迫感制造、默认勾选、暗黑模式 | "仅剩 2 件"倒计时、默认勾选附加服务 |
| 假冒伪劣 | 山寨品牌、伪进口、以次充好 | 商标相似、产地造假、材质虚标 |
| 隐私陷阱 | 过度收集信息、强制授权 | 拍照 App 要求读取通讯录 |

每个分析器输出：得分（0-100）、等级（低/中/高）、命中（true/false）、推理链、置信度、建议。

### 5.3 风险聚合

```
综合风险等级:
  - 安全 (0-15)    所有类别低分
  - 低风险 (15-40)  1-2 类中分，无高风险项
  - 可疑 (40-65)   有 1 类高风险 或 3+ 类中风险
  - 危险 (65-100)  2+ 类高风险 或 极端单项（>90）
```

### 5.4 调用方式

- **协议：** HTTP API
- **鉴权：** API Key
- **数据格式：** 请求/响应均为 JSON
- **状态：** 无状态，每次请求独立分析
- **超时：** 建议设置 30s 超时

### 5.5 反馈机制

每次分析结果附带 `feedback_token`，用户可反馈：`false_positive`（误报）、`false_negative`（漏报）、`correct`（正确）。反馈数据不改变当前行为，仅用于模型迭代评估。

## 六、用户流程

```
用户准备消费（看到商品/收到链接）
    ↓
打开消费探针 → 输入商品链接/截图/文字
    ↓
引擎提取信息 → 8 类并行分析
    ↓
返回风险报告（综合等级 + 逐项明细）
    ↓
用户参考报告决定是否继续购买
    ↓
可反馈结果准确性
```

## 七、商业模式

| 付费模式 | 定价 | 依据 |
|---------|------|------|
| API 按量计费 | 0.1-0.3 元/次 | 每次分析消耗模型调用成本 |
| 个人月付 | 10 元/月（不限次数） | 高频用户的画风 |
| 企业 SaaS | 按调用量阶梯定价 | 面向 B 端接入开发者的定价 |

**核心盈利逻辑：** AI 调用成本持续下降，量越大毛利率越高。

## 八、落地路径

### 8.1 落地难点

| 难点 | 缓解策略 |
|------|---------|
| 分析质量不稳定 | 每类分析器独立测试，持续反馈优化 |
| 用户输入格式多样 | 信息提取层兜底，信息不足时明确返回"无法判断" |
| 消费者不习惯买前查一查 | B 端嵌入已有购物流程可降低用户门槛 |

### 8.2 MVP

| 功能 | MVP | 后续 |
|------|-----|------|
| 分析器 | 价格+虚假宣传+评价造假 3 类 | 扩展到全部 8 类 |
| 输入 | 仅文字描述 | 链接 HTML + 截图 |
| 输出 | 简单风险等级 | 完整结构化报告 |

### 8.3 第一步验证

**最关键假设：** 消费者在购买前愿意花 10 秒"查一查"。

**验证方法：** 做一个 Telegram bot 或 WeChat mini 程序，用户发链接/截图返回报告。观察用户留存和重复使用频率。如果周活留存 > 30%，需求成立。

## 九、风险与预期反馈

| 预期槽点 | 应对方案 |
|---------|---------|
| "又不准" | 每类分析器独立标注可信度，低置信度时提示"仅供参考" |
| "不就是 AI 瞎编吗" | 推理链引用原文片段，用户可自行验证 |
| "要钱的？" | 个人版按量低价，足以覆盖轻量使用 |
| "我已经会识别了" | 会识别和每次都去识别是两回事——工具降低心理成本 |

## 十、边界声明

| 不做 | 原因 |
|------|------|
| 前端渠道（浏览器插件/小程序/聊天机器人等） | 第一版只做引擎，前端后续对接 |
| 内置网页爬虫 | 前端传入 HTML，引擎不处理反爬 |
| 用户系统 / 账号体系 | 引擎无状态，不存用户数据 |
| 历史价格数据库 / 价格追踪 | 依赖前端或后续规则引擎 |
| 众包数据 / 用户社区 | MVP 不做社交和 UGC |
| 多语言支持 | 初期只做中文 |
| 自动维权 / 代投诉 | 只出建议，不代操作 |

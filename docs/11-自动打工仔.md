# 自动打工仔 — 产品功能说明书

## 一、一句话定义

录制桌面窗口的操作视频，AI 通过视觉分析自动生成可执行的自动化流程，并在指定窗口精准回放。

---

## 二、系统架构总览

```
核心流程：

  录制层 ──→ AI视觉分析层 ──→ 执行层
          ↘              ↕
              存储与配置层

游戏场景专场（可选）：
  图像匹配 → 界面训练 → 连招宏 → 循环挂机 → 多分辨率
```

---

## 三、核心功能清单

1. **窗口录制** — 指定任意桌面窗口，录制鼠标/键盘/滚轮/拖拽完整操作
2. **AI 视觉识别** — OCR 识别界面文字 + 目标检测定位 UI 元素
3. **智能意图理解** — 操作序列自动抽象为有语义的逻辑步骤
4. **SOP 生成与编辑** — 自动生成可读流程，支持 YAML/JSON/流程图编辑
5. **视觉驱动执行** — 通过截图比对 + OCR 判断状态，不再依赖固定延时
6. **窗口绑定** — 锁定执行窗口，避免误操作到其他应用
7. **异常检测** — 执行过程中识别弹窗、卡死、加载失败等，自动暂停
8. **速度调节** — 回放速度可调（0.5x ~ 10x）
9. **循环执行** — 支持重复执行指定次数或无限循环
10. **多分辨率兼容** — 适配不同屏幕尺寸和缩放比例

## 四、工作流程

### 4.1 录制阶段

| 步骤 | 操作 |
|------|------|
| 1 | 指定要录制的目标窗口 |
| 2 | 点击"开始录制"，执行要自动化的操作 |
| 3 | 操作完成后点"停止录制" |
| 4 | 系统自动生成原始操作轨迹 |

**录制内容：**

| 类型 | 数据 |
|------|------|
| 鼠标 | 点击坐标、右键、滚轮、拖拽路径 |
| 键盘 | 按键序列、组合键、快捷键、文本输入 |
| 窗口状态 | 窗口大小变化、滚动位置、焦点切换 |
| 截图 | 每个关键节点的屏幕截图（用于 AI 识别） |
| 时间戳 | 每个操作的精确时间间隔 |

### 4.2 AI 分析阶段

原始操作轨迹经过 AI 处理，生成可读可编辑的自动化流程：

| 处理步骤 | 说明 |
|---------|------|
| 截图分析 | 对每个操作位置的截图做 OCR + 目标检测，识别界面元素 |
| 意图抽象 | 将"点击坐标 (320,480)" 转化为 "点击「提交」按钮" |
| 去冗余 | 去除录制过程中的无效操作（手抖点击、多余移动） |
| 流程结构化 | 生成步骤列表，含条件判断和循环 |

### 4.3 执行阶段

| 步骤 | 操作 |
|------|------|
| 1 | 用户选择要执行的流程 |
| 2 | 指定目标窗口（流程将在此窗口运行） |
| 3 | 点击"开始执行" |
| 4 | 系统通过视觉比对定位界面元素后执行操作 |
| 5 | 执行完成或出错时停止 |

## 五、执行引擎特性

### 5.1 视觉驱动

传统自动化的痛点：固定坐标失效（窗口大小变化、分辨率不同）。

自动打工仔 的解法：每次执行前，通过截图比对 + OCR 找到元素在当前界面的实际位置再点击。

| 定位方式 | 适用场景 | 优先级 |
|---------|---------|-------|
| OCR 文本定位 | 按钮有文字（"提交""确认"） | 高 |
| 图标模板匹配 | 有固定图标的按钮 | 中 |
| 语义布局定位 | 已知字段在表单中的相对位置 | 中 |
| 坐标回退 | 以上都不适用时 | 低 |

### 5.2 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 目标元素找不到 | 等待指定时间后重试，超时后暂停并弹窗提示 |
| 弹窗干扰 | 检测到未预期的弹窗，关闭后继续执行 |
| 窗口关闭/最小化 | 自动尝试恢复窗口，失败则暂停 |
| 目标窗口被遮挡 | 等待窗口前置，超时后暂停 |

## 六、存储与配置

### 流程文件格式

流程存储为结构化文件，核心字段：

```yaml
流程名称: 每日日报提交
目标窗口: Chrome
步骤:
  1:
    动作: 点击
    目标:
      ocr: "新建日报"
      fallback: [320, 180]
    等待: 2s
  2:
    动作: 输入
    目标:
      ocr: "日报内容输入框"
    内容: "{{今日工作内容}}"
  3:
    动作: 点击
    目标:
      ocr: "提交"
```

### 变量系统

| 变量类型 | 示例 | 用途 |
|---------|------|------|
| 文本变量 | {{今日工作内容}} | 执行前填写，支持多条数据批量执行 |
| 时间变量 | {{today}} / {{yesterday}} | 自动填入当前日期 |
| 剪贴板变量 | {{clipboard}} | 读取剪贴板内容作为输入 |

## 七、游戏场景专场（可选）

针对游戏自动化场景的专项优化：

| 功能 | 说明 |
|------|------|
| 图像匹配 | 基于游戏界面的截图匹配，识别血量、技能图标、地图元素 |
| 界面训练 | 用户标注界面元素（如"这个图标是背包"），AI 学习识别 |
| 连招宏 | 录制一套连招操作，按时间轴或状态触发回放 |
| 循环挂机 | 支持无限循环 + 异常检测（掉线、死亡、背包满） |
| 多分辨率 | 适配不同游戏分辨率，自动缩放识别区域 |

## 八、边界声明

| 不做 | 原因 |
|------|------|
| 桌面环境无关的云执行 | 必须在用户指定窗口运行，不上传录屏到云端分析 |
| 跨平台录制 | MVP 仅支持 Windows 桌面窗口 |
| 后台静默执行 | 执行过程对用户可见，不隐藏窗口 |
| 浏览器内自动化 | 不替代 Playwright/Selenium，专注桌面原生窗口 |
| 模拟账号登录 | 不处理需要登录态的服务，用户自行登录后录制 |
| 自动更新界面元素 | 界面元素变化后需要重新录制或调整模板 |

## 九、使用场景示例

### 场景一：每日数据填报

```
1. 录制一次：打开系统 → 选择日期 → 填入数据 → 点击提交
2. AI 生成流程，将每日数据设为变量
3. 每天只需填写数据 → 点执行，自动运行
```

### 场景二：批量导出报表

```
1. 录制一次报表导出操作的完整流程
2. 配合变量系统，循环切换不同筛选条件
3. 自动导出所有报表到指定文件夹
```

### 场景三：游戏日常任务

```
1. 录制一套游戏日常操作流程
2. 设置循环执行 + 异常检测（掉线重连）
3. 一键挂机完成日常任务
```

## 十、开发优先级（MVP 范围）

### 第一周 —— 录制 + 回放核心

- 窗口录制（鼠标/键盘事件捕获）
- 基础回放（固定坐标，无视觉识别）
- 速度调节
- 窗口绑定与恢复

### 第二周 —— AI 视觉识别

- 截图采集（关键节点自动截图）
- OCR 文本定位（对接 OCR 引擎）
- 图标模板匹配
- 坐标回退机制

### 第三周 —— 智能分析 + 流程编辑

- 操作序列结构化（意图抽象）
- 去冗余与流程优化
- 流程文件 YAML 格式
- 可视化流程编辑
- 变量系统

### 第四周 —— 异常处理 + 游戏场景

- 异常检测与暂停/恢复
- 弹窗干扰处理
- 循环执行
- 游戏场景专项（图像匹配、连招宏）

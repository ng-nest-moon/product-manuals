# 求职大厂 — 产品功能说明书

## 一句话定义

系统性备战大厂求职的一站式工具——从定目标到选 Offer，按目标公司分支精细化准备，帮求职者想清楚去哪、怎么去、选哪个。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

**主要用户：正在或准备求职大厂的中高阶开发者/产品经理（1-10 年经验）**

| 维度 | 描述 |
|------|------|
| 求职目标 | DeepSeek/字节/腾讯/阿里/美团等大厂 |
| 当前做法 | 零散刷题+网上搜面经+找朋友内推 |
| 最大痛点 | 准备方向不明确，不知道目标公司到底考什么 |
| 预期周期 | 1-6 个月 |

### 1.2 真实痛点分级

| 需求类型 | 痛点 |
|---------|------|
| **刚需** | 不同大厂的面试风格和考点差异巨大，没有系统性区分 |
| **刚需** | 投递进度/面试安排/内推状态分散各处 |
| **改善型** | 简历不知道如何适配目标公司 JD |
| **改善型** | 拿到多个 Offer 后缺乏结构化对比工具 |

---

## 二、解决方案与核心功能

### 2.1 解决方案概述

求职大厂 = 定目标 → 简历优化 → 能力诊断 → 模拟面试 → 投递追踪 → Offer 决策。核心是"公司分支引擎"——每个目标公司独立备战路径，从面试流程到高频考点各自不同。

### 2.2 核心功能清单

1. **公司分支引擎** — 针对每个目标公司独立定制备战路径
2. **目标定位** — 背景诊断+公司匹配+路径规划
3. **简历工坊** — JD 解析+关键词匹配+多版本管理
4. **职位雷达** — 多平台大厂职位聚合+新发预警
5. **面试实验室** — AI 模拟面试（分公司×分岗位×分轮次）
6. **内推桥** — 校友匹配+内推请求+进度追踪
7. **能力透镜** — 技能差距分析+补强推荐
8. **面经智库** — 面经库+AI 要点提炼
9. **投递管线** — 全流程投递状态追踪
10. **Offer 决策台** — 总包计算+职级对照+生涯推演

## 三、竞品与差异化分析

| 对比 | 求职大厂 | LeetCode | 牛客网 | 脉脉 | 猎聘 |
|------|---------|---------|-------|------|------|
| 公司分支 | **核心功能** | 无 | 无 | 无 | 无 |
| 全流程覆盖 | **定目标→选 Offer** | 刷题 | 面经 | 社交 | 投递 |
| AI 模拟面试 | **分公司模拟** | 无 | 文字题 | 无 | 无 |
| Offer 决策台 | **有** | 无 | 无 | 无 | 无 |

**差异化优势：** 公司分支引擎 + AI 模拟面试 (分公司风格) + Offer 决策台。

## 五、核心模块详解

### 5.1 公司分支引擎

内置 DeepSeek/字节/腾讯/阿里/美团预设分支，各分支独立管理面试流程模板、高频考点库、公司文化题库、职级薪酬对照。

各分支面试风格特征：

| 公司 | 一面 | 二面 | 典型痛点 |
|------|------|------|---------|
| DeepSeek | 算法+数学推理+论文理解 | 系统设计+项目深挖 | 数学基础不够深 |
| 字节 | 八股深追+算法 Hard | 系统设计+业务场景 | 边界案例处理弱 |
| 腾讯 | 基础八股+项目深挖 | 综合素质+开放题 | 表达不够系统 |
| 阿里 | 源码级八股+高并发 | 场景设计+架构演进 | 源码理解浮于表面 |
| 美团 | 业务理解+技术落地 | 系统设计+团队协作 | 业务视角窄 |

### 5.2 面试实验室

AI 面试官按目标公司的面试风格出题和追问。一面偏基础，二面偏深挖，交叉面偏综合。追问深度随用户表现动态调整。结束后生成多维度复盘报告。

### 5.3 Offer 决策台

总包计算器（薪资+股票+补贴）+ 跨公司职级对照表 + 用户自定义权重的多维度评分（薪资/成长/业务前景/团队/地点）。

## 六、用户流程

```
首次使用 → 背景诊断 → 系统推荐 2-3 目标公司
  ↓
用户确认目标 → 进入公司分支
  ↓
能力透镜扫描 → 简历工坊 → 面试实验室循环
  ↓
开始投递 → 投递管线追踪 → 面试日历管理
  ↓
获取 Offer → Offer 决策台 → 做出选择
```

## 八、落地路径

### 8.1 MVP

公司分支引擎（3 家公司：字节/腾讯/阿里）+ 面经智库 + 投递管线 + 简历工坊基础功能。

### 8.2 第一步验证

**最关键假设：** 求职者愿意按"公司分支"来差异化备战。

**验证方法：** 做 3 家公司的面经页面（按分支组织）和投递管线页面，不上线 AI 模拟。跟踪用户留存率——如果首次访问后有 30%+ 在 7 天内回流，假设成立。

## 九、风险与预期反馈

| 预期槽点 | 应对方案 |
|---------|---------|
| "面经不准确" | AI 提炼标注"仅供参考" |
| "AI 模拟不如真实面试" | 确实不能 100% 还原——辅助工具 |
| "Pro 太贵" | 免费版已有核心功能 |
| "保证能拿 Offer 吗" | 不做任何承诺 |

## 十、边界声明

| 不做 | 原因 |
|------|------|
| 代投/代面试 | 求职是用户自己的事 |
| 保证通过 | 结果受太多不确定因素影响 |
| 猎头/HR 对接 | 专注求职者端 |
| 接入招聘平台封闭 API | 基于公开信息聚合 |
| 卖课/卖课分成 | 补强推荐限于公开免费资源 |
| 用户简历对外暴露 | 仅用于用户本人的版本管理 |
| 求职务工画像变现 | 用户数据不做商业化利用 |

# 三顾 — 产品功能说明书

## 一句话定义

把"找工作"翻转过来：企业带着完整条件来敲你的门，你只决定开不开。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

**主要用户 A：28-38 岁、干得好但讲不好的"沉默中间层"**

| 维度 | 描述 |
|------|------|
| 典型处境 | 项目做了不少，作品散落在公司内网、客户邮箱和已离职同事的记忆里；一写简历就变成"负责某某模块"，一面就紧张，面完觉得自己像个骗子 |
| 职业特征 | 3-10 年经验，设计 / 研发 / 运营 / 内容 / 专业服务；不是顶尖 1%（不需要被挖），也不是新人（还没有记录） |
| 高频口头禅 | "我做过，但我讲不出来"、"面完感觉像演了一场戏"、"明明是他不懂" |
| 心理状态 | 对"被挑选"有倦怠，但不排斥更好的机会；真正想要的是**被看见**，不是被推销 |
| 付费能力 | 愿意为职业发展花 ¥100-500，但不愿为"投简历"付费——那本该是企业的成本 |
| 决策触发点 | 一次不公平的晋升、一次被"面霸"抢走的岗位、一次裁员后的重新出发 |

**主要用户 B：20-300 人公司的用人经理 / 唯一 HR**

| 维度 | 描述 |
|------|------|
| 典型处境 | 一年招 3-10 个人，每个岗位看 50 份简历、面 10-20 人、耗 30-60 天；被包装过的候选人坑过，也被大厂品牌滤镜误导过 |
| 高频口头禅 | "面得挺好，进来完全不是这样"、"简历都差不多，只能看学校和大厂"、"猎头费太贵了" |
| 真实需求 | 不是更多简历，而是**更早、更便宜地判断一个人能不能干** |
| 付费能力 | 一个岗位的年薪 15-40 万，猎头费 20-25%；愿意为"降低错招率"付 8-12% |
| 决策触发点 | 一次错招（3-6 个月工资打水漂）、一次关键岗位空窗、一次被候选人放鸽子 |

**供给冷启动用户 C：项目制知识工作者**——自由设计师、独立开发者、内容创作者、咨询顾问。他们已经有交付物、有客户、有复购记录，是"凭证密度"最高的一群人。

### 1.2 真实痛点分级

| 需求类型 | 痛点 |
|---------|------|
| **刚需** | ① **信号失真**：简历是自述，面试是 45 分钟抽样，测得出表达力和准备度，测不出真实交付；② **搜索成本错配**：个人海投、企业海筛，双方都在为"不信任"交税；③ **逆向选择**：会包装的人拿到溢价，能干但不善表达的人被系统性折价，企业只好退回学历、大厂、关系这些与岗位能力弱相关的代理指标 |
| **改善型** | 猎头贵且只服务高端；内推靠人脉；招聘平台已读不回；面试要请假；背调只查劣迹、不查能力；自由职业平台有交付记录，但只服务短单 |
| **猎奇伪需求** | ① 想让系统替自己决定去哪家公司；② 想什么都不做就被高薪砸中；③ 企业想零成本拿到全行业人才库；④ 想要一个总分，把所有人排成一张榜 |

**核心洞察一：招聘市场缺的不是人，是"可信信号"。** 当所有人都策略性呈现，信号就会通胀；信号通胀后，企业只能加码品牌、学历、关系这些"难伪造但弱相关"的代理指标。面试本来是用来去伪存真的，结果变成另一场可以准备的表演。**市场最贵的不是人，是判断一个人的成本。**

**核心洞察二：求职是唯一一个"买方有需求、卖方却承担全部搜索成本"的市场。** 企业发职位便宜，个人投递"免费"——但个人付出的是时间、隐私和情绪。把发起权翻过来，让想招人的一方付费，价格信号自然会抑制骚扰。

## 二、解决方案与核心功能

### 2.1 解决方案概述

不是做一个更好的招聘网站，而是同时换掉两样东西：**招聘的发起权**，和**能力的证据链**。

这个产品不假设"人的一切都已数字化"——那是科幻。它只假设一件事：**工作留下的痕迹可以被验证**。代码有提交记录，设计有稿件和上线链接，销售有回款，客服有满意度，项目有验收单，合作方愿意为你说过的话签字。这些今天已经发生了，只是没有被组织成一份可携带的凭证。

三件事同时成立，反向市场才跑得起来：

1. **写入者不是本人**——经历由交付物、结果数据、系统记录和合作方联署共同证明；本人只能授权读取和选择展示，不能编辑内容。自己写的叫简历，不叫凭证。
2. **反向发起**——企业付费发出带完整条件的邀约，个人免费接收、静默或拒绝。谁有求于谁，谁付钱。
3. **免面试，但不免评估**——面试被拆成"过去做过什么（凭证）+ 现在能做什么（工作样本）+ 在真实环境里做得怎么样（付费试做）"。

**外加一条不能省的前提：双向信用。** 企业也被记录——offer 反悔、试做不付钱、入职三个月跑一半、裁员不补偿，都会进入企业信用镜像。只给个人打分的系统，不叫信用体系，叫监视系统。

> 三顾记录的是"你答应的事，兑现了多少"，不是"你这个人值多少分"。信用是履约记录，不是人格定价。

**为什么是现在：**

| 条件 | 今天的状态 |
|------|-----------|
| 工作痕迹数字化 | 代码、设计稿、工单、合同、CRM、客服系统已经沉淀了大部分交付过程 |
| 结果数据可读取 | 企业微信 / 飞书 / Jira / GitHub / 销售系统提供了授权后的结果接口 |
| 存证与电子签成熟 | 交付物哈希、时间戳、电子签名成本已降到可忽略 |
| AI 匹配成本下降 | 解析凭证、解释匹配理由、生成试做任务，边际成本接近零 |
| 远程与混合办公 | 跨地域招聘成为常态，"必须见面才能判断"的假设正在松动 |

### 2.2 核心功能清单

1. **经历账本** — 把项目、角色、交付物、结果、合作方联署沉淀成一条可携带的职业记录，而不是一页随时重写的简历
2. **交付物存证** — 对代码、设计稿、文档、上线链接做哈希与时间戳存证，证明"这是你做的、什么时候做的"；合同只存哈希，不存正文
3. **结果数据接入** — 经本人授权，从 GitHub / Jira / CRM / 客服系统读取可量化结果，只取结果、不取原始内容
4. **联署网络** — 联署是加分项而非唯一凭证；优先用"验收即联署 / 离职即归档"把确认嵌进业务流程，本人不能自评，也不能删掉别人已经联署的事实
5. **五维履约信用** — 交付、协作、承诺、成长、边界五个维度，**不合成单一总分**，不做公开排名
6. **企业信用镜像** — 记录企业的邀约兑现率、offer 反悔率、试做付款、90 天留存、裁员补偿等事实，差企业要付更高的邀约价格
7. **反向邀约** — 企业带岗位、薪资带宽、汇报线、工作制、试做条件发起邀请；个人可以设门槛、静默期、自动拒收
8. **盲邀与披露阶梯** — 先看能力画像和条件，双方意向确认后再互见身份；当前雇主域名默认屏蔽
9. **邀约预算** — 企业购买邀约额度，收件人可拒收、举报；发得多不等于发得对，骚扰会扣企业信用
10. **条件透明卡** — 薪资、职级、汇报线、团队规模、工作制、试用期、近一年流失率、裁员记录，一张卡说清
11. **付费试做** — 2-4 周、20-30 小时、按市场价付酬的真实任务，替代筛选性面试；试做结果双向留痕
12. **匹配解释器** — 告诉你"为什么邀你、哪几条证据起作用、你缺哪一项"，可申诉、可纠错，不给录取概率
13. **信用衰减与修复** — 失败记录可解释、可补证、按时效衰减；严重失信需经仲裁，不设终身污点
14. **探索配额** — 平台保留一定比例"不完全匹配"的推荐位，给转行、复出、跨行业的人一条缝，防止匹配系统把阶层焊死
15. **起点通道** — 新人用开源贡献、模拟项目、竞赛、学徒制建立第一份凭证，明确标注"起点凭证"权重较低
16. **争议仲裁** — 联署造假、恶意差评、企业违约、试做剽窃的申诉与处罚机制
17. **数据可携带** — 职业记录归个人所有，可导出为标准格式，可迁移到其他平台，可删除

## 三、竞品与差异化分析

### 3.1 同类替代品对比

| 竞品 / 替代方案 | 优点 | 缺点 | 与本产品定位差异 |
|----------------|------|------|----------------|
| BOSS 直聘 / 猎聘 / 智联 | 流量大、覆盖广、即时沟通 | 本质是"简历搜索 + 聊天"，收入来自企业曝光；简历自述、信号通胀，候选人仍要海投 | 三顾不卖曝光，卖**可验证履约**；个人不投递，企业带条件来邀 |
| LinkedIn | 全球网络、职业档案标准 | 档案自填、社交表演、推荐信可客套；匹配靠关键词 | 三顾的档案由系统结果、交付物与联署共同生成，不靠自述 |
| 猎头 | 高端岗位、深度沟通、保密 | 费率高（20-25%）、只做头部、顾问水平参差 | 三顾把猎头的"判断"产品化，费率降到 8-12%，覆盖中间层 |
| 内推 | 信任传递、速度快 | 靠人脉、圈层固化、内推人背书能力有限 | 三顾把"内推"变成可追溯的联署网络，不依赖熟人 |
| 背调公司 | 能查劣迹、学历、履历真伪 | 只查"有没有问题"，不查"能不能干"；周期长 | 三顾查的是交付与履约，背调可作为合规模块接入 |
| Upwork / Fiverr | 有真实交付、有客户评价 | 只服务短单/外包，评价碎片化，不进全职市场 | 三顾把项目制凭证延伸为全职邀约，是"从短单到长期"的桥 |
| 大厂 ATS / 人才库 | 流程规范、数据完整 | 只服务内部，候选人体验差，跨公司不互通 | 三顾做跨企业的可携带账户，个人拥有自己的记录 |
| 传统面试 | 灵活、能观察临场反应 | 45 分钟抽样、可准备、表达力溢价、成本高 | 三顾用"凭证 + 工作样本 + 付费试做"替代筛选性面试 |

### 3.2 差异化优势与护城河

**差异化一句话：** 竞品在卖"更多人"，三顾在卖"更少的判断错误"。

**护城河深浅评估：**

- ❌ **反向邀约的交互** —— 一周就能抄。任何招聘平台加一个"邀请"按钮就能模仿，这只是先发优势
- ❌ **AI 匹配算法** —— 也不构成壁垒。模型是租来的，数据才是自己的
- ✅ **联署网络的密度** —— 每条关键记录最好有一个交易对手确认，确认又绑定交付物。记录越多，匹配越准；匹配越准，越多人愿意把记录放进来。这个飞轮按**行业 × 城市**局部启动，抄不走存量
- ✅ **证据连接器的覆盖** —— 谁能用最低成本接上合同、验收、回款、代码、设计稿、工单，谁就拥有别人拿不到的凭证密度。连接器比算法难抄
- ✅ **交易承接能力** —— 谁能承接合同、验收、回款，谁就自动拥有凭证；靠"收集上传"的会被隐私墙挡死。交易越深，凭证越真，迁移成本越高
- ✅ **企业工作流的嵌入** —— 当企业的 Jira / 飞书 / CRM 结果数据被授权接入，凭证的获取成本趋近于零，迁移成本随时间上升
- ✅ **争议仲裁的公信力** —— 一个能处理"联署造假、试做剽窃、offer 反悔"的中立机构，比任何算法都难复制
- ✅ **凭证标准的可携带性** —— 如果"三顾凭证"成为跨平台标准，用户就不再被单一平台锁死，平台反而因为标准而获得网络效应
- ⚠️ **诚实评估** —— 如果只能拿到简历数据，这个产品的护城河等于零，它就是"带邀请功能的招聘网站"。**必须拿到"交付物 + 结果/系统记录"至少两件；联署是加分项，不是前提。**

## 四、架构总览

```
三顾
 ├── 凭证层（把"做过"变成可验证）
 │    ├── 经历账本（项目 / 角色 / 时间 / 可携带）
 │    ├── 交付物存证（哈希 / 时间戳 / 上线链接）
 │    ├── 结果数据（GitHub / Jira / CRM / 客服系统，授权读取）
 │    ├── 采集与验真（授权读取 / 交易系统 / 公共记录 / 五层校验）
 │    └── 联署网络（客户 / 上级 / 同事 / 合作方，加权项而非门槛）
 │
 ├── 信用层（把"兑现"变成可计算）
 │    ├── 五维履约（交付 / 协作 / 承诺 / 成长 / 边界）
 │    ├── 企业镜像（邀约兑现 / offer 反悔 / 试做付款 / 留存）
 │    ├── 衰减修复（时效 / 解释 / 补证 / 删除）
 │    ├── 反作弊（交付物绑定 / 图谱审计 / 随机复核）
 │    └── 争议仲裁（联署造假 / 恶意差评 / 违约 / 剽窃）
 │
 ├── 匹配层（把"招人"变成反向邀约）
 │    ├── 反向邀约（企业带完整条件发起）
 │    ├── 盲邀披露（匿名画像 → 脱敏履历 → 实名 → 证据包）
 │    ├── 邀约预算（付费额度 / 拒收 / 举报 / 冷却期）
 │    ├── 匹配解释（为什么邀你 / 缺什么 / 可申诉）
 │    └── 探索配额（给转行 / 复出 / 跨界的非完美匹配）
 │
 ├── 交易层（把"录用"变成可结算）
 │    ├── 条件透明卡（薪资 / 职级 / 汇报线 / 工作制 / 流失率）
 │    ├── 付费试做（2-4 周 / 按市场价 / 双向评估）
 │    ├── 合同结算（试做协议 / 薪酬托管 / 发票）
 │    └── 入职保障（保证期 / 替换 / 退款）
 │
 └── 治理层（让系统不被滥用）
      ├── 授权隐私（分级可见 / 雇主屏蔽 / 可撤回）
      ├── 反歧视审计（只允许岗位相关特征）
      ├── 算法审计（可解释 / 人工复核 / 第三方年审）
      └── 数据可携带（个人所有 / 标准导出 / 可删除）
```

## 五、核心模块详解

### 5.1 凭证层

凭证的第一原则不是"自动"，而是**写入者不能是候选人**。一条经历的可信度，取决于它是谁写的、什么时候写的、能不能被独立验证——不是取决于它被排版得多漂亮。

| 等级 | 证据类型 | 谁写入 | 例子 | 候选人能否修改 | 可信度 |
|------|---------|--------|------|---------------|--------|
| L0 | 自述 | 候选人 | 简历、自我介绍、作品集封面 | 能 | 低 |
| L1 | 自提供文档 | 候选人 / 原机构 | 证书扫描件、合同扫描件（不鼓励上传）、内部邮件 | 可替换、可伪造 | 中低 |
| L2 | 系统记录 | 源系统 | GitHub commit、Jira 工单、CRM 回款、客服满意度 | 不能，只读 | 中高 |
| L3 | 合作方联署 | 客户 / 上级 / 同事 | 验收确认、任职确认、协作确认 | 不能 | 高 |
| L4 | 结果可复算 | 机构 / 审计 | 销售额、转化率、留存、复购、故障率 | 不能 | 最高 |

**硬规则：**

- **合同正文不上传**：只存哈希、电子签回执或脱敏确认单；三顾不做合同仓库
- **L2 是目标底线，L3 是加权项，不是门槛**；L4 可以独立成立
- 没有 L2/L3 时，用工作样本 + 付费试做补；**不要逼候选人去求前同事签字**
- 联署必须绑定具体交付物或项目，不能是空泛的"这人不错"
- 本人可以补充说明，但不能修改联署内容；有异议走仲裁，不走删除
- 没有证据的能力，不要假装能测——判断力、潜力、品格、隐性知识、团队氛围贡献，统一标注为"不可凭证区"，交给试做去采样

**自动生成到底自动在哪：三种来源**

| 来源 | 写入者 | 候选人做什么 | 典型证据 | 依赖第三方配合吗 |
|------|--------|-------------|---------|----------------|
| 授权读取 | 源系统 | OAuth 授权、选择范围 | GitHub、Figma、Jira、CRM、客服系统 | 不依赖，候选人自己授权 |
| 交易系统 | 客户 / 平台 | 正常签约、验收、付款 | 电子签回执、验收单、发票、回款、平台托管 | 不额外依赖，业务动作顺带产生 |
| 公共记录 | 公开平台 / 机构 | 发布或授权查询 | 开源提交、上架应用、论文、专利、赛事、离职证明 | 不依赖个人 |

注意：个人账号、公开仓库、个人作品集可以直接授权；GitHub Enterprise、公司 Figma / Jira、CRM 属于雇主资产，需要雇主或管理员授权，候选人不能单方面导出。交易系统来源的前提是客户在平台内完成签约 / 验收 / 付款；线下交易只能用合同回执/哈希、发票、回款记录补证，可信度降一档。拿不到时，用公开作品、离职证明、脱敏项目文档和试做补。

**"自动"的三条硬标准：**

1. **发生在工作发生时**，不是事后回忆——合同回执在签约时留下，验收在交付时留下，回款在结算时留下
2. **候选人不能编辑内容**，只能选择"给谁看、看多少"——能改内容的是简历，不是凭证
3. **来源可独立验证**——API 签名、企业域名、电子签证书、可信时间戳，至少有一个

**一个具体例子：自由设计师的一个项目**

| 证据 | 谁产生 | 候选人能不能改 |
|------|--------|---------------|
| 电子合同：范围、周期、金额 | 双方 + 电子签平台 | 不能 |
| Figma 文件与版本历史 | Figma | 不能改历史 |
| 客户在平台点"验收通过" | 客户 | 不能 |
| 发票 + 回款记录 | 财务 / 支付系统 | 不能 |
| 客户一键确认"合作方式" | 客户 | 不能 |
| 作品集里的项目描述 | 候选人 | **能** |

前五条是凭证，最后一条只是线索。设计师没有"写简历"，他只是授权、交付、收款，然后选择把哪几条展示给企业。

**不是简历的测试：**

- 候选人能自由编辑内容 → **简历**
- 候选人只能上传截图/PDF → **加强版简历**
- 候选人只能授权读取、选择披露范围 → **凭证**

**但自动化有边界，必须诚实：**

| 人群 | 能自动拿到的比例 | 拿不到的部分 | 第一版怎么办 |
|------|----------------|-------------|-------------|
| 项目制知识工作者 | 约 60-70% | 审美判断、沟通质量、为什么选你 | 合同/验收/回款 + 可选联署 + 试做 |
| 全职员工 | 约 30-40% | 内部代码质量、架构判断、协作口碑 | 离职证明 + 公开作品 + 可选联署 + 试做 |
| 高管 / 深度研发 | 约 20-30% | 决策质量、组织影响、隐性知识 | 背调式联署 + 长期试做/顾问期 |

全职员工的工作数据在雇主系统里，候选人没有权利随便导出；产品不能假装能拿到。**所以第一版从项目制知识工作者切入，不承诺"全行业全自动"。**

**第三方为什么配合：不是"给你签字"，是"确认一笔已经发生的交易"**

合作方没有义务给候选人背书。能让他们点"确认"的，不是人情，而是三件事：**这件事本来就要闭环、确认的成本极低、确认对他自己也有用。**

| 第三方 | 他图什么 | 怎么把成本降到最低 | 不配合时怎么办 |
|--------|---------|-------------------|---------------|
| 客户 | 验收闭环、尾款、复购、争议保护 | 验收单上勾选"确认交付"，自动生成确认记录；**不勾选也能验收、也能付款** | 用合同回执/哈希 + 发票 + 交付物，权重略低 |
| 直属上级 | 交接清楚、团队稳定、自己的管理信用 | 离职流程里一键确认任职期/职责；**不通知现雇主** | 用 HR 离职证明、社保记录、项目文档 |
| 同事 / 合作方 | 互惠、职业信用、低摩擦 | 平台预填事实，只需"确认/修正"；可匿名展示 | 用多人聚合，不要求单人签字 |
| 平台 / 客户系统 | 数据闭环、减少纠纷 | API 授权回传，不增加人工 | 用公开链接、电子签回执 + 存证 |

**联署人不是担保人：** 他只确认"合作发生过、角色是什么、交付是否被接受"，不为候选人的未来表现背书，也不写推荐语。主观评价不进入信用权重；平台承担争议处理；联署人可匿名，避免被现雇主或候选人报复。

**不需要法人签字、盖章或合同用印。** 项目对接人在平台内点"确认"即可；效力限于事实确认，不构成担保、推荐或对未来表现的承诺。

**优先找重复合作方。** 联署网络不从陌生人开始，从反复合作的客户、工作室、长期外包伙伴开始——他们本来就要反复签约、验收、结算，共享记录对双方都有用。一次性客户不强求，直接用合同回执/回款/试做替代。

**在职期间默认密封。** 现雇主和现客户看不到候选人正在维护的记录；离职或合作结束后才可展示。避免候选人因为建账被穿小鞋，也避免联署人被现雇主追责。

**合同不上传，怎么证明？**

原则：**验证事实，不收集文件。** 平台不需要合同正文，只需要确认"这份合同存在、双方签了、项目验收了、钱付了"。合同里的定价、客户名、违约条款、交付细节，都是企业的商业秘密；上传即扩大泄露面，也违反很多 NDA。**三顾不做合同仓库：合同正文留在双方或电子签平台，三顾只取回执与元数据。**

| 方式 | 怎么做 | 平台拿到什么 | 合同会不会离开双方 |
|------|--------|-------------|-------------------|
| 电子签回执 | 对接 e签宝 / 法大大 / DocuSign，候选人授权只读 | 合同编号哈希、签署时间、双方主体哈希、金额区间、状态 | 不会，只取回执 |
| 本地哈希 + 对方比对 | 候选人在本地算合同哈希，平台只存哈希；对方用自己的副本比对 | "两份文件是同一份"的确认 + 时间戳 | 不会，原文不出双方 |
| 脱敏确认单 | 平台生成一页确认单：角色、周期、交付物、金额区间 | 对方对这一页确认，不签原合同 | 不会，只确认摘要 |
| 第三方见证 | 会计师 / 律师 / 园区 / 托管方确认关键事实 | 见证方签名的断言 | 不会，见证方只确认事实 |

**平台存什么、不存什么：**

| 存 | 不存 |
|----|------|
| 合同哈希、签署时间 | 合同正文、具体条款 |
| 金额区间（如 10-20 万） | 精确价格、报价明细 |
| 角色、周期、验收状态、回款状态 | 客户名称（默认脱敏）、联系人信息 |
| 对方企业域名验证结果 | 银行账号、发票明细、聊天记录 |
| 确认事实与时间戳 | 推荐语、主观评分 |

**企业侧看到的是事实，不是合同：** "已核验：某行业客户 / 6 个月 / 已验收 / 已回款 / 金额区间 10-20 万"。NDA 项目只显示"某上市公司（匿名）/ 某类项目 / 某周期"，不显示项目内容。金额区间是可选项；对方可以只确认"已验收/已回款"，不披露金额。

**如果对方连确认都不愿意：** 电子签回执、发票、回款记录、交付物、公开作品，任意两条可以交叉；再不行用付费试做。**没有任何单一证据是必需的。**

**真伪怎么定：五层校验，结论不是一个"真"字**

| 校验层 | 验什么 | 怎么验 | 失败长什么样 |
|--------|-------|--------|-------------|
| 身份 | 联署人是不是他 | 企业邮箱/域名、电子签、手机号、身份证；通过独立渠道回访 | 候选人代填、假邮箱、无法独立联系 |
| 关系 | 他和候选人是否真合作过 | 合同、发票、项目记录、同一交付物 | 只有名字，没有项目 |
| 事实 | 说的是不是具体事实 | 时间、角色、交付物、范围；禁止空泛评价 | "他很优秀"但说不出项目 |
| 交叉 | 有没有第二个独立来源 | 2+ 独立证据、结果数据、图谱异常检测 | 所有联署来自同一小圈子 |
| 追责 | 造假有没有代价 | 实名签署、哈希存证、仲裁、法律追责 | 匿名、不可追溯、无惩罚 |

**结论分四档，不显示"已验证"这种二元徽章：**

| 档位 | 条件 | 展示方式 |
|------|------|---------|
| 已验证事实 | 身份 + 关系 + 事实 + 至少一个独立来源 | "已核验" + 可展开证据链 |
| 多方印证 | 2+ 独立联署，但缺硬证据 | "多方印证" |
| 单一来源 | 只有一条联署或一份文档 | "单一来源" |
| 存疑 | 身份/关系/事实有一项对不上 | "争议中"或不展示 |

**如果第三方就是不配合：**

- 先用"零配合证据"：公开作品、平台交易记录、合同回执/哈希、发票、代码/设计稿、结果数据
- 联署不是唯一路径；没有联署就用工作样本 + 付费试做
- 老公司倒闭、联系人失联：接受归档证据（合同哈希、电子签回执、邮件头、公开记录），降级展示
- NDA 项目：只确认"在某领域/某周期/某角色"的事实，不披露项目内容；平台做脱敏联署
- **绝不因为一个人不签字，就判候选人"有问题"**；沉默不是差评

**反直觉原则：** 凭证系统的目标不是消灭谎言，而是让**撒谎的成本高于证明的成本**。要让一条假经历成立，得同时伪造合同、回款、交付物、客户联署和平台记录——这比写一份漂亮简历难得多。反过来，如果一条凭证需要候选人去求人、请客、欠人情，那它就不是基础设施，是人情债。

**经历账本**是个人侧的主界面：一条时间轴，每个节点是一个项目，点开是"我做了什么 / 交付了什么 / 结果是什么 / 谁可以证明"。它不属于某一家公司，离职不消失，换平台可带走。

### 5.2 信用层

**五维履约模型**，每一个维度只回答一个具体问题：

| 维度 | 回答的问题 | 主要证据 | 默认衰减 | 企业可见性 |
|------|-----------|---------|---------|-----------|
| 交付信用 | 说好的东西，按时按质交付了吗？ | 验收单、上线记录、复购、返工率 | 3 年 | 可见 |
| 协作信用 | 合作过的人，还愿意再合作吗？ | 联署、复购、360 反馈 | 2 年 | 可见 |
| 承诺信用 | 答应的入职、工期、保密，守住了吗？ | 合同、HR 系统、仲裁记录 | 3 年 | 可见（附上下文） |
| 成长信用 | 同类任务的处理能力，在变强吗？ | 项目难度曲线、职责变化、技能跨度 | 2 年 | 只看趋势，不看绝对值 |
| 边界信用 | 有没有越界：泄密、侵权、骚扰、造假？ | 仲裁、审计、司法记录 | 5-10 年（严重情形） | 仅显示"风险提示"，须经正当程序 |

**三顾不出"信用分"。** 信用是五维向量，不是标量。任何把五维压成一个数字的产品，最后都会变成社会分层器：分数高的人被邀请，分数低的人被静音，而分数又由过去的雇主和平台决定——那就是把简历歧视换成了算法歧视。

**四条防异化规则：**

1. **不公开排名**——个人只能看到自己的向量和证据，企业只能看到与岗位相关的维度
2. **可申诉**——每条联署、每个结果都可质疑；申诉期间不参与匹配权重
3. **可衰减**——失败记录按时效衰减；一次项目失败不应跟着人十年
4. **可解释**——企业拒绝或邀请时，必须能说清是哪几条证据起作用，不能只说"模型觉得不合适"

**企业信用镜像**记录的是事实，不是情绪：

| 指标 | 数据来源 | 后果 |
|------|---------|------|
| 邀约兑现率 | 发出邀约后是否进入试做/录用 | 低于阈值 → 邀约价格上浮 |
| offer 反悔率 | 候选人确认后企业撤回 | 扣信用，累计触发限制 |
| 试做付款及时率 | 托管结算记录 | 逾期 → 暂停发邀约 |
| 90 天留存率 | 入职后留存（匿名聚合） | 过低 → 强制展示风险提示 |
| 非自愿离职率 | HR 系统 / 员工匿名联署 | 异常 → 企业信用报告标红 |
| 加班强度 | 匿名聚合 / 考勤授权 | 过高 → 候选人可见 |
| 裁员补偿合规 | 公开记录 / 员工联署 | 违规 → 高权重扣分 |

**信用利差**是这套系统的价格杠杆：信用差的企业，发同样一封邀约要付 1.5-3 倍的价格，试做必须预付全款；信用好的企业，价格更低、优先级更高。不用道德说教，让市场自己定价。

### 5.3 匹配层：反向邀约

一封合格的邀约，必须是一份**可决策的信息包**，不是一句"在吗，看下简历"。

| 邀约字段 | 要求 | 缺失后果 |
|---------|------|---------|
| 岗位与职级 | 具体职责、汇报线、团队规模 | 不允许发出 |
| 薪资带宽 | 区间下限必须真实，不能写"面议" | 不允许发出 |
| 工作地点 / 工作制 | 远程 / 混合 / 坐班，每周天数 | 不允许发出 |
| 试做条件 | 周期、周工时、报酬、任务范围 | 不允许发出 |
| 决策时限 | 候选人需要在几天内答复 | 默认 5 个工作日 |
| 邀约理由 | 具体引用 2-3 条凭证 | 不允许发出 |
| 不匹配项 | 主动说明候选人缺哪一项 | 至少写 1 条 |

**个人侧的控制权：**

- **最低条件**：薪资下限、地点、工作制、公司规模；不满足直接过滤，不消耗注意力
- **静默期**：随时暂停接收邀约，不解释、不扣信用
- **盲邀**：默认开启；先看能力和条件，双方有意向再实名
- **雇主屏蔽**：当前雇主及其关联公司默认不可见；猎头需实名认证后才能发邀约
- **邀约上限**：每周最多接收 N 封；超出自动排队
- **拒绝无需理由**：拒绝不扣个人信用，也不会被标记为"挑剔"

**企业侧的约束：**

- 邀约要买额度，额度按岗位稀缺度和企业信用浮动
- 同一岗位 30 天内不得重复骚扰同一候选人
- 候选人拒绝后 6 个月内不得再次联系（除非候选人主动更新意向）
- 被举报骚扰、虚假薪资、套取隐私，扣信用并冻结额度

**盲邀与披露阶梯：**

| 层级 | 企业能看到 | 个人能看到 | 触发条件 |
|------|-----------|-----------|---------|
| L0 匿名画像 | 行业、年限、能力向量、证据摘要 | 岗位、条件、企业信用摘要 | 默认 |
| L1 脱敏履历 | 项目类型、结果区间、联署人数 | 团队、汇报线、试做任务 | 企业发出邀约 |
| L2 实名 | 姓名、联系方式、完整履历 | 企业全称、HR / 用人经理 | 双方确认意向 |
| L3 证据包 | 交付物、联署原文、结果数据 | 合同、薪酬、试用期条款 | 进入试做前，签署保密协议 |

### 5.4 免面试评估

取消面试，不是取消评估，而是把评估从"说"变成"做"。面试原本承担的六个职能，必须逐一接管：

| 面试的职能 | 面试怎么做 | 三顾怎么替代 |
|-----------|-----------|-------------|
| 能力评估 | 问项目、出白板题 | 凭证 + 工作样本 + 付费试做 |
| 动机评估 | 问"为什么来我们公司" | 条件透明卡 + 候选人主动接受邀约 + 试做体验 |
| 文化 / 协作 | 聊价值观、看眼缘 | 工作风格画像 + 团队试做 + 双向互评 |
| 双向推销 | 公司讲愿景，候选人讲自己 | 角色说明书 + 团队 AMA（只答疑，不打分） |
| 薪资谈判 | 来回试探 | 薪资带宽透明 + 标准职级体系 |
| 风险控制 / 内部合法性 | 用人经理"见过才敢要" | 结构化证据复核 + 试做保证期 + 替换保障 |

**付费试做的六条硬规则：**

1. **必须付钱**：按市场价或双方约定的固定报酬，不低于当地最低工资折算；禁止"免费试稿"
2. **范围有界**：2-4 周、20-30 小时、一个可交付的真实任务，不做开放式"无限任务"
3. **任务真实**：来自岗位真实工作，不做与岗位无关的智力题
4. **双向评估**：企业给书面反馈，候选人也给企业打分；双方都可以中途退出
5. **成果归属**：企业为试做成果付费，拥有使用权；候选人保留署名与凭证权
6. **不重复试用**：试做通过后，试用期相应缩短，不能"试做三个月再试用三个月"

**试做不是免费劳动，是双方用真钱买真信息。** 企业买的是"这个人能不能干"，候选人买的是"这家公司值不值得去"。

如果企业仍然需要一次人对人的交流，可以安排 30 分钟的**信息性面谈**：只回答双方的问题，不打分、不做淘汰依据、不问"你最大的缺点"。它是服务，不是筛选。

### 5.5 匹配解释器与探索配额

每一封邀约都附一段解释，格式固定：

> 邀你的 3 个理由：① 你在 A 项目里负责 B，交付了 C，与岗位要求的 D 匹配；② 5 位合作方中有 4 位表示愿意再合作；③ 你的薪资带宽与岗位区间重叠。
>
> 你缺的 1 项：没有带过 5 人以上团队。这不代表不合适，但试做会重点看这项。
>
> 这不是录取概率，只是我们为什么把你放进名单。

个人可以逐条申诉："这条证据不适用于这个岗位"、"这个结果不是我负责的"、"联署人不是我当时的客户"。申诉成立后，该证据退出本次匹配，但不一定删除历史记录——**纠错和遗忘是两件事**。

**探索配额**是防阶层固化的结构设计：平台保留 15% 的推荐位给"非完美匹配"——转行者、career break 复出者、跨行业者、没有名校标签但证据扎实的人。企业可以自愿开启"探索模式"，平台补贴一部分试做费用。完全匹配会带来效率，也会杀死流动性；一个只推荐"最像现员工"的系统，最后会把公司变成一间回音室。

### 5.6 交易层

**条件透明卡**是把"录用"从黑箱变成合同前置信息：

| 卡片字段 | 说明 |
|---------|------|
| 薪资与结构 | 基本工资、绩效、奖金、股权；区间下限真实 |
| 职级与汇报 | 职级体系位置、汇报对象、下属人数 |
| 工作制 | 坐班 / 混合 / 远程；每周天数；加班常态 |
| 试用期 | 时长、薪资比例、考核标准 |
| 团队现状 | 近 12 个月入职 / 离职人数、岗位空缺原因 |
| 企业信用 | 邀约兑现、offer 反悔、试做付款、90 天留存 |
| 风险提示 | 近一年裁员、劳动仲裁、欠薪记录（经核实） |

**合同与结算：** 试做签服务协议，不是劳动合同；薪酬走平台托管，企业先付款、候选人交付后结算；试做通过后转劳动合同，试做期可折算试用期。平台只做托管与争议协助，不做雇主。

**客户合同与试做协议分开：** 客户合同不上传，只验电子签回执或本地哈希；试做协议是平台内的服务协议，不涉及客户商业秘密。

**入职保障：** 企业支付成功费后，若候选人在 90 天内非自愿离职，平台退还 50% 成功费，并免费补招一次；如果是企业违约（不付薪、不缴社保、擅自变更岗位），企业信用扣分且不退款。保障是双向的，不是只保企业。

### 5.7 治理层

| 机制 | 规则 |
|------|------|
| 分级授权 | 个人按"匿名画像 / 脱敏履历 / 实名 / 完整证据"四级授权，随时撤回 |
| 只读与最小范围 | 连接器只读、按项目/时间段授权；不读取聊天内容，不监控工作行为 |
| 雇主屏蔽 | 当前雇主及其关联公司默认不可见；离职后可手动解除 |
| 数据最小化 | 只采集与岗位相关的证据；不采集婚育、宗教、健康、性取向等敏感信息 |
| 反歧视 | 年龄、性别、婚育、户籍、学校不得作为硬性筛选条件；只能用岗位相关证据 |
| 算法审计 | 每年第三方审计一次；匹配解释必须可读；高风险拒绝支持人工复核 |
| 数据可携带 | 一键导出标准格式（JSON / PDF），可迁移到其他平台 |
| 删除权 | 可删除账户与记录；涉及欺诈、司法调查的记录按法律保留，但标注"争议中" |
| 合规边界 | 不做金融征信，不接入贷款、保险、租房、婚恋；不申请征信牌照，定位为职业凭证与匹配服务 |

## 七、商业模式

### 7.1 定价区间

| 产品 | 价格 | 说明 |
|------|------|------|
| 个人账户 | 免费 | 建账本、收邀约、拒绝、导出数据永久免费 |
| 履历加固 | ¥99-299 / 次 | 人工核验交付物、补联署、生成可分享证据包 |
| 职业账户年费 | ¥199 / 年 | 高级隐私（多套披露策略）、信用修复、历史曲线；**不含曝光加权** |
| 企业邀约包 | ¥1,000 / 20 封起 | 单价 ¥50-200，按岗位稀缺度与企业信用浮动 |
| 企业年费 | ¥3-20 万 / 年 | 含邀约额度、团队协作、人才池、数据看板 |
| 成功入职费 | 首年年薪 8-12% | 低于猎头 20-25%；90 天内非自愿离职退 50% |
| 试做托管 | 成交额 5% | 含合同、结算、争议协助 |
| 企业信用报告 | ¥5,000 / 年 | 给采购方 / 合作方看的企业履约报告（可选） |

**定价逻辑：** 企业今天为一个 20 万年薪的岗位付猎头 4-5 万；三顾收 1.6-2.4 万，还附一份可复用的试做记录。个人侧永久免费，不是因为善良，而是因为**向个人收"被看见"的钱，会立刻把产品变回简历军备竞赛**。

### 7.2 销售渠道

| 渠道 | 打法 |
|------|------|
| 项目制社区 | 从独立开发者、设计师、内容创作者社区冷启动，他们已有交付物和客户联署 |
| 中小企业集群 | 长三角 / 珠三角的 20-300 人公司，按行业园区的 HR 群切入 |
| HR SaaS 集成 | 与飞书、钉钉、北森、Moka 等打通结果数据与 offer 流程 |
| 猎头转型 | 猎头顾问转为"凭证审核员 / 试做设计师"，按单结算，不挖客户 |
| 开源社区 | 用 GitHub 贡献作为第一批凭证，开发者零成本建账本 |
| 高校 / 职校 | 起点通道：实习、竞赛、学徒制项目，毕业后带着记录进入市场 |

### 7.3 盈利模式

- **主收入**：企业邀约包 + 年费 + 成功入职费
- **增值**：试做托管、履历加固、企业信用报告、争议仲裁服务
- **不赚的钱**：个人曝光费、排名费、简历置顶费、候选人数据转卖、雇主广告位
- **明确拒绝**：按"候选人薪资抽成"定价——那会激励平台把人的价格炒高，而不是把人匹配对

## 八、落地路径

### 8.1 五大落地难点

| 难点 | 具体表现 | 应对方向 |
|------|---------|---------|
| ① 凭证冷启动 | 没有记录 → 匹配不准 → 没人愿意记录；合同又不愿上传 | 先做交易工具（合同模板/验收/回款），让凭证成为交易副产物；从重复合作的 freelancer-client 开始；一次性客户用回款/交付物补，不强求联署 |
| ② 联署造假 | 互相刷好评、小圈子互吹、客户碍于情面签字 | 联署只做加权项，主证据用合同/验收/回款/结果数据；联署绑定交付物；图谱审计识别"互刷 clique"；随机回访；虚假联署法律责任 |
| ③ 企业不肯放弃面试 | 面试是风险控制，也是用人经理的权力；"没见过不放心" | 不卖"取消面试"，先卖"免面试通道"：凭证 + 试做 + 90 天保障 + 免费替换；用第一批成功案例证明错招率下降 |
| ④ 信用异化 | 单一分数、公开排名、终身污点、算法歧视 | 五维向量、不公开总分、可申诉、按时衰减、反歧视审计、探索配额；把"不做总分"写进产品宪法 |
| ⑤ 合规与权力失衡 | 征信牌照、个人信息保护、算法歧视、数据泄露；企业看得太多，个人失去议价权 | 定位"职业凭证与匹配服务"，不做金融征信；分级授权、盲邀、雇主屏蔽、数据可携带；企业信用对等记录 |

**补充难点：匹配的同质化。** 越精准的匹配，越容易把"像我们的人"推给"我们"，最后行业失去跨界创新。探索配额是解药，但会降低短期匹配效率——这是一个必须主动付的成本。

### 8.2 MVP 最小可行产品

**切口：设计与前端岗位的项目制人才。** 选择理由：交付物天然可链接（Figma / GitHub / 上线链接）、合同/验收/回款本来就在外部系统里、付费试做接受度高、远程协作成熟、面试噪音大。**不选全职员工作为首发，因为他们的工作数据在雇主系统里，拿不到"自动凭证"。**

**更小的第一步：交易先行。** 如果客户连合同都不愿上传，说明凭证不能靠"收集"，只能靠"承接交易"。第一版可以不是招聘平台，而是给项目制工作者做"合同 + 验收 + 回款"的轻工具：客户用它托管付款、确认验收，候选人用它收款、留痕。凭证是交易的副产物，不是额外请求。等这个工具在一个圈子里跑通，再把凭证用于反向邀约。

| 保留 | 砍掉 |
|------|------|
| 经历账本（授权导入 + 链接存证） | 五维信用算法（先人工判断） |
| 合同回执/验收/回款 + 1 个交付物 + 可选 1 条确认 | 合同正文上传、企业信用全量镜像（只记录 offer 反悔与试做付款） |
| 轻交易工具（合同模板 / 验收 / 回款托管） | 探索配额、起点通道 |
| 条件透明卡 | 自动匹配、AI 解释器 |
| 盲邀 + 邀约预算 | 争议仲裁完整流程（先人工调解） |
| 付费试做 + 平台托管 + 双向互评 | 数据可携带标准、算法审计 |

**规模与成本：** 分两段。第一段 2-4 周：10 对重复合作的 freelancer-client，用合同模板 + 验收 + 收款链接跑通，1 名工程师 + 1 名运营即可，预算 ¥5-10 万。第二段 10-12 周：20 家企业、100 位候选人，2 名工程师 + 1 名运营 + 1 名兼职核验员，预算 ¥30-50 万。第一版甚至可以不写 App，用飞书表单 + 电子签 + 收款链接跑通。

### 8.3 第一步验证

**前置验证（2-3 周）：** 找 10 对重复合作的设计/开发 freelancer-client，用合同模板 + 验收 + 收款链接跑一个真实项目；观察客户是否愿意点"确认验收/回款"，候选人是否愿意授权展示。通过线：≥ 7 对完成闭环，≥ 5 对愿意展示脱敏记录。这个验证不碰招聘，只验证"凭证能不能作为交易副产物产生"。

**最关键假设（第二阶段）：** 企业愿意在"没有面试"的情况下，仅凭可验证凭证 + 付费试做，发出邀约并录用。

**验证方法：** 不写平台，先做 30 个岗位的人工撮合。招募 100 位有交付物的设计与前端人才，人工核验 1 条合同回执/验收/回款记录 + 1 个交付物，联署可选；向 50 家企业销售"免面试招聘"服务，收 ¥1,000 / 岗位的邀约服务费（可退）。每成功入职一单，收首年年薪 8%。

**判断标准：**

| 指标 | 通过线 | 含义 |
|------|-------|------|
| 企业愿意发出"无面试邀约" | ≥ 60% | 核心假设成立 |
| 候选人接受盲邀 | ≥ 30% | 供给端有真实意愿 |
| 试做完成率 | ≥ 80% | 试做设计可行 |
| 试做 → 录用转化 | ≥ 50% | 试做能替代面试 |
| 入职 90 天留存 | ≥ 85% | 匹配质量过关 |
| 企业复购 / 转介绍 | ≥ 50% | 有商业价值 |
| 候选人认为"比面试公平" | ≥ 60% | 价值主张成立 |
| 平均招聘周期 | ≤ 15 天 | 效率优势成立 |

**前置止损：** 如果 10 对里不到 5 对愿意确认/展示，说明"交易副产物"这个假设不成立——要么交易工具没提供足够价值，要么隐私顾虑压倒了收益。此时不要做招聘平台，先回到工具本身。

**止损线：** 如果不到 30% 的企业愿意发"无面试邀约"，说明凭证密度还不足以替代面试——退回 B 端"可信履历 + 试做管理"工具，不硬做反向市场。如果候选人普遍不愿维护记录，说明"被邀请"的吸引力不足以抵消记录成本，需要先做"履历托管"而不是"邀约平台"。

## 九、风险与预期反馈

| 预期吐槽 | 应对 |
|---------|------|
| "这不就是猎头 / BOSS 直聘？" | 猎头卖人脉，招聘网站卖流量，三顾卖**可验证履约**；个人不投递，企业带条件来邀，面试被付费试做替代。三者是不同物种 |
| "信用分会变成新的出身" | 这是最大风险，不回避。五维向量、不公开总分、可申诉、按时衰减、探索配额、禁止外接金融/租房/婚恋；产品宪法第一条就是"不做人的总分" |
| "没有面试怎么判断人？" | 面试测的是表达力和准备度，不是交付能力。三顾用凭证看过去、用工作样本看现在、用付费试做看真实环境；再加 90 天保障和免费替换，降低企业风险 |
| "企业会疯狂发邀约骚扰" | 邀约要付费、有预算、有冷却期；候选人可拒收、举报；骚扰扣企业信用、冻结额度。发得多不等于发得对 |
| "我的经历凭什么给你看？" | 分级授权、默认盲邀、雇主屏蔽、随时撤回、数据可携带；只传证据摘要，不传原始聊天记录和客户隐私 |
| "合同是商业秘密，凭什么上传？" | 不上传正文：只存哈希 / 电子签回执 / 脱敏确认单；企业侧只看到"已签署 / 已验收 / 已回款"的事实，看不到条款和客户名；NDA 项目默认匿名 |
| "所谓自动生成，最后还不是我自己填？" | 能自由编辑的是简历；只能授权读取、选择展示的才是凭证。个人账号/公开作品可直接授权；雇主系统需授权，拿不到就用离职证明 + 试做，不假装全自动 |
| "前公司/客户根本不配合，我是不是就完了？" | 联署不是门槛：先用合同、验收、回款、公开作品建账；没有联署用工作样本 + 付费试做；沉默不是差评；不通知现雇主 |
| "新人没有记录，永远进不来" | 起点通道：开源贡献、竞赛、模拟项目、学徒制；起点凭证权重低但可用。冷启动仍是难点，不假装已解决 |
| "被邀请是不是意味着我被定价了？" | 定价的是岗位，不是人；个人可以拒绝、静默、下架；平台不做公开排名，也不把"被邀次数"做成社交货币 |
| "AI 匹配会不会歧视？" | 只允许岗位相关特征；年龄、性别、婚育、户籍、学校不做硬筛；算法年审、匹配可解释、高风险拒绝可人工复核 |
| "企业也可以刷信用" | 企业信用只记录可核实事实（offer 反悔、付款、留存），不做好评差评；有申诉与回复权；刷分比刷单更难 |
| "这就是全景监狱" | 数据最小化、个人所有、可删除、可携带；但系统性风险真实存在，需要外部审计与监管，不能只靠产品自律 |
| "小公司付不起" | 按结果付费、试做托管、90 天保障；信用利差让差企业更贵、好企业更便宜，长期看是降本 |
| "被邀请也会焦虑" | 静默期、邀约上限、拒绝无需理由；"不被邀请"不推送、不提醒、不排名；产品不制造"错过恐惧" |

## 十、边界声明

| 不做 | 原因 |
|------|------|
| 金融征信、贷款、保险、租房、婚恋定价 | 职业履约记录一旦外溢，就会变成社会分层工具；这不是三顾的业务 |
| 输出"人的总分"或公开排行榜 | 信用是五维向量，不是人的价值；总分必然导致算法歧视与阶层固化 |
| 替代企业做录用决定 | 三顾提供证据、匹配与试做，不替企业承担用人决策 |
| 承诺"人人被邀请" | 市场有冷热、有稀缺、有拒绝；产品不制造"被看见"的幻觉 |
| 无薪试做 / 免费试稿 | 试做必须付酬；否则只是把面试成本转嫁给候选人 |
| 把候选人自填/自传的 PDF 叫"凭证" | 写入者不是候选人，才叫凭证；否则只能标"自述"，不能给核验徽章 |
| 把联署当作唯一凭证 | 会让候选人被迫求人签字，也会让一个不配合的前领导拥有一票否决权；联署只是加权项 |
| 未经同意公开联署人身份 | 联署人可能遭报复；默认匿名聚合，本人同意才实名 |
| 向个人收曝光费、排名费、置顶费 | 一旦个人付费买曝光，产品就变回简历军备竞赛 |
| 抓取未授权数据、监控在职员工 | 只采本人授权的结果数据；不读取聊天内容、不监控工作行为 |
| 消灭所有面试 | 医生、教师、安保、财务负责人等高风险/合规岗位保留结构化面谈；但面谈是合规步骤，不是默认筛选 |
| 终身档案 / 不可删除 | 记录按时衰减，个人可删除；严重失信经仲裁保留，但标注争议状态 |
| 把"被邀次数"做成社会地位 | 那会把产品变成新的社交攀比场，和"认识自己"无关，和"被看见"也无关 |
| 服务"付费插队" | 企业不能花钱把不合格的人塞进候选名单；邀约额度只能买"发问权"，不能买"录取权" |

**一句话边界：** 三顾是岗位与证据的匹配市场，不是人的交易所。人可以拒绝被挂牌，也可以随时下架。

## 十二、开发优先级

| 阶段 | 周期 | 主功能（不超过 4 个） | 验证目标 |
|------|------|---------------------|---------|
| P1 | 第 1-4 周 | 经历账本、采集与验真、条件透明卡、人工核验后台 | 100 位候选人能建出可读的凭证页 |
| P2 | 第 5-8 周 | 盲邀、邀约预算、付费试做托管、双向互评 | 20 家企业能完成一次"无面试邀约 → 试做" |
| P3 | 第 9-12 周 | 匹配解释器、信用衰减、企业信用镜像、争议调解 | 试做转化 ≥ 50%，90 天留存 ≥ 85% |
| P4 | 第 13-24 周 | 探索配额、起点通道、数据可携带、算法审计 | 转行/复出人群进入匹配池，且不被系统性过滤 |

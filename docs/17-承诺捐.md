# 承诺捐 — 产品功能说明书

## 一句话定义

> 设定每日挑战并绑定免密代扣，完成则无事发生，失败则自动捐出承诺金——用损失厌恶驱动行为改变，让每一份"违约"都变成善意。

---

## 一、架构总览

```
用户层
 ├── 承诺台
 │    ├── 创建挑战（类型 + 目标 + 周期 + 承诺金）
 │    ├── 签约代扣（微信支付免密代扣，不预扣款）
 │    └── 进行中挑战仪表盘
 ├── 验证引擎
 │    ├── 步数（微信运动自动同步）
 │    ├── 早起打卡（时间段内签到）
 │    ├── 专注时长（番茄钟 / 自行计时）
 │    ├── 学习阅读（截图上传 + AI 审核）
 │    └── 冥想确认（手动 / 穿戴设备）
 ├── 公益项目池
 │    ├── 3-5 个合作项目（Logo + 简介 + 每份金额的产出说明）
 │    └── 签约时选定，挑战期间不可更改
 ├── 数据看板
 │    ├── 履约日历
 │    ├── 违约记录（金额 + 去向）
 │    ├── 累计贡献
 │    └── 成就徽章
 └── 社交层
      ├── 组队挑战（2-5 人，一人违约全队受罚）
      ├── 违约广播（可选：违约自动发朋友圈）
      └── PK 模式（两人各自承诺，完成率高者胜）
```

---

## 二、核心功能清单

1. **创建挑战** — 选择挑战类型、目标值、周期长度、承诺金额
2. **签约代扣** — 微信支付服务委托代扣授权，不预扣款，仅做信用锁定
3. **每日验证** — 5 种验证方式覆盖主流习惯场景，自动/手动均可
4. **断签扣款** — 检测到断签时自动发起代扣，资金直达基金会账户
5. **公益项目自选** — 签约时从项目池选择一个作为违约资金去向
6. **履约日历** — 每日标注完成/跳过/断签状态，一目了然
7. **累计贡献看板** — 累计捐赠金额、受助人数/棵树/餐数等可视化
8. **成就徽章** — 连续完成 7/21/30/100 天解锁不同等级徽章
9. **组队挑战** — 2-5 人组队共同承诺，一人违约全队履约率受影响
10. **违约广播** — 允许用户选择断签后自动发朋友圈（社交丢脸效应）
11. **PK 挑战** — 两人各自承诺同类型目标，周期结束后履约率高者获胜
12. **免死金牌** — 每月 2 次豁免机会，断签可不扣款继续挑战

## 三、核心模块详解

### 3.1 挑战系统

**职责：** 用户创建和管理承诺挑战的核心入口。

| 功能点 | 说明 | 规则 |
|--------|------|------|
| 创建挑战 | 选择类型 + 目标值 + 周期 + 承诺金 | 周期仅提供 7/21/30 天三档 |
| 金额档位 | 4 档承诺金可选 | ￥5 / ￥20 / ￥50 / ￥100 |
| 免死金牌 | 每月 2 次豁免 | 断签时不扣款，不计入违约次数，挑战继续 |
| 挑战终止 | 连续断签 3 天触发 | 终止后剩余天数按比例扣款，代扣协议自动解约 |
| 全部完成 | 到期后所有目标达成 | 获得成就徽章 + 解锁下一级难度 |

**挑战类型：**

| 类型 | 验证方式 | 难度系数 | 默认目标 | 说明 |
|------|---------|---------|---------|------|
| 日行万步 | 微信运动步数（自动同步） | ★☆☆ | 8000/10000/12000 步 | 接入微信健康 API，每日自动拉取 |
| 早起打卡 | 指定时段内点击签到 | ★★☆ | 6:00-8:00 签到 | 基于 GPS 或 IP 定位防作弊 |
| 专注阅读 | 截图 + AI OCR 识别页数 | ★★☆ | 每天 30 分钟 | AI 仅校验截图真实性，不存原图 |
| 每日冥想 | 手动确认或穿戴设备数据 | ★★★ | 每天 10 分钟 | 支持接入潮汐/Apple Health |
| 自定义挑战 | 用户自述目标 + 自选验证 | 自定义 | 自定义 | 仅限高级用户，需人工审核 |

### 3.2 信用承诺机制

**职责：** 替代传统押金模式，用免密代扣实现零资金池的信用承诺。

**核心链路：**

```
用户创建挑战
  → 微信支付签约「服务委托代扣」（仅授权，不扣款）
  → 挑战期内每日验证
    ├── 达标 → 继续，无事发生
    └── 断签 → 系统自动发起代扣 → 资金直达基金会账户
  → 挑战结束 → 全部履约则代扣协议自动解约
```

**与押金模式对比：**

| 维度 | 传统押金模式（高风险） | 信用代扣模式（本方案） |
|------|---------------------|---------------------|
| 资金流向 | 用户 → 平台账户 → 再处理 | 用户 → 微信代扣 → 基金会（平台不经手） |
| 资金池 | 平台归集大量押金，构成资金池 | 无资金归集，不存在资金池 |
| 合规风险 | 涉嫌非法集资 + 赌博定性 | 合规路径清晰（微信支付官方接口） |
| 用户体验 | 先付钱，心理门槛高 | 先承诺，失败才付钱，启动成本为零 |
| 平台审核 | 微信明确打击"押金打卡"类 | 公益代扣属微信支付开放能力 |

### 3.3 验证引擎

**职责：** 接收并验证用户每日的履约证据。

| 验证方式 | 数据来源 | 验证方式 | 防作弊 |
|---------|---------|---------|--------|
| 微信步数 | 微信运动 API | 自动拉取，无需用户操作 | 步数由微信官方提供，不可伪造 |
| 早起签到 | 用户点击 + 时间校验 | 手动点击，系统校验时间窗 | 限制 IP/设备频率，同一设备每日仅一次 |
| 专注计时 | 内置计时器 / 接入潮汐 | 用户启动/停止计时 | 单次连续计时，不支持暂停续时 |
| 阅读截图 | 用户上传截图 | AI 校验文字密度和页边特征 | AI 判断是否为真实阅读界面，不存原图 |
| 冥想确认 | 用户手动确认 / 健康 API | 手动或自动 | 允许但不强制接入心率数据 |

### 3.4 公益项目池

**职责：** 提供 3-5 个经过合规筛选的公益项目，作为用户违约资金的去向。

**合作机构要求：**
- 持有民政部门批准的**公开募捐资格**
- 每笔捐赠可开具**公益事业捐赠票据**
- 有明确的**资金使用公示机制**

**推荐项目：**

| 项目 | 合作机构 | 每份捐赠标准产出 |
|------|---------|----------------|
| 山区净水计划 | 壹基金 | ￥20 = 1 名儿童 1 月安全饮水 |
| 免费午餐 | 中国社会福利基金会 | ￥20 = 1 名儿童 1 周午餐 |
| 荒漠植树 | 中国绿化基金会 | ￥10 = 1 棵梭梭树 |
| 乡村小书柜 | 担当者行动 | ￥50 = 1 个班级图书角 1 本书 |

**资金流向：**

```
用户代扣 → 微信支付直接结算 → 基金会对公账户
                                  ↓
                          基金会开具捐赠票据
                                  ↓
                          平台仅获取捐赠完成状态
                                  ↓
                          用户收到捐赠完成通知
```

> **关键：平台不碰钱。** 微信支付代扣直结到基金会账户，平台仅在技术上充当"验证路由器"。

## 四、用户流程

### 4.1 核心流程：创建 → 签约 → 每日验证 → 结算

```
1. 打开小程序 → 浏览承诺广场
   （热门挑战 / 公益项目展示 / 好友正在挑战）

2. 选择挑战类型 → 设定目标值 + 周期 + 承诺金

3. 从公益项目池选择"断签时捐给谁"
   ├── 查看项目详情（配图 + 故事 + 每份金额的产出说明）
   └── 选定

4. 微信授权「服务委托代扣」
   ├── 微信弹出签约页：显示扣费上限、扣费条件
   └── 确认签约 → 挑战开始倒计时

5. 每日收到服务通知提醒（模板消息）
   ├── 自动验证类（步数）：系统自动拉取，无感完成
   ├── 手动验证类（早起/冥想）：点击确认
   └── 截图验证类（阅读）：上传截图 → AI 即时校验

6. 断签时：
   ├── 宽限期：当日 24:00 前仍可补签
   ├── 超时未完成 → 次日 08:00 自动发起代扣
   ├── 微信支付通知："您已向 XX 项目捐赠 ¥XX"
   └── 可选：自动发朋友圈（违约广播）

7. 挑战结束：
   ├── 全部完成 → 成就页面（含徽章 + 可分享海报）
   └── 部分违约 → 总结看板（履约率 + 总捐赠金额 + 去向明细）
```

### 4.2 签约代扣流程

```
用户点击「开始挑战」
  → 呼起微信支付签约页面
  → 展示《委托代扣协议》+《挑战规则须知》
  → 用户确认签约
  → 微信返回签约授权码
  → 平台记录签约关系，存入挑战订单
  → 挑战正式开始
```

### 4.3 断签扣款流程

```
每日 23:59:59 校验用户今日状态
  ├── 已标记完成 → 跳过
  └── 未完成 → 检查免死金牌余额
       ├── 有剩余 → 消耗 1 枚，挑战继续
       └── 无剩余 → 进入断签流程：
            1. 平台调用微信支付扣款接口
            2. 微信从用户账户扣款直结基金会
            3. 平台接收扣款结果回调
            4. 更新挑战状态 + 发送通知给用户
            5. 累计断签计数
            6. 若连续 3 天 → 终止挑战，剩余天数按比例扣款
```

## 五、应用场景

### 场景一：新年立 Flag

用户元旦立 Flag "每天走 10000 步"，签约 30 天挑战，承诺金 ￥20/次。前两周坚持得很好，第三周某天加班到很晚忘了走。第二天早上收到 ￥20 扣款通知——钱捐给了山区净水计划，还附了一张受助儿童的照片。"虽然亏了钱，但感觉不坏。"

### 场景二：朋友组队互相监督

4 个朋友组队"21 天早起打卡"，每人承诺金 ￥20。建立群聊每天互相提醒。如果有人断签，所有人都会在群里看到通知。社交压力和金钱损失双重驱动下，4 人全部完成挑战。

### 场景三：企业团建健康挑战

公司行政组织"全员万步走"活动，30 人参加。每人签约 7 天挑战，承诺金 ￥50（公司补贴 ￥30，个人出 ￥20）。全部完成返还个人部分，公司补贴部分自动捐赠。失败者的承诺金同样捐赠。既促健康又做公益。

## 六、边界声明

| 不做 | 原因 |
|------|------|
| 不做押金池 | 资金池模式在中国法律风险不可控，直接代扣更安全 |
| 不做平台截留 | 平台不经手资金，代扣直达基金会 |
| 不做用户间转账 | 避免"瓜分"类赌博定性风险 |
| 不做退款机制 | 代扣成功即完成捐赠，不可撤回 |
| 不做动态排行榜奖励 | 避免诱导用户为排名过度竞争 |
| 不做重复验证 | 一天内同一挑战多次验证无意义 |
| 不做自由金额 | 承诺金固定在 ￥5/￥20/￥50/￥100 四档，防止变相赌博 |
| 不做无验证的纯承诺 | 所有类型必须有客观验证方式，纯打卡签到只能用于早起类 |

## 七、合规说明

### 7.1 涉赌风险管控

| 风险点 | 本方案的设计应对 |
|--------|----------------|
| 资金归集 | 零资金池，代扣直付基金会，平台不经手 |
| 用户获利 | 钱全部捐出，用户不可能从他人损失中获利 |
| 抽头渔利 | 平台不抽成，不参与资金分配 |
| 概率机制 | 结果完全由用户行为决定（是否完成），无随机/概率因素 |

### 7.2 慈善合规

| 要求 | 执行方式 |
|------|---------|
| 公开募捐资格 | 仅与持有公募资格的基金会合作，平台不自募 |
| 捐赠协议 | 与每家基金会签署书面合作协议，明确资金用途和公示义务 |
| 捐赠票据 | 基金会直接向用户开具电子捐赠票据 |
| 资金透明 | 每笔捐赠在基金会官网可查，平台展示汇总数据 |

### 7.3 平台审核合规

| 风险 | 应对 |
|------|------|
| 微信小程序审核 | 不使用"押金""对赌""返现""瓜分"等敏感词；提前提交合规说明函 + 基金会合作协议 |
| 支付接口合规 | 使用微信支付「服务委托代扣」官方接口，不走个人收款码 |
| 敏感词替换 | "承诺金" / "履约金" / "爱心约定" 替代 "押金"；"捐赠" 替代 "罚款" / "惩罚" |

### 7.4 用户协议关键条款

- 明确告知代扣触发条件（每日 24:00 校验，未完成则次日 08:00 扣款）
- 明确告知一旦扣款即完成公益捐赠，不可撤销
- 明确告知平台角色仅为验证技术服务方，不经手资金
- 免死金牌使用规则
- 挑战终止后的剩余天数按比例扣款的计算方式

# 我来当老师 — 产品功能说明书

## 一句话定义

费曼学习法的"最后一公里"——用户当老师，虚拟学生当听众，通过教学来巩固知识、暴露盲区。

---

## 一、目标用户与痛点分析

### 1.1 核心用户画像

**主要用户：知识工作者与学生（18-35 岁）**

| 维度 | 描述 |
|------|------|
| 年龄 | 18-35 岁，以大学生和职场 1-5 年为主 |
| 场景 | 备考（考研/考证/面试）、学习新技术、整理知识体系 |
| 收入 | 学生月消费 1500-3000，职场人月收入 8000-30000 |
| 学习习惯 | 看课多、笔记多，但很少"输出"——书看了就忘 |
| 日常痛点 | 读了很多书/看了很多课，但讲不出来；以为自己懂了，被一问就卡住 |
| 深层焦虑 | 学了记不住、面试被问倒、知识体系碎片化 |

**次要用户：培训师/教师**

| 维度 | 描述 |
|------|------|
| 场景 | 备课试讲、打磨表达、准备新课程 |
| 痛点 | 需要低风险环境练习讲课，没人愿意当试听小白鼠 |

### 1.2 真实痛点分级

| 需求类型 | 痛点 | 用户行为证据 |
|---------|------|-------------|
| **刚需** | 备考者需要检验知识掌握度，但找不到人听自己讲 | 考研/考公/考证群体有强烈"输出检验"需求 |
| **刚需** | 面试准备需要模拟被追问，真人陪练成本高 | 模拟面试是求职过程中的刚需环节 |
| **改善型** | 技术人员学习新技术后希望巩固，但写博客/做分享门槛高 | 写一篇文章需要大量整理，讲课门槛更低 |
| **改善型** | 学生上课听懂了但考试不会做——缺少输出训练 | "一听就会，一做就废"是普遍现象 |
| **猎奇伪需求** | "AI 陪聊天式学习" | 如果只是轻松聊天而不是严谨教学，用户不会持续使用 |

## 二、解决方案与核心功能

### 2.1 解决方案概述

我来当老师解决一个核心矛盾：**费曼学习法被广泛认可（教是最好的学），但执行门槛太高——你找不到一个真实的人愿意认真听完你讲并追问你。**

产品用虚拟学生替代真人听众：
- 你讲课时，虚拟学生会根据角色设定提出不同类型的追问
- 小白逼你用最简单的话讲清楚，杠精逼你严谨，学霸推你到知识边界
- 你卡住、跳过、含糊的地方自动标记为盲区
- 课后产出完整回放和盲区清单，告诉你哪里没讲透

不需要约人、不需要准备、打开麦克风就能直接开始。

### 2.2 核心功能清单

1. **课堂教学** — 三种模式（自由课堂/分阶段提问/课件驱动）覆盖不同教学场景
2. **虚拟学生** — 四种基础角色模板，可自定义，随机抽问增加课堂不确定性
3. **盲区检测** — 基于卡顿/跳过/矛盾自动识别知识盲区
4. **课后回放** — 完整音频 + 文字转录，可搜索可跳转
5. **盲区清单** — 列表/对比/学习路径三种视图

## 三、竞品与差异化分析

### 3.1 同类替代品对比

| 竞品 | 类型 | 优点 | 缺点 | 与本产品定位差异 |
|------|------|------|------|----------------|
| Anki / 记忆卡片 | 复习工具 | 高效重复，算法成熟 | 不支持深度理解，只是 recall | 我来当老师检验的是"能不能讲清楚"，不是"能不能记住" |
| 费曼笔记 / Obsidian | 笔记工具 | 自由度高，知识图谱 | 没有反馈机制，自己写给自己看 | 虚拟学生提供实时追问反馈 |
| 模拟面试工具 | 面试准备 | 针对性强 | 只面向面试场景，不通用 | 覆盖所有知识学习场景 |
| 真人学习小组 | 线下/线上 | 真实互动 | 组员水平参差、组局成本高、时间难协调 | 虚拟学生 7×24 可用，且可控 |
| ChatGPT 问答 | 通用 AI | 随时可问，知识广 | 被动回答，不会主动追问你的盲区 | 虚拟学生会主动追着你问，而不是你问它答 |

### 3.2 差异化优势与护城河

| 优势 | 说明 | 可模仿性评估 |
|------|------|-------------|
| 教学驱动而非问答驱动 | 用户是老师，AI 是学生，角色翻转 | 中等——需要设计好的学生角色追问策略 |
| 四种角色差异化追问 | 小白/杠精/学霸/举一反三各有风格 | 中等——角色设定容易，但追问质量取决于模型 |
| 盲区检测与回放闭环 | 从卡顿到盲区清单到学习路径 | 低——需要准确识别卡顿/矛盾/回避的信号 |
| 课堂体验设计 | 像素风教室 UI、学生座位、随机抽问 | 高——UI 体验易复制 |

**核心护城河：** 盲区检测的准确度。随着用户使用次数增加，系统对"哪种卡顿是真正的盲区"的判断越来越准，迁移成本随之提高。

## 五、核心模块详解

### 5.1 课堂教学

三种教学模式:

**模式一：自由课堂（Free Mode）**
用户点"开始上课"→ 录音开始 → 直接对着麦克风讲课。讲到自然段落时停顿超过阈值（~2s），系统触发一轮学生提问。从全班中随机抽取一名学生发言。用户回答后继续讲，循环。适合快速梳理思路、口头复述。

**模式二：分阶段提问（Staged Mode）**
进入前设定知识点列表，用户逐个知识点讲课。讲完一个知识点后触发一轮提问。全部知识点讲完进入自由 Q&A 环节。适合系统性过一遍知识体系。

**模式三：课件驱动（Outline Mode）**
用户上传/输入大纲（Markdown 格式），虚拟学生"预习"大纲，上课时按大纲结构推进。适合已有笔记/PPT 内容，按自己结构输出。

### 5.2 虚拟学生系统

**基础角色模板**

| 学生 | 人设 | 提问风格 | 课堂作用 |
|------|------|---------|---------|
| 🧒 小白 | 零基础，好奇宝宝 | "这个是什么意思？""为什么重要？" | 逼用户用最简单的话解释 |
| 🤔 杠精 | 爱挑刺，要求严格 | "你确定吗？""这里有个漏洞？" | 逼用户严谨，不留模糊地带 |
| 🎓 学霸 | 知识渊博，喜欢深挖 | "背后的原理是什么？""那 X 和 Y 的关系是？" | 推用户到知识边界 |
| 💡 举一反三 | 联想力强 | "这个在场景 Y 也能用吗？" | 帮用户建立知识迁移 |

**可调节项**: 开关选择参与学生、同类型可添加多人、提问力度可调、小白起点水平可调、支持自定义角色

**发言规则**: 轮到学生发言时从全班中随机抽取（非固定轮询），被抽到的学生座位/头像高亮并播放提示音

### 5.3 盲区检测

盲区的判断来源：
- 用户说"跳过"/"不知道"的知识点
- 学生追问后用户回答含糊、卡顿、回避
- 逻辑前后矛盾或跳跃的部分

### 5.4 课后产出

**课堂回放**: 完整音频记录 + 同步文字转录，可回放、可跳转、可搜索

**知识盲区清单（三种视图）**:

| 视图 | 形式 |
|------|------|
| 列表式 | 逐条列出未讲清的知识点，附带原文引用 |
| 对比式 | "你的回答" vs "准确解释" 并列对比 |
| 学习路径式 | 盲区按依赖关系组织成知识图谱 |

## 六、用户流程

```
启动应用
    ↓
选择教学模式 — 自由 / 分阶段 / 课件驱动
    ↓
编排学生阵容 — 增减学生、调整个性、排座位
    ↓
开始上课
    ├─ 用户讲课（录音）
    ├─ 停顿 → 随机抽取学生提问
    └─ 循环直到下课
    ↓
下课
    ├─ 课堂回放（音频 + 文字）
    └─ 知识盲区清单（三种视图）
```

### 6.1 首次使用流程

```
新用户注册
    ↓
快速引导：选择第一次学习目标（备考/面试/技术学习/其他）
    ↓
默认学生阵容：小白 + 杠精 + 学霸（适合大多数场景）
    ↓
推荐教学模式：自由课堂——直接开讲最快捷
    ↓
完成第一次 5 分钟微课堂
    ↓
查看盲区清单 → 理解"原来我在这里没讲透"
    ↓
调整学生阵容或教学模式 → 开始第二次课堂
```

## 七、商业模式

### 7.1 定价区间

| 付费模式 | 定价区间 | 依据 |
|---------|---------|------|
| 月订阅 | 19-39 元/月 | 学习工具类 APP 标准价格带 |

## 八、落地路径

### 8.1 五大落地难点

| 难点 | 详细描述 | 缓解策略 |
|------|---------|---------|
| 用户教育成本 | "对着 AI 讲课"需要克服尴尬感 | 5 分钟微课堂引导 + 像素风降低正式感 |
| 语音识别质量 | 卡顿检测依赖语音识别准确度 | 选用成熟语音 API，离线降级方案 |
| 盲区判断准确度 | 错判盲区会误导用户 | 初期多用几个信号综合判断，允许用户手动标记/取消 |
| 留存率 | 学习工具的通病——新鲜感过后不用了 | 设定学习目标提醒 + 每周盲区进步报告 |
| 定价敏感 | 学生群体付费能力有限 | 免费版保留核心功能，限制使用次数 |

### 8.2 MVP 最小可行产品

**MVP 范围：** 只做一个教学模式 + 一个学生角色。

| 功能 | MVP 做法 | 非 MVP（后续再做） |
|------|---------|------------------|
| 课堂教学 | 只做自由课堂模式 | 分阶段提问和课件驱动 |
| 虚拟学生 | 只做"小白"一个角色 | 杠精/学霸/举一反三 |
| 盲区检测 | 基于手动标记"我不知道" | 自动卡顿检测 |
| 课后回放 | 纯文本转录 + 回放 | 音频同步 + 搜索 |
| 盲区清单 | 纯列表式 | 对比式 + 学习路径式 |

**最低试错成本估算：**
- 开发：1 人 × 1.5 个月 ≈ 3-5 万
- 语音识别 API 费用：月均 500-1000 元
- 首批 200 个种子用户：0 元（学习社群内测）

### 8.3 第一步验证

**最关键假设：** 用户愿意对着 AI 讲课来检验自己的知识掌握度。

**最低成本验证方法：**

| 步骤 | 做法 | 判断标准 |
|------|------|---------|
| 1. 行为验证 | 在学习群发起挑战："打开录音，用 3 分钟讲清楚你最近学的一个概念，发到群里" | 超过 30 人发了录音 |
| 2. 产品验证 | 做一个简陋版本（只用语音输入 + 文字转录 + 盲区标注），让 50 人试用 | 每人完成至少 3 次课堂 |
| 3. 留存验证 | 追踪 7 日留存 | 7 日留存 > 35% |

## 九、风险与预期反馈

| 预期槽点 | 用户画像 | 应对方案 |
|---------|---------|---------|
| "对着 AI 讲好尴尬" | 首次使用的用户 | 5 分钟引导 + 转换心态："你是在教它，不是跟它聊天" |
| "学生问的问题太蠢/太水" | 使用小白角色的用户 | 角色可更换，杠精和学霸更犀利 |
| "盲区检测不准" | 深度使用者 | 允许手动标记/取消，持续优化检测模型 |
| "跟真人还是不一样" | 比较心理 | 承认差异，但强调 7×24 可用、无需组局、可回放的优势 |
| "学完就忘，产品没用" | 期待短期效果的用户 | 引导多课堂+盲区清单复习，学习是长期过程 |

## 十、边界与原则

| 不做 | 原因 |
|------|------|
| 题库 | 聚焦教学质量而非知识储备 |
| 自动化评分 | 不替代教师判断 |
| 多人协作课堂 | 保持一个人讲课的场景纯粹性 |
| 视频教学 | 聚焦音频讲课的低门槛体验 |
| 生成学习内容 | 用户自己准备内容才是真学习，AI 生成的内容用户无法真正掌握 |

**三条底线：**

1. **用户永远是老师** — AI 学生绝不反客为主替用户讲课
2. **不制造焦虑** — 盲区清单是帮助定位的工具，不是"你不行"的判决
3. **隐私优先** — 课堂录音不上传到云端，端侧处理或用户授权上传
